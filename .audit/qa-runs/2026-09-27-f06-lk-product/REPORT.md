## 1. TL;DR

ЛК учителя функционально **заложен как прототип** (табы, история, избранное, шаблоны, magic-link mock, аналитика), но содержит **4 критичных бага, делающих ключевые сценарии нерабочими** (кнопка «Открыть» из истории всегда ведёт в «Лист не найден»), а до прода требует подключения бэкенда, header-индикации залогиненности и **брендинговой чистки** (везде «ЛистAI», хотя бренд сменился на «РабочиеЛисты AI»).

## 5. Что сломано (BROKEN)

### B-1. CRITICAL — Клик «Открыть» из истории всегда ведёт в «Лист не найден»

`src/app/dashboard/page.tsx:341` и `:394` собирают ссылку как `/preview/${item.id}` (path-параметр).
`src/app/preview/page.tsx:23` читает **query-параметр** через `useSearchParams().get("id")`.

При переходе `/preview/abc123` параметр `id` в query string пуст → `id = ""` → `notFound = true` → страница показывает «Лист не найден» (`preview/page.tsx:85-101`).

**Сценарий:** учитель открыл ЛК → видит 5 листов в истории → нажимает «Открыть» → ❌ «Лист не найден».

### B-2. CRITICAL — Preview ищет только в `getFavorites()`, не в истории

`src/app/preview/page.tsx:34-42`:
```ts
const all = getFavorites();
const found = all.find((w) => w.id === id);
if (found) { ... } else { setNotFound(true); }
```

История хранится отдельно в `KEY_HISTORY` (`storage.ts:5`), и `UserHistoryItem` **не содержит поля `tasks`** (только метаданные, `types.ts:155-164`). Даже если B-1 починить, открыть произвольный лист из истории всё равно нельзя — данных для рендера нет.

### B-3. CRITICAL — Сердечко на HistoryCard не кладёт артефакт в «Избранное»

`src/app/dashboard/page.tsx:76-79`:
```ts
const handleToggleFav = (id: string) => {
  toggleFavorite(id);  // только флаг на history
  refresh();
};
```

`togleFavorite` (`storage.ts:50-55`) пишет только `isFavorite: !x.isFavorite` в элемент истории, **не вызывая `saveFavorite`**. Учитель видит заполненное сердечко на карточке в Истории → переходит в таб «Избранное» → пусто. Это вводит в заблуждение и противоречит контракту.

### B-4. CRITICAL — Избранное принимает 4 типа, рендерит 1

`src/lib/utils/storage.ts:94` — `saveFavorite(w: Worksheet | LessonPlan | Presentation | Ktp)`.
`src/app/preview/page.tsx:142` — рендерится только `<WorksheetPreview worksheet={worksheet} />`.

Если учитель сохранил в избранное **план урока, презентацию или КТП**, то:
- Конструктор зовёт `handleSaveFavorite` → `saveFavorite(target)` + `toggleFavorite(target.id)` (`constructor/page.tsx:542-549`).
- Дашборд → Избранное → FavoriteCard рендерится (там текст и метаданные есть, `dashboard/page.tsx:362-405`).
- Клик «Открыть лист» → `preview/page.tsx:34` ищет id в `getFavorites()` (найдёт) → рендерит **WorksheetPreview** с `worksheet.tasks` → **runtime error** (на plan/презентации/КТП поля `tasks` нет).

### B-5. BRAND-DRIFT — везде «ЛистAI», бренд уже «РабочиеЛисты AI»

`docs/BRAND.md:10-12`: имя = «РабочиеЛисты», подзаголовок «РабочиеЛисты AI», домен `rabochielisty.ru`. Решение зафиксировано 2026-09-25.

- `src/app/layout.tsx:33` — `creator: "ЛистAI"`

Учитель, получивший письмо «от ЛистAI», откроет лендинг «ЛистAI», и только в Footer мелким шрифтом увидит домен. Несогласованность бренда на каждом экране.

### B-6. UX — `name` после регистрации = `email.split("@")[0]`

`src/app/login/page.tsx:50`: `name: email.split("@")[0]`.
Учитель с почтой `marina.petrova@school59.ru` будет «marina.petrova» во всём ЛК.
В ProfileHeader (`dashboard/page.tsx:231-238`) это выводится крупно + аватар по первой букве.
Нет возможности исправить.

### B-7. UX — `addTemplate` недостижим

`src/lib/utils/storage.ts:63` — функция есть, но в UI её вызов **только в `/preview` (`preview/page.tsx:59-67`)**.
Учитель не может создать шаблон, пока не откроет preview. Preview сломан (B-1, B-2). Получается deadlock: чтобы создать шаблон, надо сначала открыть лист из избранного. Но чтобы открыть лист, надо сначала его туда положить (через конструктор, кнопка «В избранное»), а потом ещё раз найти в табе Избранное → открыть → «Как шаблон». 3 шага вместо ожидаемого 1.

## 8. Скоуп для следующего этапа

### Готово к реализации прямо сейчас (фичи № 1, 3, 5, 6, 9, 10 из топ-10)

- **Чисто фронтовые правки**, не требуют продуктового решения:
  - Storage unification (1, 4)
  - Header реагирует на профиль (3)
  - Шаблон из конструктора (5)
  - Confirm-модал выхода (6)
  - Клавиатурные табы (10)
  - Глобальная замена «ЛистAI» → «РабочиеЛисты AI» (9)
- **Трудоёмкость суммарно:** ~1-1.5 дня разработчика + 2-3 часа QA.
- **Блокеров нет.**

### Требует продуктового решения перед реализацией

| Вопрос | Кому | Почему |
|---|---|---|
| **Шаринг листа по ссылке** (M-17): делать или нет? Сколько уровней доступа (public / school-only / teacher-only)? Нужно ли хранение на бэке или достаточно сгенерировать read-only ссылку с подписью? | PM (Иван) | Меняет data-модель, добавляет KV/D1 ключи, влияет на тарифы |
