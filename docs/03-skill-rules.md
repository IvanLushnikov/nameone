# Каталог правил генерации LLM (skill rules)

> **Статус:** предварительный драфт, v0.1.
> **Дата:** 2026-09-25
> **Назначение:** версионируемый каталог правил, которыми руководствуется скилл при генерации рабочих листов. Каждое правило имеет стабильный ID, привязку к стадиям пайплайна и к задачам из golden dataset (`02-task-spec-for-testing.md`).
> **Связано:** `02-task-spec-for-testing.md` (формат задачи, §4 — общая ссылка), `01-research-naming.md` (контекст продукта).

---

## 0. Мета

### 0.1 Конвенция ID

| Префикс | Категория |
|---|---|
| `P-` | Pipeline stage rule (стадия пайплайна) |
| `N-` | Negative rule (запрет) |
| `Pos-` | Positive rule (обязательное требование) |
| `S-<SUBJ>-` | Subject-specific rule (`MATH` / `RU` / `EN` / `PHYS` / `HIST` / `BIO` / `CHEM` / ...) |
| `L-<LANG>-` | Language-specific rule (`RU` / `EN` / `DE` / `FR` / `ES` / ...) |
| `Ped-` | Pedagogical rule |

### 0.2 Версионирование

- Каталог имеет semver (`MAJOR.MINOR`).
- **MAJOR** — меняется схема категорий или конвенция ID.
- **MINOR** — добавлено/удалено/переписано правило.
- Каждое правило имеет собственную версию (`vN.M`), наследует MINOR каталога при создании, при изменении правила bump локально.
- Любое изменение правила требует прогона связанных задач из golden dataset.

### 0.3 Жизненный цикл правила

`draft` → `proposed` → `active` → `deprecated`

- `draft` — пишется, не используется в проде.
- `proposed` — готово, прогоняется на golden dataset, ждёт решения PM.
- `active` — в прода, обязательно к исполнению.
- `deprecated` — больше не требуется, но оставлено для истории прогонов.

### 0.4 Журнал изменений

| Дата | Версия | Что изменилось |
|---|---|---|
| 2026-09-25 | 0.1 | Первичный драфт каталога. ~25 правил в 5 категориях. |

## 1. Pipeline stage rules (`P-`)

Правила привязки к стадиям пайплайна. Если стадия не отработала — генерация считается проваленной вне зависимости от качества output.

### P-001. Stage 0: полнота извлечения полей

- **Applies to:** все задачи.
- **Stage:** 0.
- **Description:** из сырого ввода должны быть извлечены все поля из §2.1 спеки задачи: `subject`, `grade`, `topic`, `work_type`, `difficulty`, `language`, `scenario`. Если поле не извлечено явно — пометить как `unknown` и зафиксировать допущение.
- **Check:** автоматический парсер spec'а сверяет наличие ключей.
- **Pass:** все 7 полей присутствуют, отсутствующие помечены `unknown` с обоснованием.
- **Examples:**
  - ✅ «Площадь треугольника, 5 класс» → `subject=математика, grade=5, topic=площадь треугольника, work_type=unknown, difficulty=unknown, language=ru, scenario=unknown`.
  - ❌ «Сделай лист» → 0 полей, падение.

### P-002. Stage 1: spec без потери смысла

- **Applies to:** все задачи.
- **Stage:** 1.
- **Description:** spec, собранный из ввода, должен сохранять намерение учителя. Любые добавленные интерпретации (УМК, уровень сложности) — явно отмечены как `inferred`.
- **Check:** PM или приглашённый учитель сравнивает ввод и spec.
- **Pass:** смысл ввода сохранён, все интерпретации помечены.
- **Examples:**
  - ✅ «для слабого класса» → `difficulty=базовая, scenario=слабый класс (inferred)`.
  - ❌ «для слабого класса» → `difficulty=повышенная` (потеряно намерение).

### P-003. Stage 3: subject critic обязателен

- **Applies to:** все задачи, кроме `language` как предмета.
- **Stage:** 3.
- **Description:** второй проход модели в роли предметного критика. Ищет фактические ошибки в output (формулы, даты, имена, термины, вычисления). Если не уверен — помечает, не исправляет наугад.
- **Check:** модель-критик + случайная ручная проверка 10-20% задач.
- **Pass:** критик отработал, найденные ошибки исправлены или помечены.
- **Examples:**
  - ✅ Критик нашёл «2+2=5» → исправлено на «2+2=4».
  - ❌ Черновик без прогона через критика.

### P-004. Stage 4: языковой gate обязателен

- **Applies to:** все задачи с `language != ru` или для предметов «русский язык», «английский язык», «литература», а также для задач на иностранном языке.
- **Stage:** 4.
- **Description:** отдельный проход, проверяющий грамматическую/орфографическую/пунктуационную корректность формулировок на целевом языке. См. также §3 (Language rules).
- **Check:** отдельный critic + сверка с типовыми ошибками (см. `L-*`).
- **Pass:** критик не нашёл ошибок, либо найденные исправлены.
- **Examples:**
  - ✅ Английский: «She has been working here since 2019» → tense OK.
  - ❌ Английский: «She have been working here since 2019» → grammar error, провал.

### P-005. Stage 5: педагогический gate обязателен

- **Applies to:** все задачи.
- **Stage:** 5.
- **Description:** проверяет адекватность сложности классу, разнообразие типов заданий, читаемость формулировок, реальный объём.
- **Check:** critic + правила `Ped-*`.
- **Pass:** все `Ped-*` правила пройдены.

### P-006. Stage 6: кросс-проверка ключей

- **Applies to:** все задачи с ключами (т.е. почти все).
- **Stage:** 6.
- **Description:** автомат проверяет, что `ключи[i]` соответствует `задание[i]`, ответ действительно сходится с решением, ключи не дублируются и не пропущены.
- **Check:** автоматический скрипт-сверка.
- **Pass:** 100% ключей соответствуют заданиям.
- **Examples:**
  - ✅ Задание 1: «2+2=?», ключ 1: «4». Задание 2: «3+3=?», ключ 2: «6».
  - ❌ Задание 1: «2+2=?», ключ 1: «6» (ответ от другого задания).

## 2. Negative rules (`N-`) — запреты

Что скилл **не должен** делать. Нарушение = провал генерации.

### N-001. Запрет выдумывать

- **Applies to:** все предметы.
- **Description:** не выдумывать термины, правила, формулы, даты, имена, события. Если нет уверенности — пометить как «требует проверки учителем» или пропустить.
- **Pass:** все сущности верифицируемы по ФГОС / УМК / открытым источникам.
- **Examples:**
  - ✅ «Площадь треугольника = ½·a·h».
  - ❌ «Площадь треугольника = ⅓·a·h» (неправильная формула).

### N-002. Запрет отвечать не на тот номер

- **Applies to:** все задачи с ключами.
- **Description:** ключ отвечает ровно на тот номер задания, к которому приписан.
- **Pass:** P-006 прошёл.

### N-003. Запрет выхода за программу класса

- **Applies to:** все задачи.
- **Description:** не использовать понятия/темы/методы, не входящие в ФГОС для указанного класса. Если задача требует выхода — пометить явно и предупредить учителя.
- **Pass:** все задания внутри программы класса.
- **Examples:**
  - ✅ 5 класс математика: задачи на площадь треугольника (в программе).
  - ❌ 5 класс математика: дифференциальные уравнения (не в программе).

### N-004. Запрет однотипных заданий подряд

- **Applies to:** все задачи с `count > 5`.
- **Description:** если в листе больше 5 заданий, минимум 3 разных типа (см. `Pos-003`). Более 5 одинаковых подряд = провал.
- **Pass:** правило `Pos-003` соблюдено.

### N-005. Запрет несуществующих слов

- **Applies to:** все задачи по иностранным языкам или на иностранном языке.
- **Description:** не использовать слова, которых нет в словаре целевого языка. Особенно критично при генерации текстов для диктантов, чтения, эссе.
- **Pass:** слова верифицируемы по словарю / корпусу.
- **Examples:**
  - ✅ EN: «beautiful», «carefully».
  - ❌ EN: «beautifuly» (опечатка, нет такого слова).

### N-006. Запрет ответов в обход заданий

- **Applies to:** все задачи.
- **Description:** ответы/ключи выводятся **отдельным блоком** после заданий, не вшиты в формулировки. Учитель сам решает, показывать ли ключи ученикам.
- **Pass:** структура output содержит два отдельных блока: «Задания» и «Ключи».
- **Examples:**
  - ✅ Блок заданий → блок ключей.
  - ❌ После каждого задания сразу ответ в скобках.

## 3. Positive rules (`Pos-`) — обязательные требования

Что скилл **обязан** включать в output.

### Pos-001. Привязка к ФГОС-разделу класса

- **Applies to:** все задачи.
- **Description:** каждая задача имеет привязку к конкретному разделу ФГОС для своего класса (например, «Геометрия → Площади фигур, 5 класс»).
- **Pass:** привязка указана в метаданных листа.
- **Examples:**
  - ✅ Тема «площадь треугольника, 5 класс» → раздел «Геометрия, 5 класс».
  - ❌ Тема указана, раздел ФГОС — нет.

### Pos-002. УМК-специфичная терминология

- **Applies to:** все задачи, где УМК определён.
- **Description:** если определён УМК (Школа России, Перспектива, Spotlight и т.д.) — использовать терминологию этого УМК. Не смешивать термины из разных УМК.
- **Pass:** терминология одного УМК.

### Pos-003. Минимум 3 типа заданий

- **Applies to:** все задачи с `count > 5`.
- **Description:** в листе больше 5 заданий — должно быть минимум 3 разных типа (расчётная задача / задача на доказательство / задача с выбором ответа / задача на соответствие / текстовая задача / и т.д.).
- **Pass:** ≥3 разных типа.

### Pos-004. Диктанты с верифицированной грамматикой

- **Applies to:** `work_type=диктант`.
- **Description:** текст диктанта должен пройти отдельный языковой gate (см. `L-RU-001`, `L-EN-001` и т.д.) с повышенной строгостью. Текст должен содержать целевые орфограммы/пунктограммы.
- **Pass:** текст диктанта прошёл `L-*` правила для своего языка.

### Pos-005. Иностранный язык — отдельный языковой gate

- **Applies to:** все задачи с `language != ru` или предмет «английский/немецкий/...».
- **Description:** для каждого целевого языка — отдельный gate (см. §4 Language rules).

### Pos-006. Сложность адекватна классу

- **Applies to:** все задачи.
- **Description:** сложность заданий соответствует возрастному профилю класса (см. также `Ped-001`).
- **Pass:** `Ped-001` пройден.

## 4. Subject-specific rules (`S-<SUBJ>-`)

Правила для конкретных предметов. Общий пайплайн + эти правила = subject-aware проверка.

### Математика (`S-MATH-`)

#### S-MATH-001. Корректность вычислений

- **Applies to:** все математические задачи.
- **Description:** все арифметические и алгебраические вычисления в формулировках и ключах должны быть верны. Critic обязан проверить каждое вычисление.
- **Pass:** 100% вычислений верны.
- **Examples:**
  - ✅ «2+3=5», «¼+⅓=7/12».
  - ❌ «2+3=6», «¼+⅓=½».

#### S-MATH-002. Корректность формул

- **Applies to:** все задачи с формулами.
- **Description:** формулы записаны математически корректно (правильные индексы, степени, дроби).
- **Pass:** формулы соответствуют учебнику / справочнику.
- **Examples:**
  - ✅ S = ½·a·h, a² + b² = c².
  - ❌ S = ⅓·a·h (не та формула площади), a^2 + b^2 = c^2 (использовать степени).

### Русский язык (`S-RU-`)

#### S-RU-001. Орфография

- **Applies to:** все задачи по русскому + любые формулировки на русском.
- **Description:** орфографические ошибки недопустимы. Проверяется отдельным critic с правилами русской орфографии (Розенталь/Голуб).
- **Pass:** нет орфографических ошибок.
- **Examples:**
  - ✅ «собака», «молоко».
  - ❌ «сабака», «малако».

#### S-RU-002. Пунктуация

- **Applies to:** все задачи по русскому + любые формулировки на русском.
- **Description:** запятые, тире, двоеточия расставлены по правилам.
- **Pass:** пунктуация соответствует правилам.

#### S-RU-003. Синтаксис и согласование

- **Applies to:** все задачи.
- **Description:** предложения согласованы (подлежащее-сказуемое, управление, примыкание), нет грамматических ошибок.
- **Pass:** нет синтаксических ошибок.

### Английский язык (`S-EN-`)

#### S-EN-001. Грамматика времён

- **Applies to:** все задачи по английскому + формулировки на английском.
- **Description:** времена глаголов используются корректно, согласование с контекстом (present/past/future, simple/continuous/perfect).
- **Pass:** все времена употреблены правильно.
- **Examples:**
  - ✅ «I have lived here since 2010» (present perfect).
  - ❌ «I have live here since 2010» (отсутствует окончание -ed в past participle).

#### S-EN-002. Артикли

- **Applies to:** все задачи на английском.
- **Description:** артикли (a/an/the/—) используются корректно.
- **Pass:** нет ошибок в артиклях.
- **Examples:**
  - ✅ «the book», «a cat», «water» (no article).
  - ❌ «a water» (uncountable без артикля), «the cat» в первом упоминании (нужен a).

#### S-EN-003. Предлоги

- **Applies to:** все задачи на английском.
- **Description:** предлоги (in/on/at/for/since/during/...) используются корректно.
- **Pass:** нет ошибок в предлогах.

### Физика (`S-PHYS-`)

#### S-PHYS-001. Формулы и единицы измерения

- **Applies to:** все задачи по физике.
- **Description:** формулы записаны корректно, единицы измерения указаны и согласованы (СИ).
- **Pass:** формулы и единицы верны.

### История (`S-HIST-`)

#### S-HIST-001. Даты и имена

- **Applies to:** все задачи по истории.
- **Description:** даты событий и исторические имена указаны корректно.
- **Pass:** 100% дат и имён верифицируемы.

### Биология (`S-BIO-`)

#### S-BIO-001. Терминология и классификации

- **Applies to:** все задачи по биологии.
- **Description:** биологические термины и классификации (виды, роды, семейства, типы тканей) указаны корректно.
- **Pass:** терминология верифицируема.

### Химия (`S-CHEM-`)

#### S-CHEM-001. Формулы и реакции

- **Applies to:** все задачи по химии.
- **Description:** химические формулы и уравнения реакций корректны, коэффициенты расставлены, валентности соблюдены.
- **Pass:** формулы и реакции верифицируемы.

## 5. Language-specific rules (`L-<LANG>-`)

Отдельные gate'ы для каждого языка формулировок. Применяются поверх `S-*-` правил.

### L-RU-001. Русский: орфография/пунктуация/синтаксис

- **Applies to:** все задачи с `language=ru` или предмет «русский язык».
- **Description:** правила русской орфографии и пунктуации (Розенталь, Голуб). Для диктантов — повышенная строгость.
- **Pass:** нет нарушений правил русского языка.

### L-EN-001. Английский: грамматика, лексика, орфография

- **Applies to:** все задачи с `language=en` или предмет «английский язык».
- **Description:** времена, артикли, предлоги, порядок слов, countable/uncountable, герундий vs инфинитив, орфография (especially -ed/-ing forms).
- **Pass:** нет грамматических/лексических ошибок.

### L-DE-001. Немецкий: род, спряжение, артикли

- **Applies to:** все задачи с `language=de` или предмет «немецкий язык».
- **Description:** род существительных (der/die/das), спряжение глаголов (ich/du/er/sie/wir/ihr/sie), склонение.
- **Pass:** нет нарушений немецкой грамматики.

### L-FR-001. Французский: род, спряжение, артикли

- **Applies to:** все задачи с `language=fr` или предмет «французский язык».
- **Description:** род (le/la), спряжение (-er/-ir/-re), partitive articles (du/de la/des), согласование причастий.
- **Pass:** нет нарушений французской грамматики.

### L-ES-001. Испанский: род, спряжение, артикли

- **Applies to:** все задачи с `language=es` или предмет «испанский язык».
- **Description:** род (el/la), спряжение (-ar/-er/-ir), ser vs estar, согласование.
- **Pass:** нет нарушений испанской грамматики.

## 6. Pedagogical rules (`Ped-`)

Правила педагогической пригодности листа.

### Ped-001. Сложность адекватна классу

- **Applies to:** все задачи.
- **Description:** сложность заданий, объём, лексика формулировок соответствуют возрастному профилю класса (1-4 / 5-9 / 10-11).
- **Pass:** нет заданий, выходящих за возрастной профиль.
- **Examples:**
  - ✅ 1 класс: формулировки простыми словами, без сложных терминов.
  - ❌ 1 класс: «вычислите интеграл методом трапеций».

### Ped-002. Разнообразие типов заданий

- **Applies to:** все задачи с `count > 5`.
- **Description:** не менее 3 разных типов заданий (см. `Pos-003`).
- **Pass:** ≥3 типов.

### Ped-003. Длина формулировок читаема

- **Applies to:** все задачи.
- **Description:** формулировки не перегружены, читаемы для ученика данного класса. Длинные условия разбиты на пункты.
- **Pass:** формулировки читаются за разумное время.

### Ped-004. Объём реально сделать за урок

- **Applies to:** все задачи.
- **Description:** количество заданий реалистично для урока (45 мин) или домашки (30-60 мин).
- **Pass:** объём соответствует `work_type` (контрольная — 4-6 задач, домашка — 5-10, карточки — 1-3 и т.д.).

## 7. Привязка правил к задачам golden dataset

> Golden dataset создаётся отдельно по формату `02-task-spec-for-testing.md`. Здесь — обратная карта: какие правила должна покрывать каждая задача.

### Минимальное покрытие правил по типам задач

| Тип задачи | Обязательно покрывает правила |
|---|---|
