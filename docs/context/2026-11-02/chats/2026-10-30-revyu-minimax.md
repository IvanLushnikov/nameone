## Часть 4. Формат отчёта

Пиши в /Users/ivanlusnikov/Documents/nameone/docs/review/claude-review-<дата>.md (создай папку). Отчёт — на русском.

Каждая находка — в формате user story, ровно четыре строки:

    Как <учитель|админ|разработчик>, я хочу <что>, чтобы <зачем>.

Роли: учитель (что ломается у пользователя), админ (доступы, права, деньги, модерация), разработчик (причина в другом файле, два источника правды, поведение не воспроизводится).

Структура отчёта:
1. Сводка — что пересмотрел (сколько сессий из скольких, какие репозитории), 3–5 главных выводов.
2. Топ-15 находок — user story, отсортированы по цене ошибки.
3. Расхождения «обещание ↔ реальность» — таблица.
4. Решения, принятые за меня — список с моей оценкой риска.
5. Незакрытая работа и потерянные вопросы.
6. Устаревшее в памяти и документации — что исправить.
7. Что сделано хорошо — чтобы при следующей итерации это не переписали заново.
8. Что не удалось подтвердить — не пустой, с указанием причины (нет данных / нет доступа / противоречие в источниках).
9. Рекомендованный порядок действий — волнами, с критериями приёмки «да/нет».

## Часть 5. Особенности nameone, которые сэкономят тебе время
- Node 22, не 23. На Node 23 npm run build и next dev висят намертво (0.1 % CPU). Проверь node -v до сборки.
- Тайминги: полный бэк — ~290 с (1126 тестов), полный фронтовый набор — ~13 мин, npm run build — ~13 мин (13 884 страницы). Полный фронт в 30-минутный таймаут не влезает.
- Lock-файл генерировать тем же npm, которым ставит CI (локальный npm 11 и CI npm 10 несовместимы). Перед обновлением зависимостей — npm ci --dry-run.
- Вёрстку проверяй на 1440×900 и на 1920×1080 — на большем окне переполнение не видно, и это уже стоило провала.
- Падение теста не значит, что он твой. Сначала stat на тест и на тестируемый код: баг могли починить другой сессией, пока ты смотрел.
- Три разные системы величин не смешивать: взвешенные токены (норма), сырые токены (счёт в ответе API), деньги (фактическое списание). «Контрольная дороже листа в 54 раза» — это деньги; «~89 листов» — это токены. Рядом их публиковать нельзя.
