# Описание задачи для тестирования (draft)

> **Статус:** предварительный драфт, до фиксации архитектуры пайплайна.
> **Дата:** 2026-09-25
> **Назначение:** единый формат описания запроса учителя → используется для golden dataset, eval-прогонов и проверки, что все правила генерации LLM учитываются.
> **Связано:** `01-research-naming.md` (контекст продукта), этот документ — мета-спецификация над пайплайном.

---

## 1. Что такое «задача»

Единица тестирования = **один запрос от учителя + ожидаемое поведение пайплайна**.

Задача описывает:
- **Что ввёл учитель** (сырой input)
- **Что мы должны понять** (interpretation / spec)
- **Что должны сгенерить** (output)
- **Какие правила применить** (rules / gates)
- **Как проверить что правильно** (acceptance)

Один и тот же формат используется и для golden dataset (эталон), и для bug-report (что сломалось), и для регрессионной проверки (что не сломалось).

## 2. Структура описания задачи

### 2.1 Метаданные

| Поле | Описание | Пример |
|---|---|---|
| `id` | Уникальный ID | `task-math-5-pлощадь-001` |
| `created_at` | Дата создания | `2026-09-25` |
| `author` | Кто описал | PM / teacher / auto |
| `source` | Откуда задача | реальный запрос / синтетика / регрессия |
| `input_type` | Тип ввода | `text` / `photo` / `file` / `voice` |
| `subject` | Предмет | `математика` / `русский` / `английский` / ... |
| `grade` | Класс | `5` |
| `topic` | Тема | `площадь треугольника` |
| `work_type` | Тип работы | `контрольная` / `домашка` / `карточки` / `тренажёр` / `тест` |
| `difficulty` | Сложность | `базовая` / `повышенная` / `олимпиадная` |
| `language` | Язык формулировок | `ru` / `en` / ... |
| `scenario` | Сценарий учителя | «для слабого класса» / «на закрепление» / «подготовка к ОГЭ» |

### 2.2 Сырой ввод (что ввёл учитель)

Дословно, как пришло. Для фото — описание сцены. Для файла — что за файл. Для голоса — расшифровка с сохранением «шума» (оговорки, недоговорки).

```
«Площадь треугольника, 5 класс, 6 задач, средний уровень»
```

### 2.3 Интерпретация (что должен понять пайплайн)

- **Spec** в нормализованной форме: предмет, класс, тема, тип, кол-во, сложность.
- **Привязка к ФГОС**-разделу: «Геометрия, 5 класс, площади фигур».
- **УМК** если можно определить: `Школа России` / `Перспектива` / `Spotlight` / не определено.
- **Скрытые требования**: «средний уровень» = без звёздочки, «для слабого класса» = упростить формулировки, «подготовка к ОГЭ» = формат экзамена.

### 2.4 Ожидаемый output

- **Структура листа**: заголовок, шапка (предмет/класс/тема), N заданий, ключи, пояснения.
- **Типы заданий** и их количество.
- **Объём**: примерное кол-во слов / знаков.
- **Формат файла**: PDF A4 / DOCX / HTML.

### 2.5 Правила, которые должны быть применены

Чек-лист, по которому проверяется прохождение через gates:

**Пайплайн (стадии 0-7):**
- [ ] Stage 0: понимание ввода (извлечены все поля из 2.1)
- [ ] Stage 1: spec собран без потери смысла
- [ ] Stage 2: черновик сгенерирован
- [ ] Stage 3: subject critic прошёл (предметные ошибки исправлены)
- [ ] Stage 4: языковой gate пройден (для каждого языка)
- [ ] Stage 5: пед. gate пройден (сложность/разнообразие/длина)
- [ ] Stage 6: кросс-проверка ключей сходится
- [ ] Stage 7: PDF собран

**Запреты (negative rules):**
- [ ] Нет выдуманных терминов / правил / дат / имён
- [ ] Нет ответов не на тот номер
- [ ] Нет выхода за программу класса
- [ ] Нет однотипных заданий подряд (если лист >5)
- [ ] Нет несуществующих слов (для языков)
- [ ] Нет ответов в обход заданий (сначала задания, потом ключи отдельным блоком)

**Позитивные правила (positive rules):**
- [ ] Тема привязана к ФГОС-разделу класса
- [ ] Использована УМК-специфичная терминология
- [ ] Минимум 3 разных типа заданий (если лист >5)
- [ ] Диктантные тексты — с верифицированной грамматикой
- [ ] Для иностранных языков — отдельный языковой gate (времена/артикли/падежи)
- [ ] Сложность адекватна классу

### 2.6 Acceptance (как проверяем что задача решена)

- **Обязательные поля output**: что должно присутствовать.
- **Обязательные отсутствия**: чего быть не должно.
- **Edge cases**: какие нетипичные ситуации должны сработать корректно.

Пример:
- ✅ Есть 6 заданий, все по теме «площадь треугольника»
- ✅ Есть ключи с правильными ответами
- ✅ Формулировки читаемы для 5-классника
- ❌ Нет задач с дробями (если не просили)
- ❌ Нет олимпиадных задач со звёздочкой (т.к. «средний уровень»)

## 3. Типы задач (для разнообразия тестов)

### 3.1 По предмету

Минимальный набор для покрытия разных gate'ов:
- Математика (5-11) — арифметика, алгебра, геометрия
- Русский язык (1-11) — орфография, пунктуация, синтаксис, диктанты
- Английский (1-11) — грамматика, лексика, времена, артикли
- История (5-11) — даты, имена, события
- Физика (7-11) — формулы, единицы, задачи
- Биология (5-11) — термины, классификации
- Химия (8-11) — формулы, реакции
- (по необходимости) Обществознание, география, литература, информатика

### 3.2 По типу ввода

- `text` — тема текстом (самое частое)
- `photo` — фото учебника/тетради
- `file` — DOCX/PDF образца
- `photo+text` — фото + тема в свободной форме («как здесь, но про X»)
- `voice` — голосовая диктовка

### 3.3 По типу работы

- `контрольная` — 2 варианта + критерии
- `домашка` — набор заданий на закрепление
- `карточки` — 1-3 задания на карточку
- `тренажёр` — много однотипных для отработки навыка
- `тест` — с выбором ответа
- `диктант` — сплошной текст (отдельный gate)

### 3.4 Edge cases

Задачи, которые должны корректно срабатывать при разных вводах:
- Неоднозначный класс (тема «проценты» есть в 5 и в 9)
- Несколько тем в одном запросе («площадь и периметр»)
- Кривая формулировка («лист по треуг»)
- Нетипичный предмет (ОБЖ, технология)
- Иностранный язык как язык предмета (математика на английском)
- Нетривиальный УМК (не входит в топ-5)
- Запрос с ограничением объёма («короткий, на полстраницы»)
- Запрос с указанием слабого/сильного класса
- Фото плохого качества / размытое
- Голос с фоновым шумом
- Файл в экзотическом формате

## 4. Правила генерации LLM (что скилл должен делать)

### 4.1 Пайплайн (стадии)

См. основной пайплайн. Здесь — фиксация, что каждая стадия обязательна.

### 4.2 Каталог правил (версионируется отдельно)

Хранится как `rules/<id>.md` или в БД, каждое правило имеет:
- `id` — стабильный
- `category` — pipeline_stage / negative / positive / subject / language
- `description` — что проверяет
- `applies_to` — предметы/классы/типы, к которым применимо
- `version` — чтобы отслеживать изменения
- `examples_good` / `examples_bad` — референсы
- `test_tasks` — какие задачи из golden dataset проверяют именно это правило

### 4.3 Связь правил и тестов

Каждое правило в каталоге ссылается на ≥1 задачу из golden dataset, которая его проверяет. Каждая задача в golden dataset ссылается на правила, которые она покрывает. Двусторонняя связь: меняем правило → видим какие задачи его покрывают → прогоняем → не сломали ли что-то ещё.

## 5. Как используется

### 5.1 Golden dataset

- **30-50 эталонных задач**, каждая описана по формату §2.
- Покрывает: все предметы из §3.1 (хотя бы по 1-2 задачи), все типы ввода из §3.2, все типы работы из §3.3, все edge cases из §3.4.
- Источник: реальные запросы учителей (с обезличиванием) + ручная синтетика от PM.
- Версионируется в репо или в Google Sheets с привязкой к `task-id`.

### 5.2 Метрики

| Метрика | Что мерит | Порог (предварительно) |
|---|---|---|
| % листов без критичных ошибок | основной quality bar | ≥90% |
| % листов с ≤1 минорной ошибкой | качество в целом | ≥95% |
| Время генерации | UX | ≤30 сек |
| Стоимость генерации | экономика | ≤X ₽ на лист |
| Частота прохождения каждого правила | покрытие rules | ≥X% per rule |
| Частота false-positive на языковом gate | качество gate'а | ≤X% |

Пороги — к обсуждению после первого прогона на реальной выборке.

### 5.3 Eval pipeline

- **Прогон при каждом изменении**: промпта / модели / правила.
- **Подвыборка на PR** (быстрые smoke-тесты, 5-10 задач).
- **Полный прогон на релиз-кандидат** (все 30-50).
- **Разметка**:
  - **Автоматическая** — структурные проверки (формат, наличие полей, ключи сходятся).
  - **Ручная** — содержательные (правильность по предмету, пед. пригодность, языковая чистота) — PM + приглашённый учитель.
