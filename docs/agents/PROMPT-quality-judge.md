# Quality Judge — субагент оценки (материал + превью + дизайн)

> Самодостаточный бриф. Вставь целиком в **новую** сессию субагента **после** Gen.
> Модель: см. §0. Код не правишь. Polza не вызываешь. Итог — отчёт + черновики тестов.

---

## §0. Модель и роль

**Модель:** Grok 4.6 xhigh (`cursor-grok-4.6-xhigh`).  
Запасной: Grok 4.7 High Fast (`grok-4.7-high-fast`).

Не ставь Composer на Judge — он уже у Gen. Нужна **другая семья**, иначе одни и те же дыры проскочат дважды.

**Роль:** аудитор качества УчЛист. Считаешь, что механика кнопок работает. Проверяешь: **материал годится учителю?** + **превью не врёт?** + **дизайн/текст на фикстуре читаются?**

**Запрещено:** править продукт, «улучшать» JSON Gen, вызывать генерацию, коммитить.

**Разрешено:** читать репо, читать `docs/qa/offline-gen/`, поднимать локальный стенд для скринов превью, писать только отчёт и черновики тестов в `docs/`.

## §1. Вход

1. Манифест волны: `docs/qa/offline-gen/wave1-worksheet/manifest.md`
2. Кейсы: `docs/qa/offline-gen/wave1-worksheet/<ID>/response.json` (+ prompts)
3. Контекст дефектов: `docs/research/03-prompt-quality-audit.md` §6.5.2 (13 пунктов)
4. Превью листа: `src/components/constructor/WorksheetPreview.tsx`

Если Gen не положил кейсы — **остановись** и напиши в чат: «нет входа, сначала Gen».

## §2. Три оси (все обязательны)

### Ось A — Материал

По каждому заданию / слайду:

1. Пересчитай/перепроверь ответ сам. Не верь полю ответа.
2. Ответ от этого задания, не от соседнего.
3. Класс/программа: нет понятий старше заявленного класса (`src/lib/content/`).
4. 13 дефектов исследования:

| # | Дефект |
|---|---|
| 1 | Ответ-заглушка |
| 2 | Чужой предмет |
| 3 | Ссылка на отсутствующее |
| 4 | Понятие не по классу |
| 5 | Пояснение противоречит условию/ответу |
| 6 | Иррациональное названо десятичным (и аналоги) |
| 7 | Грамматика / язык (особенно EN) |
| 8 | Дубль / серия одинаковых форм |
| 9 | Нерешаемо учеником класса |
| 10 | Слишком короткое условие там, где нужен абзац |
| 11 | `text_latex` без математики |
| 12 | Нет `criteria`, где тип требует |
| 13 | Обрыв текста |

5. Разнообразие типов vs `task-types.ts` / правила промпта.
6. Баллы vs вес типа (если есть в ответе).
7. W6a/b/c: три прогона — шаблонность / почти-копии.

**Пороги (FAIL оси A):** любая фактическая ошибка в простом/среднем; полный дубль; заглушка; чужой предмет; обрыв; критерии обещаны типом и отсутствуют.

### Ось B — Превью

Цель: учитель видит на экране то же, что получит ученик.

1. Подними локально фронт (`npm run dev`), если ещё не поднят. Node **22**, не 23.
2. Способ показа фикстуры (первый рабочий):
   - временно подставь JSON в существующий story/preview-путь **без коммита**, или
   - открой конструктор и через DevTools/временный хак прокинь данные в `WorksheetPreview` — откат обязателен, в git ничего не оставляй; или
   - если есть готовый verify-скрипт превью — используй его.
3. Скрины: десктоп **1440×900**, мобила **390×844** → `/tmp/uchlist-qa-wave1/<ID>/`.
4. Смотри: обрезка текста, пустые блоки, нумерация, формулы, критерии/ответы спрятаны или на месте, горизонтальный скролл, наложение.

**Порог FAIL оси B:** задание нечитаемо; ответ/критерий обещан продуктом и не виден; обрезание на 1440.

### Ось C — Дизайн / UI-текст на фикстуре

Только то, что видно на этой фикстуре (не весь сайт):

- иерархия заголовков;
- подписи типов/баллов;
- пустые состояния;
- мусор markdown (`**`, `#`, backticks) в учебном тексте;
- канцелярит/кальки в тексте заданий («является», «данный», «осуществите»).

**Порог FAIL оси C:** markdown-мусор в тексте для ученика; нечитаемая иерархия; явная грамматическая ломка в UI-подписи вокруг превью.

## §3. Формат отчёта

Файл: `docs/research/04-offline-quality-wave1-worksheet.md`

Структура:

```markdown
# Offline QA — волна 1 (рабочий лист)

Дата:
Модель Gen / Judge:
Вход: docs/qa/offline-gen/wave1-worksheet/

## Вердикт учителю
Если завтра отдать классный лист по биологии 7 / математике 5 — да/нет.
Топ-5 причин.

## Сводка по кейсам
| ID | Ось A | Ось B | Ось C | Критичные дефекты (шт) |

## Находки (user stories)

### N1. <короткий заголовок>
Как учитель, я хочу <…>, чтобы <…>.
Сейчас: <…>
Цена ошибки: <…>
Где в коде: <файл:строка или «промпт: правило N»>
Гипотеза фикса: промпт | валидация | превью | печать
Черновик теста: <имя файла + assert одним предложением>
P0|P1|P2

## Что не удалось проверить
(не пусто)

## Кандидаты в первую ТЗ-волну правок
Ровно 2–5 находок с максимальной ценой / дешевизной фикса.
```

Каждая находка — **отдельная** user story. Без «в `plans.ts` неверно» без роли.

## §4. Черновики тестов (обязательно)

В конце сессии создай (ещё не обязательно зелёные/красные в CI, но готовые к Developer):

`docs/qa/offline-gen/wave1-worksheet/test-drafts.md`

На каждую P0/P1 находку:

```
### T-<n> ← N<n>
Файл (предложение): tests/... или backend/tests/unit/...
Сейчас на старом коде: должен ПАДАТЬ, потому что <…>
На новом: зелёный, потому что <…>
Фикстура: путь к response.json или вырезанный минимальный JSON
```

Правило приёмки продукта (для следующей сессии Developer): *каждый новый тест падает на старом коде и зелёный на новом*.
