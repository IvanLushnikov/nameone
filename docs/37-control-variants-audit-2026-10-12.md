# Аудит: почему контрольная приходит одним вариантом или с повторами

Дата: 12.10.2026. Жалоба: «контрольная английский 11 класс, 2 варианта —
задания повторяются, два варианта не сделано».

Проверяющий скрипт: `scripts/diagnose-control-variants.mjs`.

## Как идёт запрос

1. Фронт: `generateWorksheetSmart` — один POST на `/api/worksheets/generate`.
2. Роут `backend/src/routes/worksheets.ts:168` зовёт `generateWorksheet`.
3. `backend/src/llm/index.ts:196` собирает промт через `buildWorksheetPrompt`.
4. Один вызов модели. В ответе ожидается `{ variants: [v1, v2] }`.
5. `index.ts:258` достаёт `variants[0]` и `variants[1]`.
6. Каждый вариант проходит `filterTasks` и `sanitizeTextLatex`.
7. Роут возвращает `worksheet` + `secondVariant`.
8. Фронт рисует `ControlVariantSwitch` — но только если `secondVariant` не null.

## Промты, которые реально уходят в модель

| Файл | Роль | Про варианты |
|---|---|---|
| `backend/src/llm/prompts/worksheet-gen.ts` | system | есть блок про `variants`, есть требование «Варианты — РАЗНЫЕ» |
| `backend/src/llm/prompts/worksheet-gen.ts` | user | `type` передаётся голым значением, слова «вариант» нет |
| `backend/src/llm/index.ts:213` | параметры вызова | `maxTokens` 8192 для control, 4096 иначе |

## Где теряется различие

### 1. User-промпт не просит два варианта

Различие вариантов живёт только в system-промпте, в самом конце, после
двенадцати правил. В user-промпте `type: "control"` — просто значение
поля, без пояснения. Модель обязана сама вспомнить двенадцатое правило.

### 2. В коде нет проверки «варианты разные»

`variants[1]` берётся как есть. Никто не сверяет тексты заданий первого и
второго варианта. `filterTasks` про варианты ничего не знает — он чистит
каждый список по отдельности, межвариантных повторов не видит.

### 3. Модель легко отдаёт два одинаковых листа

Один вызов, temperature 0.7, требование «два разных варианта» — вторая
половина ответа по умолчанию повторяет первую: это самая частая форма
«задания повторяются». Никакой код это не ловит.

### 4. Пустой второй вариант тихо прячется

Если модели не хватило токенов, `variants[1]` может не прийти или прийти
пустым. Тогда `secondVariant = null`, фронт не рисует переключатель — и
учитель получает один лист. Признака «второй вариант не удался» в ответе
API нет: поле просто отсутствует, как будто так и задумано.

### 5. Кэш — здесь вариант не при чём

Ключ кэша строится из subject/grade/topic/difficulty/count/type/userId.
`variant` в ключе нет, но и не должен: оба варианта приезжают одним
ответом и кладутся в кэш парой `{ worksheet, secondVariant }`. Запись
контрольной без `secondVariant` считается промахом и сносится. Эта часть
сделана правильно.

### 6. Английский — отдельная слепая зона

`language-guard` для иностранных языков всегда пропускает текст. Для
русскоязычного предмета обрыв ответа по токенам приводит к
`InternalError`, а для английского — нет. Второй вариант может
получиться оборванным, и это пройдёт как обычный ответ.

## Что чинить (в порядке важности для учителя)

1. Сверять варианты после ответа и перегенерировать, если задания совпали.
2. Не прятать отсутствие второго варианта: отдавать признак в ответе API.
3. Указать в user-промпте, что нужен именно `type=control` и два разных
   варианта — не полагаться на память модели о system-промпте.
4. Ловить обрыв ответа по `finish_reason` и для иностранных языков.
