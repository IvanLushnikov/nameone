# ТЗ-41: Prompt cache — провайдеру надо сказать «закэшируй», и деньги за это посчитать

> **Статус:** 🔴 Не начато.
> **Приоритет:** 🟡 высокий · **Волна:** 2 · **Трудоёмкость:** 4 дн
> **Закрывает проблемы:** M-01
> **Связано:** TZ-42 (учёт `cached` и `cache_read` в логах и норме — там же
>   `backend/src/llm/index.ts`; здесь только провайдер и калькулятор денег)

## 1. Контекст и зачем

У контрольной работы system-промпт — 12 799 токенов. Он уходит провайдеру на
каждом вызове и тарифицируется по полной входной цене. Для контрольной это
**36 % списания**: факт 8,51 ₽ против 6,30 ₽, если бы чтение шло по цене
prompt cache (23,97 ₽ за 1M против 239,65 ₽).

Кэша нет. Причина видна в коде:

- флаг `cacheSystemPrompt` выставляется честно — `backend/src/llm/index.ts:550`
  через `supportsPromptCache(model)`;
- **но polza-провайдер его не читает**: тело запроса (`backend/src/llm/providers/polza.ts:74-90`)
  содержит `model`, `messages`, `max_tokens`, `temperature`, `response_format` —
  и **ни одного `cache_control`**;
- единственное место, где `cache_control` формируется, — `backend/src/llm/providers/anthropic.ts:68-77`,
  а этот провайдер в проде не используется: polza — единственный
  (`backend/src/llm/config.ts:99`).

Документация polza (проверена 29.10.2026, `polza.ai/docs/osobennosti/caching`):
у Claude кэш **ручной** — `cache_control: {type: "ephemeral"}`, чтение 0,1×,
запись 1,25×, TTL 5 минут или 1 час; у OpenAI кэш **автоматический**, порог
1 024 токена.

### Шаг 1 (обязательный, до правки кода): живой пробный вызов

Один запрос к polza с ключом, где system-сообщение отправляется массивом
content-parts с `cache_control`. Проверяем три вещи:

1. **Провайдер не отвергает поле.** Если polza отвечает 400 на неизвестное
   поле — вариант A невозможен, и сразу переходим к варианту B (нативный
   эндпоинт `/v1/messages`).
2. **`usage.prompt_tokens_details.cached_tokens` приходит и растёт.** Два
   одинаковых запроса подряд: во втором `cached_tokens > 0`.
3. **`usage.cost_rub` во втором меньше.** Это главная цифра.

Если polza принимает поле, но `cached_tokens` остаётся 0 — кэш через
OpenAI-совместимый путь не работает, и вариант A закрыт.

**Результат шага 1 — обязательная часть приёмки:** числа из ответа провайдера
(`cached_tokens`, `cost_rub` до и после), а не пересказ документации.

### Тело запроса (вариант A)

```ts
// backend/src/llm/providers/polza.ts
const useCache = args.cacheSystemPrompt === true;
const messages = args.messages.map((m, i) => {
  if (i !== 0 || m.role !== "system" || !useCache) {
    return { role: m.role, content: m.content };
  }
  return {
    role: m.role,
    content: [{ type: "text", text: m.content, cache_control: { type: "ephemeral" } }],
  };
});
```

Если провайдер отвечает 400 на такой формат — откат к плоскому `content`
(сохраняем работоспособность ценой кэша) и переход к варианту B.

### Вариант B (если A не работает)

Перевести Claude-типы на нативный эндпоинт polza `/v1/messages`, где
`cache_control` поддерживается штатно, а счётчики `cache_read_input_tokens` /
`cache_creation_input_tokens` приходят отдельными полями. Это переписывание
разбора ответа — **отдельная оценка: M (4–5 дн) сверх этой задачи**, и
решение по ней — за владельцем (это уже не «правка», а «смена пути вызова»).

### Деньги

```ts
// backend/src/llm/providers/polza.ts
const costUsd = calcCost(args.model, tokensIn, tokensOut, {
  cacheRead: cachedTokens,      // прочитано из кэша
  cacheWrite: cacheWriteTokens, // записано в кэш (Anthropic: 1,25× input)
});
```

`cacheWriteTokens` берётся из `usage.cache_creation_input_tokens`, если
провайдер его отдаёт; иначе — 0.

### Что НЕ меняется в этой задаче

- `backend/src/llm/index.ts` (учёт в логах и норме — TZ-42),
- таблицы и миграции,

- тарифы и нормы.

## 4. Решения

**AD-1 · Сначала пробный вызов, потом код.**
Один живой вызов решает, какой вариант реализуем.
*Рационал:* документ polza описывает кэш для нативного Anthropic-формата. Наш
путь — OpenAI-совместимый (`/chat/completions`), и как polza обрабатывает
`cache_control` в нём, по документации не определяется. Править код, не
проверив формат, — значит отдать тестовый вызов в прод.

**AD-2 · Кэш включаем только для моделей, которые его держат.**
Флаг `cacheSystemPrompt` уже считается по свойству модели — правило не меняем.
*Рационал:* у Luna в `MODEL_COSTS` нет `cacheReadPer1M`, то есть её
автоматический кэш мы посчитать не можем.

**AD-3 · Запись в кэш стоит 1,25× входа — это учитывается в деньгах.**
`cacheWrite` идёт отдельной строкой в `costBreakdown`.
*Рационал:* иначе «включили кэш» будет выглядеть как удорожание на одиночном
вызове (TTL 5 минут — кэш может не успеть окупиться).

**AD-4 · Правило «system-промпт не меняем без миграции» возвращается в силу.**
*Рационал:* сейчас это правило охраняет кэш, которого нет, и потому выглядит
пустым. С кэшем оно снова становится денежным: смена промпта обнуляет кэш у
всех, кто его пользует.

**AD-5 · Если формат polza не принимает `cache_control` — откат, а не молчание.**
Провайдер продолжает работать без кэша, в лог пишется предупреждение.
*Рационал:* поломанный вызов листа хуже листа без кэша.

**AD-6 · Оценка экономии даётся на факте, а не на формуле.**
Число «2,8 ₽ с контрольной» — расчёт по ценам из документации. После выкатки
число берётся из `llm_costs_actual.cost_rub` (TZ-45).

## 5. Критерии приёмки

Функциональные:
- [ ] Живой пробный вызов выполнен, и его результат зафиксирован: `cached_tokens` первого и второго вызова, `cost_rub` первого и второго.
- [ ] Во втором вызове (тот же system-промпт, в пределах TTL) `cached_tokens > 0`.
- [ ] `cost_rub` второго вызова меньше первого — либо проба показала, что кэш через этот путь не работает, и тогда задача закрывается честным отрицательным результатом с планом B.
- [ ] Тело запроса к polza содержит `cache_control: {type: "ephemeral"}` в system-сообщении, когда `cacheSystemPrompt === true` (тест на перехваченном теле).
- [ ] Тело запроса НЕ содержит `cache_control`, когда флаг выключен (тест).
- [ ] `calcCost` с `cacheRead` считает меньше, чем без него (тест на `cost.ts`).
- [ ] `cacheReadTokens` провайдера заполняется из `usage`.

Регрессионные:
- [ ] Модель без поддержки кэша (Luna) шлёт запрос в прежнем формате — плоский `content`.
- [ ] Если polza отвечает 400 на content-parts, провайдер **откатывается** к плоскому формату, генерация не падает, в лог пишется предупреждение.
- [ ] Существующие тесты провайдера (`backend/tests/unit/**polza**`) — зелёные.

Качественные:
- [ ] В шапке `worksheet-gen.ts` правило о неизменности system-промпта снова на месте и ссылается на эту задачу.
- [ ] НОВЫЙ тест падает на старом коде: на старом коде в теле запроса нет `cache_control`. Результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не переписываем system-промпт.** Правка промпта обнулит кэш — сначала
  кэш, потом промпт.
- **Не переводим Claude на нативный эндпоинт в этой задаче.** Это вариант B,
  отдельная оценка и отдельное решение.
- **Не меняем нормы и тарифы.** Экономия придёт в тариф через TZ-44/TZ-45.
- **Не трогаем `backend/src/llm/index.ts`** — учёт там (TZ-42).
- **Не добавляем зависимостей.**

## 8. Порядок работ

1. (1 дн) **Шаг 1: пробный живой вызов.** Ответ провайдера сохранить в отчёт (без ключа и без содержимого промпта). **Первая точка решения: поддерживает ли polza `cache_control` в этом формате.**
2. (1 дн) Правка `providers/polza.ts`: content-parts + `cache_control`, `cacheReadTokens`, `calcCost` с `opts`.
3. (0,5 дн) Тесты на тело запроса (с кэшем и без) и на откат при 400.
4. (0,5 дн) Второй живой вызов: подтвердить `cached_tokens > 0` и снижение `cost_rub`.
5. (0,5 дн) Возврат правила в шапке `worksheet-gen.ts`; прогон бэкенд-тестов.
6. (0,5 дн) Передать данные в TZ-42 (учёт `cached` и `cache_read` в логах).

## 9. Что не удалось подтвердить

- **Сколько вызовов провайдера реально не использовало кэш.** Реестр пишет
  «`cached = 0` у 99 вызовов `gpt-6-luna`, 15 `claude-sonnet-5-5` и 415
  `deepseek-v4-flash`» — но в снимке прода от 29.10.2026 **все SQL-запросы
  упали** (`/tmp/q.sh: No such file or directory`, `JSONDecodeError`), и этих
  чисел в базе прочитать не удалось. Факт, который стоит на коде: polza
  **не отправляет** `cache_control` — значит, кэш не мог сработать ни разу.
  Сколько именно вызовов прошло — по D1 без доступа не считается.
- **Точная экономия.** 2,8 ₽ с контрольной — расчёт по ценам из документации
  polza и по `tokens_in = 12 799`, взятому из снимка владельца (не из нашего
  прогона). Фактическая — после выкатки, из `llm_costs_actual`.
- **Поддерживает ли polza автоматический кэш OpenAI-моделей.** Порог 1 024
  токена выполнен (4 374), но `cached_tokens` в ответах не наблюдалось.
  Проверяется тем же пробным вызовом.
