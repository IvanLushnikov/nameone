# ТЗ-28: Мобильный доступ ученика — сдача работы с телефона без приложения

**Дата:** 15 октября 2026
**Продолжение:** `docs/tz/12-online-forms.md`, `docs/tz/22-class-grading.md`
**Кто делает:** фронт + бэк
**Размер:** L (короткая ссылка + фото + PWA + черновик)

---

## 1. Проблема в словах учителя

«Я выдала QR на доске, тринадцать человек открыли, а остальные пятнадцать сказали, что не пришло. Или пришло, но не с телефона, а с домашнего компьютера — и там ещё вопросы, как сохранить.»

Ученик на уроке получил ссылку. Дальше начинается не работа, а техника.

## 2. Что уже работает (не переписываем)

| Механика | Где | Состояние |
|---|---|---|
| Форма по ссылке/QR, ученик отвечает без входа | `backend/src/routes/publicForms.ts:224` | Работает |
| Персональная ссылка: имя подставляет сервер | `backend/src/routes/classes.ts:1067` | Работает |
| Страница ученика отдаёт снимок заданий | `publicForms.ts:320` | Работает |
| Общий лимит на класс: 60/час на пару «форма + IP» | `classes.ts:1-40` | Работает, ТЗ-22 §4 |
| Страница `/form` — статическая, токен в query | `src/app/form/page.tsx` | Работает, схема из-за `output: "export"` |

Ограничение, которое определяет всю конструкцию: фронт собирается как статика (`output: "export"`), динамических маршрутов с токенами быть не может. Поэтому страница ученика — одна статическая, а код и токен приходят в query.

## 3. Сценарий 1 — учитель один раз кидает классу ссылку

**Кто:** учитель 5А, 27 человек, урок по окружающему миру.

**Шаг 1. Учитель открывает класс в кабинете.**
`Мои классы` → «5А» → блок с составом (`ClassRosterSection.tsx`).

**Что видит учитель (новое):** в шапке блока с классом — поле «Ссылка для класса» и большая кнопка «Скопировать». Рядом — QR, который учитель может распечатать, но теперь QR ведёт на ту же короткую ссылку, а не на длинный адрес с токеном.

**Шаг 2. Учитель жмёт «Скопировать».**
В буфер обмена попадает `https://uchlist.ru/k/7F2KQ9`. Учитель вставляет его в классный чат.

**Что происходит под капотом:** код `7F2KQ9` — 6 знаков, без похожих символов (нет `0/O`, `1/I/L`), чтобы учитель продиктовал его вслух и ученик не ошибся.

**Что учитель не должен делать:** рассылать 27 персональных ссылок вручную.

**Шаг 3. Ученик открывает ссылку с телефона.**
Видит страницу с заданием. **Имя не спрашивается** — сервер его подставляет.

**Когда сервер не знает, кто ученик:** если ссылка открыта в новом браузере, где ученик ещё не был, сервер отдаёт экран «Введите фамилию и имя». После этого страница помнит ученика на этом телефоне, и при следующем открытии ссылки фамилия не спрашивается.

**Границы:** если учитель не завёл класс, короткой ссылки нет — нечего копировать. Поле появляется вместе с классом, не раньше.

## 4. Сценарий 2 — ученик фотографирует ответ вместо того, чтобы вбивать

**Кто:** тот же ученик, математика, задание «реши уравнение» — три задания с развёрнутым ответом.

**Шаг 1.** Ученик открывает задание, видит снимок заданий.

**Шаг 2.** В каждом задании, где это допускает, под полем ответа — кнопка «Сфотографировать». Камера телефона открывается прямо на этой странице.

**Шаг 3.** Ученик фотографирует написанное в тетради, подтверждает, фото уходит в тот же контур, что и работы по фото тетради из ТЗ-11: бакет `PDFS`, удаление через 7 дней, те же лимиты.

**Шаг 4.** Учитель открывает форму в журнале и видит фото рядом с ответом. Разбор фото делает тот же код, что и для работ по фото тетради (`backend/src/services/photoCheckGrading.ts`).

**Что учитель видит в ведомости:** рядом с фамилией — пометка «фото» и число страниц. Учитель понимает: это не пустой ответ, а фотография, которую машина не смогла разобрать.

**Что делать, если машина не смогла:** учитель открывает фото и ставит отметку руками, как сейчас в журнале. Путь с фото не обязан заканчиваться автоматически.

**Правила съёмки:**
- фото больше 2000 px по длинной стороне сжимается на телефоне до отправки;
- формат JPEG;
- один ученик — один файл на задание, второй снимок заменяет первый;
- если связь пропала в момент отправки — фото остаётся на телефоне, кнопка «повторить» появляется сама.

## 5. Сценарий 3 — ученик ставит страницу на домашний экран

**Кто:** ученик, у которого домашние задания проверяют вечером.

**Шаг 1.** Ученик открывает страницу заданий и видит внизу подпись: «Поставь на домашний экран — не придётся каждый раз искать в браузере».

**Шаг 2.** На Android: меню браузера → «Установить приложение». На iPhone: кнопка «Поделиться» → «На экран «Домой»».

**Шаг 3.** На домашнем экране появляется иконка УчЛиста. По нажатию открывается страница заданий, без адресной строки, без поиска ссылки.

**Что делает учитель:** ничего. Это делает ученик, который не потерял ссылку.

**Границы:** установка на iOS работает только из Safari. Это ограничение платформы, поэтому инструкция на странице разная для iOS и Android — двумя строками с картинкой.

## 6. Сценарий 4 — ученик не потерял начатое

**Кто:** ученик, который набирал ответ, отвлёкся, телефон разблокировался — страница перезагрузилась.

**Шаг 1.** Ученик снова открывает страницу. Видит блок поверх заданий: «У тебя есть неотправленные ответы. Восстановить?» — одна кнопка, без объяснений.

**Чаг 2.** Жмёт. Все введённые ответы возвращаются в поля.

**Что учитель не должен делать:** разбираться, что ученик «не дописал и отправил пустое». Ответ, который не отправлен, не отправлен — ученик увидит напоминание.

**Где хранится:** на телефоне, в `localStorage`, по ключу класса. Ничего не уходит на сервер, пока ученик не нажал «Отправить».

## 7. Технические решения

**AD-1 · Короткий код класса, а не токен ученика.**
Класс получает `class_code` из 6 знаков. Открытие `/k/<код>` без сессии ученика показывает экран ввода фамилии и запоминает выбор в `localStorage` + `Cookie`.
**Рационал:** 30 персональных ссылок учитель не рассылает руками. Код запоминается на телефоне один раз.

**AD-2 · Код не самостоятельный пропуск — он открывает только задания, а приём ответа идёт по лимиту.**
Любой запрос к `/k/<код>` требует, чтобы класс существовал; отправка ответа дополнительно ограничена лимитом 60/час на «форма + IP».
**Рационал:** иначе перебор 6 знаков = перебор учеников. Приватность здесь держится не на длине кода, а на том, что код не отдаёт чужие работы.

**AD-3 · Фото идёт в существующий контур, а не в новый.**
`POST /api/public/class-links/:st/forms/:t/submit` получает новое необязательное поле `photo_r2_key`. Разбор — `services/photoCheckGrading.ts`, срок хранения — 7 дней, как у фото тетради.
**Рационал:** второй контур хранения фото — это второе место, где можно забыть про удаление персональных данных.

**AD-4 · Черновик только на телефоне.**
`localStorage`, ключ `uchlist:draft:<class_code>`. Сервер о нём не знает.
**Рационал:** черновик — это неподтверждённый ответ, хранить его на сервере незачем, а удалять потом придётся.

## 8. Форматы

**Новый статический маршрут:** `src/app/k/[code]/page.tsx` — при `output: "export"` это невозможно, поэтому страница одна: `/k`, код читается в `useEffect` из `window.location.search` так же, как сейчас читается токен в `FormRunner.tsx`. Маршрут: `https://uchlist.ru/k?c=7F2KQ9`.

**Новый эндпоинт:** `GET /api/classes/code/:code/tasks` — отдаёт задания класса и, если в `Cookie` есть `class_student_<code>`, имя ученика. Без cookie отдаёт `{ needName: true }`.

**Изменение в существующем:** `POST /api/public/class-links/:st/forms/:t/submit` — новое необязательное поле `photo_r2_key`. Старые отправки работают как раньше.

**Новые статические файлы:** `public/manifest.webmanifest`, `public/icons/icon-192.png`, `public/icons/icon-512.png`.

## 9. Acceptance criteria

- [ ] В блоке класса есть «Ссылка для класса»: кнопка «Скопировать» и QR, обе ведут на один и тот же код.
- [ ] Код — 6 знаков без похожих символов (0/O, 1/I/L) при выдаче.
- [ ] Ссылка открывается на телефоне без входа; при первом открытии спрашивается фамилия, при следующем — нет.
- [ ] Ученик видит только свои задания; чужой ученик, открывший ту же ссылку, получает свои, а не чужие.
- [ ] Если класс не заведён, поля со ссылкой нет; при попытке открыть несуществующий код — 404 с понятным текстом.
- [ ] В допускающих заданиях есть кнопка «Сфотографировать»; камера открывается на странице.
- [ ] Фото длиннее 2000 px сжимается на клиенте; второй снимок заменяет первый.
- [ ] Фото попадает в ведомость с пометкой и разбирается тем же кодом, что работы по фото тетради.
- [ ] При исчерпании лимита фото не теряется: есть кнопка «повторить», она срабатывает после восстановления сети.
- [ ] Фото ученика удаляется через 7 дней тем же триггером, что и фото тетради (проверяется тестом на одну дату).
- [ ] Страница ставится на домашний экран: manifest, иконка 192 и 512, режим standalone.
- [ ] Без сети страница открывается и показывает последний снимок заданий с пометкой «нет связи».
- [ ] Неотправленный ответ предлагается восстановить одной кнопкой; сервер о черновике не знает.
- [ ] Лимиты не изменились: 60/час на пару «форма + IP», 200/час на IP.
- [ ] На странице заданий есть инструкция установки отдельно для iOS и для Android.

## 10. Чего не делаем

- **Не делаем нативное приложение.** Другой бюджет и другая поддержка. PWA закрывает задачу «ссылка в телефоне» полностью.
- **Не делаем Telegram-бота.** Учителя его хотят, но бот требует отдельного канала приёма фото и отдельной модерации. PWA решает то же самое дешевле. Вернуться к боту можно, когда появятся цифры по конверсии.
- **Не отправляем ученику уведомления.** Нет ни его контакта, ни согласия на рассылку. Учитель отправляет сам, это сознательный отказ от спама.
- **Не спрашиваем пароль.** Персональная ссылка и есть вход.

## 11. Риски

- **6 знаков перебираются.** Код открывает только задания, а не чужие работы; приём ответа ограничен лимитом. Для чувствительных классов (старшая школа, олимпиадный поток) включаем режим с подтверждением по фамилии.
- **Фото ученика — персональные данные.** Срок 7 дней уже прописан для фото тетради, здесь тот же срок и тот же триггер, отдельного механизма удаления не заводим.
