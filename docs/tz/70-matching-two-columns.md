## 1. Контекст и зачем

Как учитель, я хочу, чтобы «установите соответствие» содержало обе колонки, чтобы ученик мог сопоставить, а не гадать буквы.

Сейчас: биология W2 з.3 — в `items` три органоида, ответ «1-в, 2-б, 3-а», букв а/б/в на листе нет. Английский W3 з.5 — два предложения, значений нет. Задание нерешаемо.

Цена ошибки: учитель в классе импровизирует или выкидывает лист.

Где подтверждено 02.11.2026: `quality-filter.ts` в `checkTaskTypeRequirements` для `matching` требует только непустой `items` (`:397-405`). Реестр пишет: «в `items` — элементы правой колонки» (`task-types.ts:195-203`) — левая колонка должна быть в тексте, но код это не проверяет.

## 3. Технический дизайн

| Файл | Что меняем |
|---|---|
| `src/lib/content/task-types.ts` | У `matching`: ясный `whatTeacherAsks` — **левая колонка с метками а/б/в в `text`**, правая — в `items` (или пары «элемент — значение» в `items`). Добавить в `TaskTypeSpec` опциональный флаг `needsLetterLabelsInText?: boolean` (true только у matching) — декларативно, без `if (type === "matching")` вразнобой |
| `backend/src/llm/validation/quality-filter.ts` | В `checkTaskTypeRequirements`: если у спеки `needsLetterLabelsInText` и ответ похож на пары `1-а` / `1-в`, а в `text` нет меток `а)`/`а.`/`а —` (и в `items` нет строк, начинающихся с буквенных меток) → `"matching-without-right-column"` |
| `backend/src/llm/cache.ts` | `FORMAT_VERSION += 1` в том же коммите |
| `backend/tests/unit/quality-filter.test.ts` | Кейсы из T-2: фикстура W2 з.3 падает/режется; matching с буквами в тексте — проходит |
| `backend/tests/unit/cache-format-version.test.ts` | Обновить хэш после подъёма версии (как принято в репо) |

**Эвристика «ответ — пары с буквами»:** ответ матчит `/\d\s*[-–—:]\s*[а-яa-z]/iu` хотя бы раз.

**Эвристика «метки есть»:** в `text` или в любом `items[]` есть `(^|[\s(;])[а-яa-z][)\]\.\:]/iu` или явные «а)», «б —».

Пример плохого (режем):

```json
{
  "type": "matching",
  "text": "Установите соответствие между органоидом и функцией.",
  "items": ["1) ядро", "2) митохондрия", "3) клеточная стенка"],
  "answer": "1-в, 2-б, 3-а"
}
```

Пример хорошего (оставляем):

```json
{
  "type": "matching",
  "text": "Соотнесите: а) хранит ДНК б) синтез белка в) клеточная стенка растений",
  "items": ["1) ядро", "2) рибосома", "3) клеточная стенка"],
  "answer": "1-а, 2-б, 3-в"
}
```

---

## 4. Решения (AD-N)

**AD-1 · Правило в реестре, проверка из флага.**  
Флаг `needsLetterLabelsInText` на типе, а не голый `if (rawType === "matching")` без данных.  
*Рационал:* следующий тип с двумя колонками добавится записью в реестре.

**AD-2 · Режем задание, не «чиним» колонки.**  
Модель не дописала правую колонку — дописать за неё нельзя честно.  
*Рационал:* тот же паттерн, что `pattern-without-sample`.

**AD-3 · Подъём FORMAT_VERSION.**  
Текст `whatTeacherAsks` меняет system-промпт.  
*Рационал:* правило репозитория ТЗ-35 / AGENTS.md.

---

## 5. Критерии приёмки

- [ ] Фикстура W2 з.3 (`matching` + ответ `1-в…` без меток в text/items) → `checkTaskTypeRequirements` возвращает `matching-without-right-column`; в `filterTasks` номер попадает в `droppedTypeMismatch`
- [ ] Matching с метками а/б/в в `text` и тем же ответом → проверка возвращает `null`
- [ ] Каждый новый тест **падает на старом коде** и зелёный на новом (вывод в отчёте)
- [ ] `FORMAT_VERSION` поднят; `cache-format-version` зелёный
- [ ] Промпт-блок для matching в `buildTaskTypesPromptBlock` содержит требование двух колонок / меток

---

## 6. Чего не делаем

- Не меняем схему формы для ученика (ТЗ-16, 5 типов автопроверки).
- Не вводим отдельное поле `rightColumn` в JSON ответа модели — хватает text+items.
- Не трогаем печать DOCX отдельно (после фильтра плохое matching до печати не доезжает).
- Не чиним N5/N11 в этом ТЗ.

## 7. Риски

| Риск | Цена ошибки | Что делаем |
|---|---|---|
| Ложное срабатывание на matching без буквенных пар в ответе | Лишнее выкидывание | Эвристику букв включаем **только** если ответ похож на `N-буква` |
| Сброс semantic cache | Холодный кэш на всех типах | Осознанно: FORMAT_VERSION; в отчёте написать номер версии до/после |
