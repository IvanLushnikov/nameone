# ТЗ-30: Честные деньги — счётчик выручки и обещанное, чего нет

**Дата:** 15 октября 2026
**Кто делает:** бэк (пункты 1, 2, 4, 5), фронт (пункт 3)
**Размер:** S по деньгам, M по редактированию листа

---

## 1. Проблема

Цены снизили 12 октября: было 500 / 990 / 1500 ₽, стало 249 / 499 / 999 ₽. Биллинг и прайс обновились, **а админка — нет**. `backend/src/routes/admin.ts:51-59` до сих пор считает выручку по старым числам.

Это поломка, а не косметика. По этой цифре владелец принимает решение «хватает ли денег». Сейчас решение принимается по выдуманной выручке.

Четыре вещи, о которых мы говорим пользователю, а их нет: редактирование листа отдаёт 501, генерация картинок — 503, длительность экзамена захардкожена, число страниц в журнале считается на лету.

## 3. Сценарий 1 — владелец смотрит деньги и принимает решение

**Кто:** владелец продукта, понедельник, сверка недели.

**Шаг 1.** Открывает `Деньги` (`/superpower/money`).

**Что видит сейчас:** «Средний чек 1 240 ₽» при средней цене тарифа 249–999 ₽. Числа завышены почти втрое.

**Что видит после изменения:** те же экраны, те же графики, цифры из настоящих платежей. Средний чек считается по фактическим суммам платежей, а не по таблице цен.

**Шаг 2.** Владелец смотрит на порог «себестоимость выше 25% выручки». Раньше он не срабатывал никогда, потому что выручка была завышена. Теперь он срабатывает по делу, и это может означать, что тарифы надо поднимать — но это уже решение, а не ошибка в счётчике.

**Граница задачи:** сами цены и нормы не трогаем, они утверждены 12.10. Меняется только то, откуда берётся число.

## 4. Сценарий 2 — учитель хочет поправить сгенерированный лист

**Кто:** учитель, сделал лист по теме «Дроби», в третьем задании опечатка.

**Шаг 1.** Учитель открывает свой лист (`/preview` или из истории в кабинете).

**Шаг 2.** Нажимает «Редактировать».

**Что видит:** поля как при создании — текст задания, ответ, пояснение. Метка темы, если лист создан после ТЗ-27, редактируется в этом же месте.

**Шаг 3.** Правит текст, жмёт «Сохранить».

**Что происходит:** лист перегенерируется не через ИИ, а пересобирается из сохранённой структуры. Плата за генерацию не списывается — учитель уже заплатил за этот лист, повторный клик не должен стоить токенов.

**Шаг 4.** Учитель скачивает DOCX — правка видна в файле.

**Что учитель видит, если правка приведёт лист в бессмысленное состояние:** кнопка «Сохранить» неактивна, под полем подпись «после сохранения проверить работу будет нельзя». Не блокируем молча, объясняем.

## 5. Сценарий 3 — учитель не может понять, сколько страниц в работе

**Кто:** учитель, у которого 40 работ в журнале, R2 временно недоступен.

**Шаг 1.** Учитель открывает журнал проверок.

**Что происходит сейчас:** поле «число страниц» пропадает из каждой строки, журнал выглядит так, будто работ одностраничных. Учитель решает, что ученики сдали пустые листы.

**Что видит после изменения:** при недоступном бакете в строке пишется «не удалось определить», а не просто исчезает. Число страниц, посчитанное при загрузке работы, хранится и не пересчитывается.

## 6. Технические решения

**AD-1 · Админка не знает ни одной цены.**
`routes/admin.ts` импортирует `PRICES` из `services/billing.ts`. Цена платежа — из самой записи платежа, а не из текущего прайса.
**Рационал:** платёж 12 октября по старой цене должен попадать в выручку по старой цене. Если считать по текущему прайсу, история за месяцы перепишется задним числом.

**AD-2 · Правка листа — пересборка, а не регенерация.**
`PATCH /api/worksheets/:id` пересобирает сохранённую структуру `tasks[]` и перерисовывает превью. LLM не вызывается, квота не списывается.
**Рационал:** регенерация = другой лист и ещё одна платная генерация за ошибку, которую учитель уже оплатил.

**AD-3 · Правка закрывает проверку.**
Если по листу уже есть работа с отметками, кнопка «Редактировать» неактивна с текстом «по этому листу уже проверена работа — правка закрыта».
**Рационал:** лист в работе ученика и отметка учителя — это то, что уже нельзя менять задним числом, иначе ученик принесёт сдачу, а учитель увидит другой текст.

**AD-4 · Тип артефакта «картинки» убираем из интерфейса, а не чиним.**
Провайдера генерации изображений нет, `llm/router.ts:178` отдаёт 503. Тип убирается из списка в конструкторе и из типов `llm/types.ts:164`.
**Рационал:** шесть типов артефактов, из которых один не работает, хуже пяти рабочих. Возврат — отдельная задача с расчётом себестоимости картинки.

**AD-5 · Длительность экзамена — из профиля, fallback один.**
Таблица `exam_profiles (slug, subject, minutes, fgos_profile)`. Промпт берёт минуты из профиля; если профиля нет — 235.
**Рационал:** у ОГЭ и ЕГЭ разная длительность, и держать одно число в промпте — это ошибка, которая всплывёт на пробном экзамене.

## 7. Форматы

**`PATCH /api/worksheets/:id`** (новый):
```json
{ "tasks": [{ "id": "...", "prompt": "...", "answer": "...", "explanation": "...", "skill": "Дроби" }] }
```
Ответ при чужом листе — 404, не 403 (по той же причине, что и в `interactives.ts`: иначе по id перебираются чужие id).

**Новая таблица `exam_profiles`:**
```sql
CREATE TABLE exam_profiles (
  slug TEXT PRIMARY KEY, subject TEXT NOT NULL, minutes INTEGER NOT NULL,
  fgos_profile TEXT, user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE
);
```

**Колонка числа страниц:** `photo_checks.pages INTEGER` — считается при загрузке работы, дальше только читается.

## 8. Acceptance criteria

- [ ] В `backend/src/routes/admin.ts` нет ни одного литерала цены; выручка считается через `PRICES` и по фактическим суммам платежей.
- [ ] Тест роняет сборку при расхождении цен между админкой, биллингом и прайсом; тест для бэкенда дописан в `backend/tests/`.
- [ ] Платёж до 12.10 попадает в выручку по своей цене, а не по текущей.
- [ ] `PATCH /api/worksheets/:id` меняет текст задания; чужой лист даёт 404; правка видна в скачанном DOCX.
- [ ] Правка не списывает квоту генерации — проверяется тестом на счётчике `usage_counters`.
- [ ] Если по листу уже проверена работа, кнопка «Редактировать» неактивна с понятным объяснением.
- [ ] `PATCH` валидирует пустые поля: пустое задание не сохраняется, под полем — причина.
- [ ] Роут `f08.ts` больше не отдаёт 501 ни на одном пути.
- [ ] Тип «картинки» убран из конструктора и из `llm/types.ts`; 503 не отдаётся; ссылка на тип в коде не осталась.
- [ ] У профиля экзамена своя длительность; при отсутствии профиля — 235 минут; в сгенерированном варианте время указано верно.
- [ ] Число страниц работы пишется при загрузке и не пересчитывается при открытии журнала.
- [ ] При недоступном R2 в строке журнала написано «не удалось определить», а не пустое поле.

## 9. Чего не делаем

- Не трогаем цены и нормы — они утверждены 12.10.
- Не делаем выгрузку отчёта о выручке в 1С: это школьный B2B, не наша задача.
- Не делаем генерацию картинок — см. AD-4, вернём отдельной задачей.

## 10. Риски

- **Правка листа ломает уже выставленные отметки** — отдано на AD-3: после проверки правка закрыта.
- **Откат типа «картинки» отнимает функцию у тех, кто ей пользовался.** Перед откатом смотрим `track` за 30 дней: если генерация картинок не использовалась — откатываем, если использовалась — оставляем и идём в подключение провайдера.
