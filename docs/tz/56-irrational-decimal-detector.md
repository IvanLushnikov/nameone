## 1. Контекст и зачем

Учительница получила контрольную по математике 8 класса (лист `ws_1spiva55zlgh`, 13.10) с пояснением: «Число √7 — бесконечная непериодическая десятичная дробь, оно иррациональное». Ответ верный. Пояснение вводит в заблуждение: **десятичная дробь по определению рациональна** — так учат в школе, и это ровно то, что потом учительница объяснит классу.

Из-за этого случая 14.10.2026 в промпт вписали правило 14 («НЕ ПУТАЙ ИРРАЦИОНАЛЬНОЕ И ДЕСЯТИЧНУЮ ДРОБЬ», `backend/src/llm/prompts/worksheet-gen.ts:183-191`). Лист с дефектом был **до** правила — это его причина, а не нарушение. После 14.10 нарушений в бою не было: 0 из 864 заданий.

Но «не было» здесь означает «ещё не повторилось», а не «невозможно»: кодовой проверки нет ни одной. Единственное, что есть, — тест `backend/tests/unit/grade-level-prompt.test.ts`, который проверяет **наличие текста правила в промпте**. Правило, живущее только в промпте, не обеспечено: модель может забыть, а объяснение с неверным определением уедет в класс вместе с листом.

**Что делаем:** появляется кодовая проверка. Она **декларативная**: не «если математика — проверь √», а «если в тексте встретились несовместимые друг с другом термины — это нарушение». Список терминов и правила их несовместимости лежат в данных и утверждаются владельцем; опираются они на темы каталога программы.

### 3.2. Формат таблицы

```ts
// src/lib/content/term-conflicts.ts — РУЧНОЙ ФАЙЛ. Утверждает владелец.

/** Ссылка на тему каталога: основание, по которому термин вообще считается термином. */
export interface CatalogRef {
  subject: string;
  grade: number;
  topicSlug: string;
}

/**
 * Группа терминов. Группа «найдена», если выполнено её условие.
 *
 * · stems — наборы основ слов. Внутри набора — ИЛИ («любая из основ подходит»),
 *   между наборами — И («все наборы должны найтись»).
 * · patterns — регулярные выражения; группа найдена, если совпало хотя бы одно.
 * · irrationalMarker — специальная группа: «иррациональный признак».
 *   Это ИЛИ из двух вещей: слово «иррационал*» в тексте ИЛИ неполный
 *   квадратный корень (см. 3.4).
 */
export interface TermGroup {
  /** Основы слов: первые 4+ символа слова. */
  stems?: string[][];
  /** Регулярные выражения по нормализованному тексту. */
  patterns?: string[];
  /** Спец-матчер «иррациональный признак». */
  irrationalMarker?: boolean;
  /** Темы каталога, на которых стоят термины группы. */
  catalogRefs?: CatalogRef[];
}

/**
 * Правило несовместимости.
 *
 * Срабатывает, когда в одном задании одновременно:
 *   · нашлась хотя бы одна группа из `require` (ИЛИ между группами), и
 *   · нашлась хотя бы одна группа из `forbid` (ИЛИ между группами), и
 *   · не сработал ни один `neutralizer` (см. 3.5).
 */
export interface ConflictRule {
  id: string;
  /** Человеческое объяснение — попадёт в отчёт и в сообщение учителю. */
  why: string;
  /** Достаточно одной совпавшей группы. */
  require: TermGroup[];
  /** Достаточно одной совпавшей группы. */
  forbid: TermGroup[];
  /**
   * Предметы, к которым правило относится. Пусто — любые.
   * Заполняется, чтобы правило не срабатывало там, где терминов нет.
   */
  subjects?: string[];
  /**
   * Конструкции, которые снимают правило (см. 3.5).
   * Регулярные выражения по нормализованному тексту.
   */
  neutralizers?: string[];
}

export const TERM_CONFLICTS: ConflictRule[];
```

### 3.3. Почему это не «частное правило под математику»

Три вещи, которые делают правило **декларативным**, а не частным:

1. **Механизм общий.** Матчер умеет распознавать группы: слова, регулярки, «иррациональный признак». Он ничего не знает ни про математику, ни про √. Чтобы добавить новое правило (например, «рациональное = иррациональное»), добавляется строка в `TERM_CONFLICTS` — код не меняется.
2. **Термины опираются на темы каталога, а не на список разработчика.** У каждой группы есть `catalogRefs` — темы программы, в которых эти термины живут. Тест `tests/term-conflicts-catalog.test.ts` проверяет, что (а) указанная тема существует в каталоге `src/lib/content/subjects.ts` и (b) **хотя бы одна основа из `stems` группы является началом слова в названии этой темы**. Если каталог переименует тему или термин выпадет из её названия — тест падает. Таблица не может разойтись с программой молча.
3. **Предмет — это данные, а не `if`.** Поле `subjects` в правиле. Для другой дисциплины добавляется строка.

### 3.4. Матчер: что и как ищется

Нормализация текста задания (одна на все группы): нижний регистр, `ё` → `е`, тире/дефис → пробел, пунктуация → пробел, пробелы схлопываются.

**Слова-основы.** Слово из текста подходит под основу, если начинается с неё. Основы в таблице — длиннее 4 символов там, где 4 символов мало («десятичн» вместо «деся»): «десятичная» и «десятичные» подходят под `десятичн`, но «десяток» — нет.

**`irrationalMarker` (иррациональный признак)** — срабатывает, если выполнено **хотя бы одно** из двух:

- **Слово «иррационал…»** есть в тексте («иррациональное число», «иррациональных»).
- **В тексте есть неполный квадратный корень.** Ищутся конструкции: `√N`, `√(N)`, `√ N`, `\sqrt{N}`, `корень из N`, `корнем из N`. Из них берётся подкоренное выражение `N`; если `N` — **целое число, не являющееся полным квадратом**, корень иррационален и признак найден. Если `N` — полный квадрат (4, 9, 16, 25…) → признак **не** найден. Если `N` не разобралось (буквы, дробь, выражение) → признак не найден.

**Зачем проверка «полный квадрат».** Без неё правило даёт два вида ложных срабатываний:

- `√4 = 2` — 4 полный квадрат, 2 рационально, называть 2 десятичной дробью правильно. Без проверки — ложное срабатывание.
- Слово «корень» вообще-то живёт и в русском языке: тема «Корень и однокоренные слова» в каталоге — russian/2 и russian/3 (`koren-kak-obyazatelnaya-chast-slova-odnokorennye-rodstvenn-2`). Русское задание про однокоренные слова не должно ловиться на «корень». Поэтому в признак входит не слово «корень», а **число под корнем**.

### 3.5. Нейтрализаторы (почему «запишите в виде десятичной дроби» — не дефект)

Живая школьная задача: «Вычислите √7 и запишите результат в виде десятичной дроби с точностью до 0,01». Здесь иррациональный признак есть («√7»), и «десятичная дробь» есть — но задание корректное: Approximation иррационального через десятичную запись — нормальная практика.

Дефект — **назвать само иррациональное число десятичной дробью** («√7 — бесконечная непериодическая десятичная дробь»). Различие — в конструкции, а не в словах. Поэтому в правиле есть список `neutralizers` — регулярные выражения, присутствие которых снимает правило для этого задания:

| Нейтрализатор | Что снимает |
|---|---|
| `в\s+виде\s+десятичн` | «запишите в виде десятичной дроби» |
| `с\s+точностью\s+до` | «…с точностью до 0,01» |
| `округл` | «округлите до сотых» |
| `приближ` | «приближённое значение» |
| `≈` | «√2 ≈ 1,41» |

Если в задании есть хотя бы один нейтрализатор — правило не срабатывает. Это **данные**, а не ветка в коде: владелец может дописать конструкцию, не трогая код.

### 3.6. Что делает конвейер

**Предупреждение, а не удаление задания.** Обоснование — в §7 (частота ложных срабатываний не измерена).

- Новое поле отчёта: `QualityLossInfo.termConflicts: TermConflictViolation[]` — по образцу `typeDiversityViolations`.
- Структура нарушения: `{ number, ruleId, why, matched: { require: string, forbid: string } }` — чтобы учитель и разработчик видели, **какие именно два термина столкнулись**.
- Учитель видит предупреждение тем же путём, что `repeatedSkills` и `tasksWithoutAnswer`: строка в блоке предупреждений на странице материала. Текст — по-русски, без терминов: «В пояснении к одному заданию число названо десятичной дробью, хотя оно иррациональное. Проверьте это задание перед выдачей».
- Задание **не выкидывается**: задание с неверным определением в пояснении учителю полезнее, чем отсутствующее задание, а ложное срабатывание отнимало бы у учителя материал.

## 4. Решения (AD-N)

**AD-1 · Несовместимость терминов — это данные, а не код.**
Проверка не «для математики проверяем √», а «нашлись два несовместимых термина». Таблица `TERM_CONFLICTS` — единственное место, где живёт знание о том, что с чем несовместимо.
*Рационал:* добавление нового правила = одна строка в данных. Код не трогаем, тесты не переписываем. Это тот же принцип, что в реестре типов задания (`src/lib/content/task-types.ts`) — знание в данных.

**AD-2 · Правило 14 в промпте остаётся.**
Правило 13 в ТЗ-55 ушло из промпта, а правило 14 остаётся. Разница принципиальная: правило 13 было **таблицей данных** («смешанные числа — с 6 класса»), и такая таблица разошлась с каталогом — два источника правды. Правило 14 — это **подсказка формулировки** («так и говори: “иррациональное число”»), данных в ней нет, и код её не заменяет: код может обнаружить ошибку, но не может переписать формулировку.
*Рационал:* убирать подсказку, которую код не умеет заменить, — значит уменьшить шанс правильной формулировки, не получив взамен ничего.

**AD-3 · Термины опираются на темы каталога, и это проверяется тестом.**
У каждой группы — `catalogRefs`; тест проверяет, что тема существует и что основа из `stems` встречается в её названии.
*Рационал:* иначе таблица превращается в такой же рукописный список, как правило 13, — который разошёлся с каталогом. Тест делает расхождение заметным сразу.

**AD-4 · Иррациональный признак — это «слово “иррационал”» ИЛИ «корень с неполным квадратом под ним».**
*Рационал:* слово «иррационал» ловит живую формулировку; неполный корень ловит случаи, где модель называет иррациональность через √, не используя слова. Проверка «полный квадрат» отсекает √4, √9, √16 — там десятичная дробь правомерна. Число под корнем, а не слово «корень», — потому что «корень слова» есть в русском языке 2–3 класса (russian/2, russian/3) и слово «корень» не может быть признаком иррациональности.

**AD-5 · Нейтрализаторы — данные, а не исключения в коде.**
«Запишите в виде десятичной дроби» — корректная задача, и отличить её от «√7 — десятичная дробь» можно только по конструкции.
*Рационал:* конструкции конечны и наблюдаемы; их список утверждает владелец. Код остаётся тупым исполнителем таблицы.

**AD-6 · Проверка предупреждает, задание не удаляет.** *(Решено владельцем 30.10.2026 — вариант А.)*
*Рационал:* частота ложных срабатываний не измерена. Пока не измерена (ТЗ-59) — удалять задание нельзя: цена ошибки (потерянное задание у учителя) выше цены пропуска (одно неверное пояснение, о котором учитель узнает из предупреждения). Автоудаление — отдельное решение, и только после замера.

**AD-7 · Проверка смотрит в текст, в формулу, в ответ и в пояснение.**
*Рационал:* в живом случае ошибка была в пояснении; формула `√7` может быть в `text_latex`, а не в `text`. Проверка только одного поля пропустила бы половину случаев.

## 5. Критерии приёмки

- [ ] Есть файл `src/lib/content/term-conflicts.ts`; в нём ровно одно правило с `id = "irrational-vs-decimal-fraction"`, у которого `require` содержит группу с `irrationalMarker: true`, а `forbid` — группу с `stems: [["десятичн"], ["дроб"]]`.
- [ ] Живой пример срабатывает: на тексте «Число √7 — бесконечная непериодическая десятичная дробь, оно иррациональное» проверка возвращает **одно** нарушение с `ruleId = "irrational-vs-decimal-fraction"`, `number` равным номеру задания, и заполненным `matched.require` / `matched.forbid`.
- [ ] Полный квадрат не срабатывает: на тексте «√16 + √9. Представьте результат в виде десятичной дроби» нарушений **нет**.
- [ ] Легальная задача на приближение не срабатывает: на тексте «Вычислите √7 и запишите результат в виде десятичной дроби с точностью до 0,01» нарушений **нет**.
- [ ] Русская тема про корень слова не срабатывает: на тексте «Подберите однокоренные слова к слову “корень”» нарушений **нет**.
- [ ] Слово «иррационал» без десятичной дроби не срабатывает: на тексте «Докажите, что √2 — иррациональное число» нарушений **нет**.
- [ ] Тест `tests/term-conflicts-catalog.test.ts` зелёный: для каждой `catalogRefs` тема существует в каталоге, и хотя бы одна основа из `stems` группы является началом слова в названии темы. После переименования темы в каталоге тест падает.
- [ ] Каждый новый тест падает на старом коде и зелёный на новом: тест на живой пример (√7 + десятичная дробь) падает на коде без `term-conflicts.ts` (модуль не существует — тест красный) и зелёный после.
- [ ] В ответе API у листа с нарушением есть ключ `quality.termConflicts` — массив объектов с `number`, `ruleId`, `why`, `matched`; у листа без нарушений массив пустой.

## 6. Чего не делаем

- **Не трогаем правило 14 в промпте** (AD-2). Ни текст, ни формулировку.
- **Не удаляем задание при нарушении и не запускаем дозапрос** (AD-6). Решение об автоудалении — после замера в ТЗ-59.
- **Не строим полноценный лингвистический анализ.** Никаких морфем, зависимостей, тегов. Только основы слов, регулярки и один числовой матчер.
- **Не пишем правила про грамматику английского** (правило 15). Это следующая волна: нужна отдельная модель и деньги (решение владельца 30.10).
- **Не добавляем другие строки таблицы, кроме одной.** Таблица рассчитана на расширение, но наполняется по мере подтверждённых дефектов — иначе в ней появятся правила «на всякий случай», которые сами станут источником ложных срабатываний.
- **Не привязываем проверку к листу целиком.** Совпадение ищется в пределах одного задания: в разных заданиях «√7» и «десятичная дробь» — это два разных задания, а не одно противоречие.
- **Не меняем каталог и не правим темы под правило.**

## 7. Риски

| Риск | Цена ошибки | Что делаем |
|---|---|---|
| Ложное срабатывание на легальной задаче про приближение | Учитель видит предупреждение о несуществующей ошибке | Нейтрализаторы (3.5) — данные, владелец дополняет список; проверка не удаляет задание (AD-6) |
| Ложное срабатывание из-за слова «десятичн…» в другом значении («десятичная запись», «десятичная система счисления») | То же | Нейтрализатор `в\s+виде\s+десятичн` + будущая запись в списке; частота измеряется в ТЗ-59 |
| Пропуск: модель пишет «√7 — иррациональное», а ошибка в другом месте («7 — десятичная дробь») | Дефект доедет до учителя | Ограничение признака: иррациональность должна быть в том же задании; это осознанное ограничение (см. §8) |
| Подкоренное выражение не разобралось («√(2+3)», «√x») | Признак не найден → пропуск | Осознанно: «√x» без числа не доказывает иррациональность. Пропуск фиксируется в §8 |
| Каталог переименует тему, таблица отстанет | Термины потеряют основание | Тест `tests/term-conflicts-catalog.test.ts` |
| Разработчик напишет частное правило вместо строки в таблице | Одна новая правка кода вместо данных | Таблица и матчер — единственный путь; критерий приёмки требует, чтобы правило лежало в `TERM_CONFLICTS` |
| Нейтрализатор снимает настоящее нарушение | Пропуск дефекта | Список нейтрализаторов минимален и утверждается владельцем; каждый новый — с примером в отчёте |

## 8. Что не удалось подтвердить

- **Не измерена частота ложных срабатываний.** Проверка написана по жирному примеру, но на живых листах не прогонялась. Замер — в ТЗ-59 (дефект № 6 чек-листа); до него автоудаление сознательно не включается.
- **Не проверено, покрывает ли проверка все формулировки дефекта.** Известен один живой случай («√7 — бесконечная непериодическая десятичная дробь»); другие формулировки («иррациональное — это десятичная дробь», «√7 является десятичной») считаются покрытыми по правилу, но на живых данных не подтверждены.
- **Не проверено, как часто в заданиях встречается конструкция «в виде десятичной дроби»** — если она частая, правило будет молчать о настоящих нарушениях. Это измеряется тем же счётчиком.
- **Не проверено, не конфликтует ли правило с заданиями по физике и информатике**, где встречаются и √, и десятичные записи. Правило ограничено предметами `math`/`algebra`/`geometry`; насколько этого достаточно — проверяется на живых листах.
- **Не проверено, как отработает тест против каталога, если тема в каталоге будет переименована** — тест написан по формуле «основа является началом слова в названии», но на живом переименовании не прогонялся.
- **Формат `quality.termConflicts` не согласован с фронтом.** Фронт читает `quality` поимённо; новое поле не должно ломать разбор, но это проверяется на реальном ответе — вынесено сюда.
