### 2.3. Что реально уходит модели (живая проверка промпта)

Промпт собран ровно так, как его соберёт бэк для математики 5 класса:

```
ДОСТУПНЫЕ ТИПЫ ЗАДАНИЙ (выбирай из этого списка, и только из него):
- `computation` — Расчёт. Вычислите / решите — нужен один точный числовой ответ.
- `multiple-choice` — Выбор из вариантов. …
- `short-answer` — Краткий ответ. …
- `essay` — Развёрнутый ответ. …
- `fill-blank` — Вставь в пропуск. …
- `pattern` — По образцу. Выполните по образцу. В задании обязательно приведите
  разобранный пример — например «Образец: 3/12 = 1/4. Выполните по образцу: 8/20 = …».
- `error-fixing` — Найдите и исправьте ошибку. …
- `table-task` — Задание по таблице. … В `table` — заголовки и строки …
- `multi-answer` — Несколько правильных вариантов. …
- `open-ended` — Открытый ответ. … В `criteria` — критерии приёмки …
- `word-problem` — Текстовая задача. …

ПРАВИЛА РАЗНООБРАЗИЯ:
1. Типы заданий в листе должны различаться. Не пиши 5 одинаковых задач подряд.
2. Не больше половины заданий одного вида: иначе лист выглядит как один длинный
   пример, а не как набор разных заданий.
3. Тип задания выбирай по смыслу, а не по кругу: …
```

Математике предложено **11** типов. «Практическая работа», «установите
соответствие», «расположите в порядке», «разделите на группы», «сравните» и
«работа с источником» — **не предложены**: они не по этому предмету.

Правило 3 в system-промпте:
```
3. Разнообразие типов заданий. Список допустимых типов и требования к каждому
приходят в user-запросе, блоком "ДОСТУПНЫЕ ТИПЫ ЗАДАНИЙ" — бери типы только
оттуда. Не пиши 5 одинаковых задач подряд, и не больше половины листа одного типа.
```

**Не выполнена — и это ограничение, а не пропуск.** По промпту владельца (§3 гейтов): «Плюс живая проверка на боевом воркере **после мержа в `main` (не раньше)**». Правило репозитория: «Не пушить в `main`. Публикует владелец». То есть до мержа задеплоить изменения на бой нельзя, а живая проверка по условию идёт после мержа.

**Что нужно сделать владельцу после мержа** (команда готова, ждёт выката):

`computation`/`short-answer`; (2) у задания типа `pattern` есть поле `sample`;

Пока код не на бою, проверить поведение модели на новых типах нельзя: живой

## 3. Что не удалось доказать

1. **Как модель отнесётся к 12 новым типам.** Проверяется только живым прогоном: 10 листов по разным предметам, счёт типов в каждом. Пока это гипотеза — промпт и валидация готовы, но фактическое поведение модели не измерено.
2. **Сколько токенов стоит блок типов в промпте.** Реестр на 17 типов добавляет к user-промпту ориентировочно 700–1000 токенов. Для «Плюса» — попадание в кэш, для free — рост входа. Замер будет на живых прогонах.
3. **Не проверено, как ведёт себя `polza.ai` при `max_tokens` и новых типах.** Ответ с новыми полями (`sample`, `table`, `items`) длиннее; при `baseMaxTokens = 4096` лист из 12 новых заданий может обрезаться. Механизм обрыва (`finishReason`) сработает, но порог, возможно, придётся поднять. Не проверено.
4. **Живая проверка на бою** — см. §2.4. Выполняется владельцем после мержа: до мержа задеплоить изменения на бой нельзя (правило «не пушить в `main`»). Команда для проверки готова и лежит в §2.4.
5. **Печать PDF.** В проекте нет генерации PDF для листа: учитель печатает DOCX или через браузер (`window.print`). Новые блоки попали в DOCX и в превью; отдельный PDF-рендерер не трогался и не существует.
6. **Автопроверка новых типов в форме для ученика.** Форма принимает 5 типов (ТЗ-16); новый тип переносится в форму как `short-answer` — учитель проверяет вручную. Автопроверка «двух колонок» и «чек-листа» — отдельная работа.

## 5. Пакет вопросов

Максимум 10, каждый с вариантами. Вопросы, ответы на которые меняют следующий шаг.

1. **Живая проверка: меряем разнообразие на 10 листах или сперва на одном?** (А) 1 лист по математике 5 класса — если типы не появятся, чинить промпт дальше; (Б) сразу 10 листов по разным предметам — картина полнее, но дороже.
2. **Что делаем с кэшем?** Старые листы в кэше лежат с пятью типами и будут отдаваться ещё 30 дней (TTL). (А) Кэш не трогаем — старый материал хорош, просто однообразен; (Б) сбрасываем кэш листов, чтобы разнообразие было сразу; (В) сбрасываем только те, где типы однообразны.
3. **Порог «не больше половины листа одного типа» — оставляем?** (А) Да, как в промпте сейчас; (Б) ослабить до «не больше двух подряд» — мягче для коротких листов.
4. **Волна 2: начинаем с В1.2 (критерии оценивания) или с В1.5 (добивка количества + разбор несмёрженных веток)?** (А) В1.2 — это обещание тарифа «Плюс», которое сейчас не выполнено; (Б) В1.5 — там 21 несмёрженный коммит и висящий функционал.
5. **`criteria` в листе — отдавать учителю в интерфейсе отдельной вкладкой или только в DOCX?** (А) Только в DOCX — меньше работы; (Б) отдельная вкладка в кабинете — учитель правит критерии, не перескачивая файл.
6. **Новые типы в форме для ученика: пока оставляем ручную проверку?** (А) Да, как сейчас (AD-9); (Б) делать автопроверку «соответствия» в этой волне — заметно дороже и дольше.
7. **Нормы токенов (В1.6) считаем после В1.1?** Блок типов в промпте увеличивает расход — возможно, нормы надо пересчитывать уже сейчас, до того как выкатим. (А) Да, сначала В1.6, потом В1.2–В1.5; (Б) Нет, сначала остальные фичи волны 1, нормы — в конце.
8. **Реестр — 17 типов достаточно на эту волну или расширять?** (А) 17 достаточно, расширяем по жалобам; (Б) добавить ещё `fill-in-table`, `true-false`, `match-columns` — часто просят.

## 7. Ограничения и честные оговорки

- **Ветка не запушена.** Правило репозитория: «Не пушить в `main`. Публикует владелец». Ветка `feat/teacher-gaps-w1` создана локально; мёрж и выкачка — за владельцем.
- **Правка system-промпта сбрасывает prompt cache у тарифа «Плюс»** — один раз, разовая переплата за входные токены. Причина жёсткая: без нового блока модель физически не знает про новые типы. Зафиксировано в шапке `worksheet-gen.ts` и в ТЗ, AD-8.
- **Реестр лежит во фронте, бэк импортирует его относительным путём.** Это исключение из правила «бэк не зависит от фронтовой кодовой базы» — иначе две копии реестра разъедутся (тип, который бэк считает мусором, бэк бы и отверг). Проверено: vitest бэка проходит, `wrangler deploy --dry-run` собирает бандл без ошибок.
- **Страница `/methodology` теперь называет 17 форм, а перечисляет пять.** Это осознанно: страница объясняет лист в общих чертах, а не перечисляет все формы (среди которых есть узкие, вроде «задание по таблице»). Но если решение владельца — перечислить все 17, это правка одной строки в `src/app/methodology/page.tsx`.
