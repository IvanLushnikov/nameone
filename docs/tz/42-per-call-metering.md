## 1. Контекст и зачем

**Часть 1. Ретраи не тарифицируются.** Карточки, план урока, КТП, презентация,
материалы и ОГЭ/ЕГЭ могут делать до 2–3 вызовов провайдера: ретрай по языку или
по качеству. В тарифную норму и в `meta.costUsd` попадает **только последний
вызов**.

Путь листа сделан правильно: `generateWorksheet` копит все вызовы в `calls[]`
(`backend/src/llm/index.ts:525`) и sums их и в `meta` (`:1288`, `:1293`), и в
норму (`:1375`), и в лог (`:1354-1368` — по строке на каждый вызов). Конвейер
документных типов написан позже и этого не унаследовал: `generateStructuredArtifact`
(`:1753`) и `generateExam` (`:1457`) пишут в `meta` и в `recordUsage` результат
**последнего** вызова (`:1940-1941`, `:1978`, `:1647-1648`). То есть ретрай —
это «попытка», а не «вызов», и в коде он живёт внутри цикла, который их не
различает.

Учитель это видит так: тарифный отчёт показывает меньше, чем потрачено. В
месяцы, когда ретраи срабатывают регулярно, счётчик расхода врёт.

**Часть 2. В колонке «модель» лежит хеш ключа кэша.** При попадании в
семантический кэш в `llm_logs.model` пишется `cacheKey.slice(0, 12)` — 12
символов djb2-хеша (`backend/src/llm/index.ts:442`, и аналогично в
structured-пути `:1819`). Любая аналитика по моделям получает строки, которых
нет среди моделей: `/superpower/usage` группирует расход по `model`
(`backend/src/routes/admin.ts:186-196`), и там появляются «модели» вида
`a1b2c3d4e5f6`.

**Часть 3. Ловушка для следующего разработчика.** `checkLlmRateLimit`
(`backend/src/llm/ratelimit.ts:346`) для бесплатного тарифа читает счётчик по
ключу `iphash:<хеш IP>`, а вся реальная квота пишется по ключу `fp:<отпечаток>`.
Функция помечена `@deprecated` (`:343`), но её зовут все три генератора
(`generateWorksheet`, `generateExam`, `generateStructuredArtifact`). Счётчик
`iphash:` всегда пуст, проверка всегда проходит. Обхода квоты тут нет — реальная
защита в атомарном занятии слота в `guardGeneration` (`ratelimit.ts:169`), —
но код читает не тот счётчик, и это мина.

## 3. Технический дизайн

| Файл | Что меняем |
|---|---|
| `backend/src/llm/index.ts` | (1) `generateStructuredArtifact` и `generateExam` копят вызовы, как `generateWorksheet`; (2) в `llm_logs.model` для кэш-хита пишется `semantic-cache` вместо хеша; (3) `cached` из ответа провайдера пишется в лог; (4) удаляются вызовы `checkLlmRateLimit` |
| `backend/src/services/usage.ts` | `recordUsage` получает сумму по всем вызовам (вызовы уже приходят суммой — проверяем, что пути документных типов передают сумму) |
| `backend/src/llm/ratelimit.ts` | `checkLlmRateLimit` помечается как неиспользуемая и удаляется вместе с вызовами (или переводится на ключ `fp:`) |
| `backend/src/routes/admin.ts` | Группировка по модели: `semantic-cache` выводится отдельной строкой, а не растворяется в моделях |
| `src/app/superpower/generations/page.tsx` | Экран показывает «semantic-cache» как отдельный источник, а не как «модель» |
| `backend/tests/unit/per-call-metering.test.ts` (новый) | Тесты: ретрай тарифицируется, кэш-хит пишется как `semantic-cache`, deprecated-функция не вызывается |

**Что НЕ меняется:** таблицы и миграции, промпты, тарифы и нормы (их значения —
TZ-44), модельная таблица `MODEL_COSTS` (это TZ-45).

### Контракты

```ts
// backend/src/llm/index.ts — общий вид для документных типов и экзаменов
type ProviderCall = {
  provider: string;
  model: string;
  tokensIn: number;
  tokensOut: number;
  costUsd: number;
  costRub: number | null;
  latencyMs: number;
  generation: string;
  /** Признак попадания в prompt cache провайдера (не в семантический кэш). */
  providerCached: boolean;
};
```

**Правила:**

1. **Каждый вызов провайдера — отдельная строка в `llm_logs`.** Так уже
   работает путь листа — этот путь и есть образец.
2. **`meta.costUsd` и `meta.costRub` — сумма по всем вызовам.** Ровно так же,
   как в `generateWorksheet`.
3. **`recordUsage` получает сумму взвешенных токенов по всем вызовам.**
4. **Для попадания в семантический кэш `model` = `"semantic-cache"`.** Не хеш.
   Хеш ключа не нужен никому: ключ есть в самой записи `semantic_cache`.
5. **Признак `cached` в `llm_logs` различает два разных кэша:**
   - `semantic-cache` (наш кэш ответов) — вызов не состоялся;
   - `providerCached = true` (prompt cache провайдера) — вызов состоялся, но
     вход был прочитан из кэша провайдера (результат TZ-41).
6. **`checkLlmRateLimit` удаляется.** Три места вызова — `generateWorksheet`,
   `generateExam`, `generateStructuredArtifact` — перестают её звать. Функция
   удаляется из `ratelimit.ts` целиком, вместе с комментарием про
   `@deprecated` и напоминанием, что `guardGeneration` её заменяет.

### Что видно на экране «Генерации»

Сейчас аналитика «какая модель сколько стоила» частично врёт. После правки:

- «gpt-6-luna» — реальные вызовы;
- «claude-sonnet-5-5» — реальные вызовы;
- «semantic-cache» — попадания в наш кэш, денег не стоили;
- внутри строк — колонка «из prompt cache» (доля вызовов, где вход был
  прочитан из кэша провайдера), если TZ-41 подтвердил, что кэш работает.

## 4. Решения

**AD-1 · Учёт по каждому вызову — как в пути листа.**
Не изобретаем новый механизм — переносим уже работающий.
*Рационал:* ТЗ-25, AD-5 («два вызова контрольной честно стоят двух вызовов»)
уже сделал это для листа. Документные типы просто не догнали.

**AD-2 · `model = "semantic-cache"` вместо хеша ключа.**
Без миграции: колонка уже есть, меняется только значение.
*Рационал:* хеш ключа не несёт информации, которую нельзя получить из самой
записи кэша, и ломает всю группировку по моделям. Отдельная колонка `cache_key`
не нужна: идентификатор записи кэша есть в `semantic_cache`.

**AD-3 · Два разных кэша различаются в логах.**
Наш семантический кэш и prompt cache провайдера — разные вещи с разными
смыслами: первый не тратит денег вовсе, второй тратит меньше.
*Рационал:* смешивать их в одном поле `cached` — значит нельзя понять, откуда
 взялась экономия.

**AD-4 · `checkLlmRateLimit` удаляется, а не чинится.**
Она читает счётчик, который никто не пишет; «починить» — значит перенести её
на ключ `fp:` и оставить второй путь к лимиту, который дублирует
`guardGeneration`.
*Рационал:* одна функция — один источник правды. `guardGeneration` уже умеет
отпечаток, капчу и бесплатную квоту.

**AD-5 · Ретраи не «прячем» — они просто считаются.**
Никакой попытки сделать ретрай дешевле: он стоит провайдеру денег, и тариф
должен это видеть.
*Рационал:* тарифный отчёт, который не знает про ретраи, хуже того, который
знает.

**AD-6 · Правка не меняет числа, которые видит учитель.**
Ни норма, ни число листов, ни цена в этой задаче не меняются. Меняется
ТОЧНОСТЬ учёта. Влияние на тариф — TZ-44 и TZ-45.
*Рационал:* «после этой правки маржа тарифа другая» — это следствие, а не
цель; решение по тарифу принимает владелец.

## 5. Критерии приёмки

Функциональные:
- [ ] Документный тип (карточки, план урока, КТП, презентация) с одним ретраем: в `llm_logs` **две** строки, в `meta.costUsd` — сумма обеих, в норме — взвешенные токены обеих.
- [ ] ОГЭ/ЕГЭ с ретраем: то же самое.
- [ ] Путь листа не изменился: одна строка на вызов, сумма в `meta`.
- [ ] Попадание в семантический кэш пишет в `llm_logs.model` значение `semantic-cache`, а не 12-символьный хеш.
- [ ] На экране «Генерации» «semantic-cache» виден отдельной строкой и не попадает в разряд моделей.
- [ ] Если TZ-41 подтвердил работу prompt cache: в логе видно, что вызов прочитал вход из кэша провайдера (`providerCached`), и стоимость такого вызова посчитана по цене cache-read.
- [ ] `checkLlmRateLimit` не вызывается ни из одного места (проверка: `grep -rn "checkLlmRateLimit" backend/src` → только объявление или ничего).

Регрессионные:
- [ ] Бесплатная квота по-прежнему считается один раз за генерацию, независимо от числа ретраев (квота — это попытки, а не вызовы).
- [ ] Экран «Деньги» (`/superpower/money`) не сломался: он читает `llm_costs_actual`, который не меняется.
- [ ] Существующие тесты учёта и rate-limit — зелёные.

Качественные:
- [ ] Сумма `meta.costUsd` равна сумме строк `llm_logs` по этому вызову (тест на синтетическом ретрае).
- [ ] НОВЫЕ тесты падают на старом коде: на старом коде ретрай не попадает в `llm_logs` и в `meta`, а в `model` лежит хеш. Результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не меняем нормы, цены и формулу взвешенных токенов.** Это TZ-44.
- **Не переписываем `MODEL_COSTS`.** Это TZ-45.
- **Не убираем ретраи.** Они нужны: без них обрыв ответа и «по образцу» едут
  учителю.
- **Не вводим новых таблиц.** Для M-15 хватает значения в существующей
  колонке.
- **Не меняем механику занятия бесплатной квоты** (`guardGeneration`) — он
  работает.
- **Не чиним `checkLlmRateLimit`, а удаляем.**

## 7. Риски

| Риск | Вероятность | Цена | Что делаем |
|---|---|---|---|
| Удаление `checkLlmRateLimit` открывает обход квоты | Низкая | Высокая | Реальная защита — атомарное занятие слота в `guardGeneration` (`ratelimit.ts:169`); функция и сейчас читает пустой счётчик. Тест: бесплатная квота по-прежнему кончается после 5 генераций |
| Ретраи станут заметны в тарифе и «поднимут расход» | Высокая | Средняя — владелец увидит цифру и решит, что с этим делать | Это правда, а не проблема. Изменение нормы — решение владельца (TZ-44) |
| `semantic-cache` в `model` сломает существующие запросы к базе | Средняя | Низкая | Проверяем все места, где `llm_logs.model` используется: `routes/admin.ts` (GROUP BY), экраны `/superpower` |
| Фильтрация по моделям в админке начнёт считать «semantic-cache» моделью | Средняя | Низкая | Отдельная строка в отчёте + подпись |

## 8. Порядок работ

1. (1 дн) `generateStructuredArtifact`: копим вызовы, суммируем в `meta` и `recordUsage`, пишем по строке на вызов. Тест на ретрае. **Первая точка приёмки: тест красный на старом коде.**
2. (1 дн) То же для `generateExam`.
3. (0,5 дн) `model = "semantic-cache"` вместо хеша + правка группировки в `routes/admin.ts` и на экране «Генерации».
4. (0,5 дн) Приём результата TZ-41: `providerCached` пишется в лог, стоимость кэш-объёма считается по цене cache-read.
5. (1 дн) Удаление `checkLlmRateLimit` и его трёх вызовов.
6. (1 дн) Регрессионные тесты, `npm test --prefix backend`, `npm run typecheck`, `npm test`.

## 9. Что не удалось подтвердить

- **Сколько ретраев фактически происходит.** Не измерено: в `llm_logs` по
  документным типам пишется одна строка на генерацию, и по базе это не видно.
  Доступ к D1 у агента закрыт (снимок 29.10.2026: все SQL-запросы упали).
  После правки это станет видно — это и есть главный результат задачи.
- **Доля вызовов, где провайдер считал кэш.** Та же причина: `cached` в логах
  не писался для реальных вызовов.
- **Сколько попаданий в семантический кэш и как они распределены по типам.**
  Не измерено. Известно только по живым прогонам: попадание есть, стоит 0 ₽,
  latency 753–778 мс.
- **Точное число ретраев на тип.** Из кода: до 2 вызовов у документных типов
  (`MAX_LANG_RETRIES = 1`) и до 3 у экзаменов (`:1480`, `MAX_LANG_RETRIES = 2`).
  Сколько из них реально срабатывает — не измерено.
