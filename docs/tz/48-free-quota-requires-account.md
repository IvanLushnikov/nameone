## 1. Контекст и зачем

Бесплатный тариф — 5 генераций в месяц. Лимит держится на отпечатке
`sha256(salt|ip|userAgent|country)` (`backend/src/lib/antifraud.ts:106-112`).

В ходе исследования 29.10.2026 один и тот же анонимный «клиент» с постоянным
User-Agent сделал **10 успешных генераций** при лимите 5. Счётчик показывал
`429 {"limit":5,"used":5}` только после того, как IP сменился; следующий запрос
с нового IP снова прошёл.

То есть бесплатная квота обходится сменой адреса сети. Для обычного человека
это неудобно (VPN, мобильный интернет, смена Wi-Fi в школе), а для того, кто
хочет получить больше бесплатного материала, — это один переключатель.

Отдельно: сам модуль знает о проблеме. В комментарии `antifraud.ts:75-80`
описан тот же плавающий IP, и сказано, что отпечаток «не идентифицирует
человека надёжно».

| Файл | Что меняем |

| `backend/src/lib/antifraud.ts` | Отпечаток остаётся (для антифрода и для «гостевого» режима), но больше не является носителем квоты |
| `src/app/constructor/page.tsx` | Обработка 401 «войдите, чтобы получить бесплатные листы»: вход по magic-link прямо из конструктора, без потери выбранных параметров |

### Три варианта (владелец выбирает, §7)

| Вариант | Что делаем | Что это значит для учителя | Конверсия |
|---|---|---|---|
| **А. Вход обязателен для генерации** | `free` без сессии → 401 | «Войдите по почте — и сделайте 5 листов бесплатно» | Падает: человек, который не готов оставить почту, уходит |
| **Б. Вход обязателен, но один лист без входа** | первая генерация — без входа (квота по отпечатку), дальше нужен аккаунт | «Первый лист — сразу, остальные — после входа» | Почти не падает, обход ограничен одним листом на IP |
| **В. Учёт по ASN/подсети вместо IP** | отпечаток включает сеть, а не адрес | Ничего не меняется для учителя | NAT в школах даёт ложные срабатывания: у всей школы один счётчик |

**Рекомендация: Б.** Она закрывает обход (10 генераций → 1) и почти не трогает
конверсию: человек получает первый лист без почты и решает сам.

### Что делаем в варианте Б (реализация)

1. Бесплатная квота по-прежнему живёт на отпечатке, но **счётчик для
   отпечатка без сессии = 1**. Это одна строчка в `holdFreeQuotaSlot`:
   лимит зависит от того, есть ли `userId`.
2. Сессия → квота живёт на аккаунте (`usr:<id>`), 5 генераций в месяц, как
   сейчас.
3. Антифрод (капча, всплески) работает как раньше и для гостя, и для
   пользователя.

### Чего не делаем

- Не меняем число 5.
- Не вводим блокировку по подозрению (принцип «подозрение ≠ блокировка»).
- Не просим карту, телефон или любые другие данные.

## 4. Решения

**AD-1 · Квота привязывается к человеку, а не к сети.**
*Рационал:* «пять листов в месяц» — это обещание человеку, а не его IP.
Отпечаток остаётся для антифрода, но перестаёт быть носителем права.

**AD-2 · Один лист без входа (вариант Б) — если владелец выбрал Б.**
*Рационал:* полностью закрытый вход (вариант А) обрывает путь «зашёл →
попробовал → не понравилось → ушёл» в самом начале. Один лист без почты
сохраняет этот путь, а обход при этом остаётся обходом одного листа.

**AD-3 · Никакой блокировки за подозрение.**
Существующий принцип не меняется: капча вместо отказа.
*Рационал:* решение владельца от 07.10.2026 и общий тон продукта.

**AD-4 · Вход не должен терять материал учителя.**
Если человек нажал «создать» и его отправили на вход, то после входа
конструктор возвращается к тем же параметрам и запускает генерацию.
*Рационал:* иначе учитель потеряет выбранную тему и сложность — и уйдёт.

**AD-5 · Для авторизованного учителя счётчик не меняется.**
5 в месяц, сброс 1-го числа, мягкий порог.
*Рационал:* регрессия против текущего поведения недопустима.

## 5. Критерии приёмки

Функциональные:
- [ ] Анонимный запрос генерации на бесплатном тарифе возвращает 401 с кодом, который фронт понимает (например `AUTH_REQUIRED_FOR_FREE`), а не 429 и не 500.
- [ ] Войдя по magic-link, учитель получает 5 генераций в месяц; счётчик привязан к аккаунту.
- [ ] В варианте Б: анонимный клиент может сделать ровно 1 генерацию; вторая — 401.
- [ ] После входа параметры конструктора (предмет, класс, тема, число заданий, тип) сохраняются и генерация запускается автоматически.
- [ ] Смена IP не даёт дополнительных генераций: тот же отпечаток/аккаунт упирается в свой лимит.
- [ ] Антифрод не изменился: подозрительный всплеск по-прежнему приводит к капче, а не к блокировке.

Регрессионные:
- [ ] Платные тарифы работают без входа так же, как раньше (никаких 401).
- [ ] Учитель, вошедший ранее, не теряет свою квоту (5, а не 1).
- [ ] Квота сбрасывается 1-го числа, как раньше.
- [ ] `npm test --prefix backend` — зелёные.

Качественные:
- [ ] Текст на входе объясняет, зачем нужен вход: «5 листов в месяц бесплатно — нужна почта, чтобы сохранить листы и не потратить квоту зря», а не «войдите».
- [ ] НОВЫЙ тест падает на старом коде: на старом коде анонимный клиент делает 5+ генераций. Результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не меняем число бесплатных генераций.**
- **Не ставим блокировку по подозрению.**
- **Не собираем данные сверх почты для входа.**
- **Не убираем антифрод и капчу.**
- **Не делаем ASN-определение** (вариант В) — он ложно срабатывает в школах с
  NAT; если владелец всё же выберет В, это отдельная задача.
- **Не меняем механику бесплатной квоты для платных тарифов.**

## 9. Что не удалось подтвердить

- **Сколько реально людей пользуется бесплатным тарифом без входа.** Не
  измерено: снимок от 29.10.2026 не отработал запросы к `users` (все SQL
  упали). Без этой цифры нельзя оценить эффект на конверсию — только
  осторожность.
- **Доля учителей, которым мешает вход по почте.** Не измерено. Из живых
  событий известно: 19.10.2026 `constructor_generate_click` — 4, при
  `worksheet_generated` — 8; 18.10.2026 было 39 кликов и **0** генераций,
  и причина найдена (релиз-баг с капчей), а не вход. То есть в тот день
  проблема была не во входе.
- **Насколько часто меняется IP у обычного учителя.** Не измерено; оценка «часто
  в мобильной сети» — из общих соображений, а не из данных.
- **Не проверено, как поведёт себя `holdFreeQuotaSlot` при смене владельца
  счётчика** (отпечаток → аккаунт). Это надо покрыть тестом на переход:
  вход с отпечатка, на котором уже была анонимная генерация.
