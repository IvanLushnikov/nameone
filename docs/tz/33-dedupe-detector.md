## 1. Контекст и зачем

Учитель распечатал лист по русскому языку, 8 класс, тема «Типы предложений». В
листе десять заданий. Пятое и седьмое — **один и тот же вопрос**: «Укажите
сложное предложение.» и один и тот же список из четырёх вариантов ответа.
Учитель раздал это классу. Два ученика получили одинаковое задание — и, что
хуже, никто не сказал учителю, что это дубль.

Система про этот лист отчиталась: повторов нет (`quality.repeatedSkills = 0`).
Предупреждения на экране не было. Учитель нашёл дубль глазами — на бумаге.

**Почему система не увидела.** Штатный детектор дублей ищет совпадение по
трём подряд идущим словам в тексте задания. Перед этим из текста вычищаются
служебные слова: «укажите» — разделитель, «предложение» — инструкция. У
короткого задания после чистки остаётся одна сигнатура — `["сложн"]`. Дальше
срабатывает порог «сигнатура короче трёх слов — не дубль», и пара пропускается.

То есть чем короче задание, тем надёжнее оно дублируется и тем меньше шансов,
что это заметят. Проверено штатной функцией репозитория:

```
findSkillDupes([{text:"Укажите сложное предложение."},{text:"Укажите сложное предложение."}])
→ { hasDupes: false, pairs: [] }
```

Вторая половина той же проблемы: **метка навыка от модели в детекторе не
используется вообще.** Модель уже разделила лист по навыкам и честно назвала
навык у каждого задания — «Различение простых и сложных предложений» у обоих
дублей. Детектор об этом не знает: он смотрит только на `task.text`.

### Контракты (готовы к вставке)

```ts
/** Нормализованный текст задания: обрезка, нижний регистр, схлопнутые пробелы,
 *  срезанная конечная пунктуация. Числа НЕ срезаются: «3/4» и «5/8» — разные задания. */
export function normalizeTaskText(value: unknown): string;

/** Ключ задания для точного сравнения: текст + множество вариантов ответа.
 *  null — если в задании нет ни текста, ни вариантов (сравнивать нечего). */
export function exactTaskKey(task: SkillTaskLike): string | null;

export interface SkillDupePair {
  first: number;
  second: number;
  signature: string;
  /** Почему признано дублем: "exact" | "same-text" | "grams" | "same-skill" */
  reason: "exact" | "same-text" | "grams" | "same-skill";
}

export interface SkillDupeResult {
  hasDupes: boolean;
  pairs: SkillDupePair[];
  compared: number;
  /** Пары с одинаковой меткой навыка, но не признанные дубликатами.
   *  НЕ заменяются: правило промпта разрешает два задания одного навыка. */
  sameSkillPairs: Array<{ first: number; second: number; skill: string }>;
}
```

**Критерии дубликата (в порядке проверки):**

1. **exact** — нормализованный текст совпал И наборы вариантов ответа совпали
   (варианты сравниваются как МНОЖЕСТВО, не как список: перестановка вариантов
   не делает задание другим).
2. **same-text** — нормализованный текст совпал, а варианты различаются.
   Один и тот же вопрос дважды — это дубль, какой бы набор ответов ни стоял
   рядом. Если у обоих заданий есть метка навыка и она разная — это всё равно
   дубль текста, но метка разная — признак того, что модель ошиблась в
   подписи; в лог это попадает отдельным полем.
3. **grams** — нынешнее поведение: ≥3 общих 3-грамм. Не трогаем.
4. **same-skill** — совпали непустые нормализованные метки навыка И ≥2 общих
   3-грамм. Порог 2 — только для пар с одинаковой меткой: это ровно тот
   случай, где глобальный порог 3 молчал.

**Нормализация метки:** `trim` + нижний регистр + схлопнутые пробелы. Без
стоп-слов и без морфологии — метка приходит от модели, и мы не знаем её
словарь.

## 4. Решения

**AD-1 · Точное совпадение — основной критерий; метка — второй.**
Ложных срабатываний у точного сравнения быть не может: совпал текст — совпало
задание. Метка навыка используется как усиление: она либо подтверждает дубль
(критерий 2), либо понижает порог грамм (критерий 4).
*Рационал:* реестр рекомендует ровно A+B. Проверка «по трём словам» без
точного сравнения останется слепой к коротким заданиям — а именно там дубль и
возникает.

**AD-2 · Глобальный порог 3-грамм не снижаем.**
Понижение разрешено только для пар с совпавшей меткой навыка. Пара «живая /
неживая природа» из трёх слов обязана остаться НЕ дублем.
*Рационал:* ложное срабатывание отнимает у учителя нормальное задание и тратит
вызов модели; пропущенный дубль стоит одного лишнего задания в листе. Правило
из комментария `skill-dupes.ts:270-283` — рабочее, ломать его нельзя.

**AD-3 · Одинаковая метка ≠ дубликат сама по себе.**
Правило промпта («один навык — максимум два задания на лист») разрешает два
задания одного навыка. Поэтому одинаковые метки попадают в `sameSkillPairs` —
это отчётность, а не повод для замены.
*Рационал:* иначе детектор начнёт выбрасывать нормальные листы, где два
задания проверяют один навык, — это ровно тот ложный страх, который пять раз
добавляли в словари.

**AD-4 · Словари стоп-words не расширяем.**
За словарями уже пять заходов, и каждый приносил новое ложное срабатывание.
Точное сравнение снимает необходимость в новых словах.
*Рационал:* комментарий `skill-dupes.ts:96-130` прямо это фиксирует.

**AD-5 · Варианты ответа сравниваются как множество.**
Порядок вариантов не влияет на суть задания. В живом прогоне №5 и №9 в
русском 8 классе варианты были переставлены — задание осталось тем же.
*Рационал:* иначе Rule 1 не поймает самый частый вид дубля.

## 5. Критерии приёмки

Функциональные:
- [ ] `findSkillDupes` на двух одинаковых заданиях «Укажите сложное предложение.» с одинаковыми четырьмя вариантами возвращает `hasDupes: true` и одну пару с `reason: "exact"`.
- [ ] Те же два задания с вариантами в переставленном порядке → `hasDupes: true`.
- [ ] Те же два задания без вариантов ответа → `hasDupes: true`.
- [ ] Два задания с одинаковой меткой навыка, совпадающей по двум 3-граммам → `hasDupes: true`, `reason: "same-skill"`.
- [ ] Два задания с РАЗНЫМИ метками и двумя общими граммами → `hasDupes: false` (порог 3 не опущен).
- [ ] `sameSkillPairs` заполняется для пар с одинаковой меткой; такие пары НЕ попадают в `pairs`.

Регрессионные (обязаны остаться зелёными):
- [ ] «Вычислите 3/4 + 1/4» и «Вычислите 5/8 + 1/8» → `hasDupes: false` (различаются только числами).
- [ ] «Живая природа» / «Неживая природа» → `hasDupes: false`.
- [ ] Пустой список заданий → `hasDupes: false`, `compared: 0`.
- [ ] Задание без текста и без вариантов не роняет функцию.

Качественные:
- [ ] Каждый распознанный дубль имеет `reason`, и в лог генерации видно, по какому критерию он найден.
- [ ] Ни один из живых примеров реестра (прогоны 4, 7, 10) не остаётся незамеченным: все три группы байт-идентичных заданий признаются дублями.
- [ ] НОВЫЙ тест падает на старом коде: прогон `skill-dupes-exact.test.ts` на коммите до правки даёт `hasDupes: false` там, где ожидается `true`. Проверяется `git stash` или отдельным worktree, и результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не переписываем `findSkillDupes` начисто.** Меняются критерии, не каркас: функция остаётся чистой, без сети и без побочных эффектов.
- **Не снижаем `MIN_SHARED_PHRASE` глобально.**
- **Не добавляем новые стоп-слова и разделители.**
- **Не трогаем `index.ts`, `skill-labels.ts`, промпты и кэш.** Это задача детектора.
- **Не меняем формат ответа API и не добавляем в него поля.** `sameSkillPairs` — внутренний счётчик, наружу он не выходит (см. «Что не удалось подтвердить»).
- **Не переносим `assignTopicSkills` выше чистки.** Метка от модели и так доступна детектору (см. §2).

## 7. Риски

| Риск | Вероятность | Цена | Что делаем |
|---|---|---|---|
| Ложное срабатывание: два задания с одинаковым текстом, но это ОДИН вопрос с двумя подпунктами | Низкая | Средняя — зря потраченный вызов модели | Критерий 2 требует совпадения ТЕКСТА целиком; подпункты различаются текстом |
| Учитель потеряет задание, которое было не дублем, а «похожим» | Средняя | Низкая — задание вернётся дозапросом | `tasksToReplace` заменяет только второе из пары; `ensureCount` доберёт длину |
| Метка от модели начнёт приходить реже (модель перестанет её давать) | Низкая | Низкая | Критерии 1-3 работают без метки; критерий 4 просто не сработает |
| `sameSkillPairs` в результате детектора сломает потребителя, который перебирает поля | Низкая | Низкая | Потребитель один — `index.ts`; добавление поля обратно совместимо |

## 9. Что не удалось подтвердить

- **Частота дублей в проде.** В базе `llm_logs` нет содержимого листов, а
  выборки листов у агента нет (доступ к D1 закрыт). Известен факт: в 3 листах
  из 10 живых прогонов были дубли. Масштаб (1 лист из 50 или 1 из 5) не
  измерен. После выкатки ТЗ-34 это видно по `repeatedSkills` в ответе API.
- **Ложные срабатывания на живых листах.** Синтетика покрывает известные
  случаи; реальный лист с двумя одинаковыми по тексту, но разными по смыслу
  заданиями не проверен. Первый признак — учитель жалуется, что «задание
  пропало». Сборка такой жалобы — в приёмке TZ-34.
- **`sameSkillPairs` наружу.** Решено не выводить: поле ответа не меняется, а
  значит, не требуется поднимать версию формата (TZ-35). Если владелец
  захочет показывать учителю «два задания на один навык» — это отдельное
  продуктовое решение, а не побочный эффект этой правки.
