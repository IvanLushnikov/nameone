# ТЗ-71: В ключе превью показывать criteria, а не «Ответ: —»

**Дата:** 2026-11-02  
**Кто делает:** фронт  
**Размер:** S (превью + тест; 2–3 файла)  
**Источник:** N4 из `docs/research/04-offline-quality-wave1-worksheet.md`; черновик T-4 в `docs/qa/offline-gen/wave1-worksheet/test-drafts.md`  
**Волна:** Offline QA 1 · обзор `69-offline-qa-wave1-overview.md`  
**Влияет на кэш: НЕТ.** Только UI превью.

---

## 1. Контекст и зачем

Как учитель, я хочу видеть в ключе критерии открытого задания, чтобы проверить работу ученика, а не смотреть на прочерк.

Сейчас: у `open-ended` / `essay` / `practical` в JSON есть `criteria`, `answer: null`. Превью с ответами пишет «Ответ: —» (`WorksheetPreview.tsx:401-406`). Печать DOCX уже ставит «Критерий: …» в ключ (`docx.ts` ~1113). Экран и бумага расходятся.

Цена ошибки: учитель на экране думает, что критериев нет.

Подтверждено 02.11.2026: рендер ключа читает только `task.answer`; `task.criteria` в блоке ключа не используется.

```
Критерии:
• Называет, что знаменатель показывает…

```


## 4. Решения (AD-N)

**AD-1 · Читать criteria с задания, не ждать evaluation.**  
У листа evaluation часто нет; критерии уже на task.  
*Рационал:* совпадает с DOCX; не блокирует ТЗ-34.

**AD-2 · Пустой answer + есть criteria → не показывать «—».**  
Прочерк врёт.  
*Рационал:* находка N4 ровно про это.

**AD-3 · Не дублировать страницу evaluation в этом ТЗ.**  
Отдельный блок «Критерии оценивания» с порогами 5/4/3/2 — если его нет для листа, не изобретаем.  
*Рационал:* scope — ключ по заданиям.

---

## 5. Критерии приёмки

- [ ] Рендер `WorksheetPreview` с `withAnswers` и фикстурой open-ended + 2 criteria → на экране виден текст хотя бы одного критерия
- [ ] При `answer: null` и непустых criteria строка «Ответ: —» **не** является единственным содержимым ключа по этому заданию
- [ ] Задание с обычным `answer` без criteria — поведение как раньше («Ответ: …»)
- [ ] Новый тест падает на старом коде и зелёный на новом
- [ ] DOCX не меняем в этом ТЗ (уже ок)

---

## 6. Чего не делаем

- Не собираем `evaluation` на бэке для листа.
- Не меняем ученический раздаточный файл (без ключа) — ТЗ/фикс UL-D12.
- Не трогаем баллы / ТЗ-50.
- Не поднимаем FORMAT_VERSION.
