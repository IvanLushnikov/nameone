## 1. Контекст и зачем

Страница «Методика» обещает: «Подряд одинаковые формы не идут: лист из пяти
одинаковых заданий проверяет один навык и ничего больше».

В живых прогонах 29.10.2026 это обещание нарушено **в 7 листах из 10**:

| Прогон | Последовательность типов | Что получилось |
|---|---|---|
| 1 (математика 5, «Проценты») | К В **В В** В1 К В К В П К В В1 | три `computation` подряд |
| 3 (математика 5, «Обыкновенные дроби») | К В1 П К **К В В В** К К В П | четыре одинаковых подряд |
| 4 (русский 8) | В1 П К **В1 В1** К В1 К В1 Р В1 К | два `multiple-choice` подряд |
| 7 (история 6) | П В1 **К К** П В1 **К К** В1 П Р В1 | две пары подряд |
| 8 (информатика 9) | **В В** В1 П К **К К** В1 Р П В1 | две пары подряд |
| 10 (русский 8, тест) | 7 `multiple-choice` из 10 | почти весь лист одного формата |

Учитель получает лист из семи вопросов с выбором ответа подряд. Для класса это
выглядит как один большой тест с одним форматом, и методически это хуже, чем
разнообразие упражнений, о котором спорит учитель.

Проверки в коде нет: `grep -rn "подряд" backend/src` находит только промпт
(«Не пиши 5 одинаковых задач подряд») — а это просьба к модели, не гарантия.

### Контракты

```ts
// backend/src/llm/validation/type-sequence.ts
export type TaskTypeName = "computation" | "multiple-choice" | "short-answer" | "essay" | "fill-blank";

export interface TypeRun {
  /** Позиция первого задания серии, с единицы. */
  start: number;
  /** Длина серии. */
  length: number;
  type: TaskTypeName;
}

/** Серии одинаковых форм длиной не меньше minRun. */
export function findTypeRuns(
  tasks: readonly { type?: unknown }[],
  minRun?: number,   // по умолчанию 3
): TypeRun[];
```

### Порядок в конвейере листа

Сейчас: фильтр → `ensureCount` → чистка дублей → `ensureCount` → нумерация.
Добавляем один шаг — **после** чистки дублей и последнего добора, перед
нумерацией:

1. `findTypeRuns(tasks, 3)` — ищем серии из трёх и более одинаковых форм.
2. Для каждой серии берём **последние** задания серии (кроме первого) —
   именно их форма выбивается.
3. Каждое такое задание заменяется на задание **другого типа**: используется
   существующий дозапрос (`ensureCount`-подобный вызов), в промпте которого
   прямо сказано, какой тип нужен.
4. Если замена не удалась — задание **удаляется**, лист становится короче, и
   это видно через `stillMissing`.

**Почему именно три, а не два:** два одинаковых типа подряд — это нормальный
лист (например, два вычисления подряд в математике). Три подряд — уже «лист из
одной формы». Порог 3 — тот же, что у детектора дублей (`MIN_SHARED_PHRASE`),
и он же зафиксирован в тексте страницы.

**Почему последние, а не первые:** первое задание серии уже стоит в листе и
выглядит уместно; выбивать его — ломать лист сильнее, чем нужно.

## 4. Решения

**AD-1 · Проверка в коде, а не новое правило в промпте.**
Правило «не пиши 5 одинаковых подряд» в промпте уже есть и не работает.
*Рационал:* обещание страницы может держаться только на коде. Правило в
промпте остаётся как подсказка модели, но гарантию даёт проверка.

**AD-2 · Порог — три подряд.**
*Рационал:* два одинаковых типа подряд — обычный лист. Настоящая проблема —
«лист из семи одинаковых вопросов», и она начинается с трёх.

**AD-3 · Сначала замена, потом удаление.**
*Рационал:* удалять без попытки заменить — это минус задание у учителя;
заменять — это то же, что делает `ensureCount`. Порядок «сначала чистота,
потом длина» работает и здесь.

**AD-4 · Ошибка типа в задании не считается серией.**
Если модель вернула неизвестный тип, такое задание считается отдельной формой.
*Рационал:* серверной валидации типа сейчас нет вообще (это отмечено в
реестре как наблюдение, не как проблема). Придумывать правила для мусора не
надо.

**AD-5 · Серия в КОНТРОЛЬНОЙ считается по обоим вариантам.**
*Рационал:* учитель раздаёт оба варианта; серия в одном из них — та же
проблема.

**AD-6 · Текст «Методики» возвращается к обещанию только после того, как код заработал.**
Пока код не работает — действует смягчённая формулировка из TZ-37.
*Рационал:* обещание, которое перестаёт работать задолго до выкатки, хуже
честной формулировки. Порядок: TZ-37 (волна 1) → код (эта задача) → возврат
текста.

**AD-7 · Новых полей в ответе API не появляется.**
Факт «серия была и убрана» виден в логе, учителю — только через `stillMissing`.
*Рационал:* формат ответа не меняется → версия формата не поднимается.

## 5. Критерии приёмки

Функциональные:
- [ ] `findTypeRuns` на последовательности `К В В В В1 К` находит серию из трёх `В` (или больше) с правильными `start` и `length`.
- [ ] На листе, где три задания подряд одного типа, после конвейера **не остаётся** серии из трёх (проверяется на синтетическом ответе модели).
- [ ] Если замена не удалась, задание удаляется, длина листа уменьшается, а `quality.stillMissing > 0` — учитель видит честное число.
- [ ] Серия из двух одинаковых типов подряд **не трогается** — это нормальный лист.
- [ ] Контрольная: серия в любом из двух вариантов убирается; оба варианта после этого сравниваются по количеству (механизм ТЗ-25 не ломается).

Регрессионные:
- [ ] Лист без серий проходит конвейер без лишних вызовов провайдера: количество вызовов не растёт.
- [ ] Разнообразие навыков не деградировало: после замены число различных `skill` не меньше, чем было до замены.
- [ ] Существующие тесты ТЗ-25/ТЗ-26 (потери, два варианта, чистка) — зелёные.

Качественные:
- [ ] В логе видно: сколько серий было, сколько заданий заменено, сколько удалено.
- [ ] Текст страницы «Методика» после выкатки обещает то, что код теперь держит; формулировка согласована с владельцем (см. §7).
- [ ] НОВЫЙ тест падает на старом коде: на старом коде серия из трёх остаётся в листе. Результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не добавляем правило в промпт.** Оно уже есть и не работает; добавление
  ещё одного правила сбрасывает prompt cache «Плюса» без выигрыша.
- **Не вводим новые типы заданий.** Список из пяти типов остаётся.
- **Не делаем серверную валидацию типа задания.** Это отдельная тема (в реестре
  отмечена как наблюдение), и она не в этой задаче.
- **Не меняем число заданий, которое обещает конструктор.**
- **Не показываем учителю «мы убрали одинаковые формы» отдельной строкой.**

## 9. Что не удалось подтвердить

- **Как часто серия возникает в проде.** Измерено только на 10 живых листах
  реестра: 7 из 10 содержат серию. Масштаб по всей базе неизвестен (доступа к
  D1 у агента нет). После выкатки это видно по логу.
- **Сколько заданий теряется при замене.** Зависит от того, сможет ли модель
  дать задание другого типа по той же теме, — а это предмет живой проверки.
  Первый замер покажет.
- **Не проверено, что «другой тип» решает проблему.** Замена задания на
  `short-answer` вместо `multiple-choice` меняет форму, но не навык. Если
  серия образовалась потому, что тема узкая, форма сменится, а суть останется.
  Это осознанный размен: обещание страницы — про формы, а не про навыки.
