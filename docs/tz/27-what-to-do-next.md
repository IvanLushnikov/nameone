# ТЗ-27: «Что делать дальше» — разбор результатов класса по темам

**Дата:** 15 октября 2026
**Продолжение:** `docs/tz/22-class-grading.md` (путь «лист → ответы → отметки»)
**Кто делает:** фронт + бэк
**Размер:** M (по разбивке §8 — три независимых куска, можно отдать трём исполнителям)

---

## 1. Проблема в словах учителя

Учитель провёл проверку, открыл ведомость и видит: 12 человек сдали, 4 не сдали, средний процент 71. Что дальше — непонятно.

Главный вопрос после проверки: **«какая тема у меня провалилась и что я завтра буду делать»**. Сейчас ответить на него нечем: в ведомости есть процент по классу и по ученику, но не по конкретному навыку внутри работы. При этом у конкурентов-генераторов (Study.ai, Examka) такого разбора нет вообще, а у «Госуслуги Моя школа» есть только общая статистика по классу.

## 3. Сценарий 1 — учитель открывает ведомость и видит провал темы

**Кто:** учитель физики, 7Б, 28 человек. Сегодня проверел контрольную по теме «Давление твёрдых тел».

**Шаг 1. Учитель в кабинете.**
Открывает `Мои классы` → видит «7Б» → нажимает на класс.

**Что происходит:** открывается существующий экран класса с составом ученика (`ClassRosterSection.tsx`) и блоком ведомости (`ClassReport.tsx`). Весь этот экран остаётся как есть, новое добавляется одним блоком ниже.

**Шаг 2. Учитель дочитывает ведомость до конца.**
Сейчас он видит блок «Работы по формам» с буквами и процентами, потом строки учеников.

**Что видит учитель (новый блок, добавляется ниже ведомости):**

```
Темы, где просели
                                 28 ответов
Давление твёрдых тел        ████████░░░░░  71%    22 ошибки
Давление жидкостей          ██████████░░   88%     8 ошибок
Площадь прямоугольника      ███░░░░░░░░░░  31%    38 ошибок
```

Каждая строка: название темы, полоса, процент верных, число ошибок. Сортировка по проценту — по возрастанию, худшая сверху. Ровно та же формулировка, что в мобильном конструкторе и в PDF.

**Что делает учитель:** нажимает на строку «Давление твёрдых тел».

**Шаг 3. Открывается карточка темы.**
Внутри — четыре блока, сверху вниз:

1. **«Эта тема в трёх последних проверках»** — три строки: дата, название работы, процент. Если проверок меньше трёх — строк столько же, без пустых заглушек.
2. **«Кто ошибается два раза подряд»** — список фамилий и две даты. Это учительский список «позвать поговорить», а не оценка. Под заголовком подпись: «это не вывод об ученике, это приглашение посмотреть вместе».
3. **«Разбор по заданиям»** — какие задания этой темы провалились: текст задания, процент верных, сколько учеников ошиблись.
4. **Кнопки внизу:** «Сделать проверочную по теме» и «Вернуться к ведомости».

**Шаг 4. Учитель жмёт «Сделать проверочную по теме».**
Открывается конструктор (`/constructor`), тема и класс уже подставлены, шаг выбора темы пропущен. Учитель дописывает только название работы и жмёт «Создать» — дальше сценарий как в обычном конструкторе.

**Что происходит под капотом:** в листе, который создаст конструктор, у каждого задания уже стоит `skill` этой темы. Учитель ничего не заполняет.

**Шаг 5. Учитель провёл проверочную, зашёл снова в карточку темы.**
Видит 4 строки вместо трёх, с новой датой сверху. Если процент вырос — рядом со стрелкой вверх.

**Границы экрана:** карточка темы не отдельная страница с адресом, а раскрывающийся блок в ведомости или модальное окно на всю высоту. Отдельный маршрут — отдельная задача.

## 4. Сценарий 2 — учитель правит метку темы, которую ИИ поставил неверно

**Кто:** та же учительница. Работа по теме «Давление твёрдых тел», ИИ отметил задание про атмосферное давление как «Давление твёрдых тел».

**Шаг 1.** Учитель открывает карточку темы → блок «Разбор по заданиям».

**Шаг 2.** Нажимает на метку рядом с заданием. Метка — редактируемая строка, не кнопка с заранее известными вариантами: ИИ предлагает список тем из таксономии (`src/lib/content/subjects.ts`), но поле принимает и свой текст.

**Шаг 3.** Выбирает «Давление жидкостей» из выпадающего списка или печатает свою формулировку.

**Что происходит:** метка меняется сразу. На следующих работах по этой теме учитель увидит метку уже подставленной — её выбирает он, а не ИИ. Это и есть основной аргумент: ручная правка не пропадает.

**Что учитель не должен делать:** он не обязан придумывать формулировку заново при каждой работе.

## 5. Сценарий 3 — учитель отдаёт ведомость завучу

**Шаг 1.** В ведомости жмёт «Скачать ведомость» (существующая кнопка, отдаёт CSV).

**Шаг 2.** Файл скачивается как `.xlsx` и открывается двойным щелчком в Excel, без «импортировать данные».

**Что видит завуч в файле:**
- **Лист «Класс»** — текущая ведомость, как на экране.
- **Лист «Темы»** — таблица: тема · попыток · % верных · ошибок · кто ошибается два раза подряд. Одна строка на тему, тот же порядок, что на экране.

**Границы:** файл содержит то, что уже видно на экране, и не добавляем отчётов, которых на экране нет. Всё, что не видно учителю, в файл не попадает.

## 6. Технические решения

**AD-1 · Метка навыка живёт в самом листе, а не в отдельной таблице.**
Каждое задание в листе получает поле `skill` при генерации, учитель правит его вручную. Отдельная таблица навыков потребовала бы синхронизации с листом: правишь метку в листе — правишь в таблице. Ошибки рассинхрона здесь стоят дороже, чем две лишние колонки.
**Рационал:** правка метки — редкое действие, а чтение — постоянное. Дублировать данные на запись и рассинхронизировать их невыгодно.

**AD-2 · Связь попыток по теме — своя таблица `skill_attempts`, а не вычисление на лету.**
Таблица: `id, user_id, class_id, skill, form_id, checked_at, correct, total`. Заполняется при завершении проверки.
**Рационал:** «кто ошибается два раза подряд» и «три последние проверки» без такой таблицы считаются на каждом открытии ведомости, а это выборка по всем работам класса. Дёшево сделать один раз при проверке.

**AD-3 · Числа считает сервер, браузер только рисует.**
Новые числа расширяют уже существующий `GET /api/classes/:id/report`. Браузер не складывает ничего сам — так же, как сейчас сделано со «сколько сдали».
**Рационал:** в ведомости уже есть расхождение между устройствами, если считать на клиенте. Не добавляем ещё одно место, где счёт может разойтись.

## 7. Форматы

**Поле в листе:**
```ts
{ id, prompt, answer, explanation, type, skill: string | null }
```

**Новый блок в ответе `GET /api/classes/:id/report`:**
```json
{
  "skills": [
    { "skill": "Давление твёрдых тел", "correct": 20, "total": 28,
      "attempts": 28, "last_checked_at": "2026-10-15T09:00:00Z" }
  ]
}
```
Сортировка — по `correct/total` по возрастанию, на стороне сервера.

**Новый эндпоинт `GET /api/classes/:id/skills/:skill`:**
```json
{
  "skill": "Давление твёрдых тел",
  "recent": [
    { "form_id": "...", "title": "Контрольная №3", "checked_at": "...", "percent": 71 }
  ],
  "struggling": [
    { "student_id": "...", "student_name": "Иванов И.", "dates": ["2026-10-08", "2026-10-15"] }
  ],
  "tasks": [
    { "prompt": "...", "correct": 18, "total": 28, "skill": "..." }
  ]
}
```

**Правка метки:** `PATCH /api/worksheets/:id` с полем `tasks[].skill` (общий с ТЗ-30, один эндпоинт на оба).

## 8. Разбивка на три независимых куска

| Кусок | Что внутри | Зависит от |
|---|---|---|
| A. Метка навыка | Поле `skill` в листе, правка учителем, выгрузка в XLSX | — |
| B. Разрез в ведомости | Блок «Темы, где просели», новый эндпоинт карточки темы | A |
| C. Повторная проверка | Таблица `skill_attempts`, список «ошибается два раза подряд», кнопка в конструктор | A, B |

Кусок A можно отдать и взять в работу первым: он самодостаточен и виден в интерфейсе.

## 9. Acceptance criteria

- [ ] У каждого задания в сгенерированном листе есть `skill`; метку видно рядом с текстом задания, а не внутри него.
- [ ] Учитель меняет метку вручную из выпадающего списка тем или печатает свою.
- [ ] Блок «Темы, где просели» в ведомости: процент, число ошибок, сортировка по возрастанию процента, полоса на каждую строку.
- [ ] Клик по строке открывает карточку темы: 3 последние проверки, список «ошибается два раза подряд», разбор по заданиям.
- [ ] Кнопка «Сделать проверочную по теме» открывает конструктор с подставленными темой и классом, шаг выбора темы пропущен.
- [ ] Новая проверка появляется в блоке «последние проверки» с датой, и видно, вырос ли процент.
- [ ] Лист в XLSX открывается в Excel без импорта; лист «Темы» содержит те же строки, что и экран.
- [ ] У листа без меток (все старые листы) ведомость выглядит как раньше, блок разреза просто пустой — без ошибки.
- [ ] `GET /api/classes/:id/report` возвращает `skills` отсортированным по возрастанию доли верных.
- [ ] Тест: лист на 28 ответов, 20 верных на метку «Давление твёрдых тел» → в ведомости одна строка разреза с `correct: 20, total: 28`.

## 10. Чего не делаем

- Не делаем рекомендации от ИИ («прочитайте параграф повторите»): это стоит токенов на каждого ученика, а учителю не помогает.
- Не делаем индивидуальные траектории по ученику — это школьная админка, не наша задача.
- Не меняем механику отметок: кто поставил и как — остаётся как есть.
- Не делаем карточку темы отдельной страницей с адресом.

## 11. Риски

- **Метка навыка от ИИ будет ошибаться.** Учитель правит вручную, метка помнит правку и подставляет её в следующих работах.
- **«Разрез по темам повысит удержание»** — гипотеза, цифры не проверены. Мерим через `track`: событие открытия карточки темы и создание проверочной по ней. Если за месяц карточку не открывают — фича не работает, разрез переезжает в отчёт по классу.
