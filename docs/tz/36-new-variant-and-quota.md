# ТЗ-36: «Новый вариант» делает новый вариант, а попадание в кэш не тратит квоту

## 1. Контекст и зачем

**Часть 1. Кнопка «Новый вариант» не делает новый вариант.**

Учитель сделал лист по «Обыкновенным дробям», 5 класс, 5 заданий. Ему не
понравился третий вопрос — он нажал «Новый вариант». Он получил **тот же лист
байт в байт**: тот же `id` (`ws_i3apmgq5hga7`), та же дата создания
(`2026-10-28T11:15:14.739Z` — то есть материал сделан накануне, до его первого
запроса), `meta.model = "semantic-cache"`, `costUsd = 0`, `latencyMs = 778`.

Тот же запрос с `bypassCache: true` дал другой материал: `gpt-6-luna`,
`costRub = 0.098`, другой `id`, другая дата, другие тексты заданий.

При этом учитель:
- **потерял одну из пяти бесплатных попыток** — квота списывается в любом
  случае, даже когда провайдер не потратил ни копейки;
- в списке «мои листы» не увидел нового материала: запись та же, просто
  обновилась дата.

**Часть 2. Квота тратится за то, чего не было.**

Кэш стоит ноль. Попадание в кэш — это не генерация. Но `consumeGenerationQuota`
вызывается после `generateWorksheet` безусловно, поэтому «создать ещё раз» по
той же теме съедает месячную квоту бесплатного тарифа и возвращает тот же
материал.

Это прямое расхождение с тем, что обещает продукт: кнопка «Новый вариант» и
счётчик «осталось 3 генерации».

**Где именно ломается (часть 1).** `src/app/constructor/page.tsx:1947`:

```ts
const handleNewVariant = () => {
  if (subject && grade && topic) generate();     // ← generate() без bypassCache

```

`generate()` идёт в `generateWorksheetSmart(body)` (`src/lib/client/llm.ts:448`),
а `opts.bypassCache` там по умолчанию `false` (`:457`). Роут честно передаёт

бэк готов, а фронт не говорит.

**Где именно ломается (часть 2).** `backend/src/routes/worksheets.ts:241`:
`consumeGenerationQuota` вызывается безусловно, а `result.meta.cached` доступен
и при попадании в кэш равен `true`.

## 3. Технический дизайн

| Файл | Что меняем |
|---|---|
| `src/lib/client/llm.ts` | `generate()` получает опцию `bypassCache`; она прокидывается в smart-функции всех типов, у которых есть бэкенд-эндпоинт |
| `src/app/constructor/page.tsx` | `handleNewVariant` вызывает `generate({ bypassCache: true })`; первый заход остаётся без обхода кэша |
| `backend/src/routes/worksheets.ts` | При `result.meta.cached === true` квота **не списывается**, а занятый слот возвращается; антифрод-запрос при этом засчитывается |
| `backend/src/llm/ratelimit.ts` | Новая экспортируемая функция `noteCachedGeneration` — засчитать генерацию для антифрода без списания квоты |
| `backend/tests/unit/free-quota-cache-hit.test.ts` (новый) | Тест: попадание в кэш не уменьшает остаток бесплатной квоты |
| `tests/` (фронт) | Тест: «Новый вариант» отправляет `bypassCache: true`, обычная генерация — нет |

**Что НЕ меняется:** ключ кэша (`backend/src/llm/cache.ts` — это TZ-35),
`generateWorksheet` на бэке, таблицы, промпты, тарифы.

### Что показываем учителю

Кнопка «Новый вариант» после правки делает реальную генерацию. Учитель должен
видеть, что это стоит денег и времени:

- во время генерации — уже есть progress-UI (`scheduleStage` в `generate()`),
  он показывает стадии; ничего нового не нужно;
- **внимание к тексту кнопки:** если учитель нажимает «Новый вариант» на
  бесплатном тарифе, он тратит попытку. Это должно быть видно. Вариант —
  подпись под кнопкой: «Новый вариант — это новая генерация, она расходует
  квоту». Решение по формулировке — за владельцем (см. `docs/backlog.md`,
  раздел «Требует решения владельца»); **по умолчанию подпись добавляется**,
  потому что иначе учитель не понимает, куда делась его квота.

## 4. Решения

**AD-1 · «Новый вариант» = обход кэша на фронте.**
Одна строка в обработчике кнопки плюс прокидывание опции.
*Рационал:* `bypassCache` уже работает от начала до конца, кэш строгий, а
серверный nonce в ключе потребовал бы хранить историю вариантов и менять
таблицу кэша. Кнопка без варианта — это чистая потеря.

**AD-2 · Ключ кэша не трогаем.**
Вариант в ключ не добавляем.
*Рационал:* реестр прямо предупреждает: не расширять кэш до «похожих тем» —
строгость ключа его и спасает. Вариантность решается на стороне кнопки.

**AD-3 · Попадание в кэш не тратит бесплатную квоту.**
Занятый слот возвращается, антифрод-запрос засчитывается.
*Рационал:* квота — это «сколько генераций я сделал», а не «сколько раз я нажал
кнопку». Кэш-хит генерацией не является: провайдеру не заплатили, нового
материала не получили.

**AD-4 · Антифрод не ослабляем.**
Счётчик всплесков (`generations_total`) и визиты продолжают считаться при
кэш-хите.
*Рационал:* иначе «нажимай „Новый вариант“ и не трать квоту» станет способом
нагрузить API. Счётчик остаётся, квота — нет.

**AD-5 · Первая генерация идёт через кэш.**
Кэш — это ускоритель, и он остаётся полезным: повторное открытие того же
материала не стоит денег.
*Рационал:* если обходить кэш всегда, мы платим провайдеру за каждый клик и
теряем единственное, ради чего кэш существует.

**AD-6 · Обход кэша не затирает запись в кэше.**
`saveCache` идёт через `INSERT OR IGNORE` — первая запись по ключу живёт весь
TTL. После обхода кэш хранит прежний материал.
*Рационал:* это осознанно: кэш — не «последний материал», а «быстрый ответ на
тот же запрос». Побочный эффект: обычная генерация после обхода вернёт прежний
материал. Это нормально и совпадает с текущим поведением.

**AD-7 · Для платных тарифов ничего не меняется.**
Квота платных считается по токенам, а кэш-хит токенов не тратит.
*Рационал:* правка касается только счётчика бесплатных попыток.

## 5. Критерии приёмки

Функциональные:
- [ ] Нажатие «Новый вариант» отправляет запрос с `bypassCache: true`; обычная генерация — без этого флага (тест на перехваченном теле запроса).
- [ ] После «Нового варианта» `meta.model` НЕ равен `semantic-cache`, а `meta.costUsd > 0` (то есть это реальная генерация).
- [ ] Материал после «Нового варианта» отличается от предыдущего: другой `id`, другая дата, другой текст хотя бы одного задания.
- [ ] В «моих листах» появляется **новая запись** (а не обновление даты старой): у нового листа свой `id`.
- [ ] Попадание в кэш (обычная генерация того же запроса) **не уменьшает** остаток бесплатной квоты: `freeRemaining` до и после совпадает.
- [ ] При этом счётчик антифрода `generations_total` за запрос с кэш-хитом **увеличивается** (тест на `fraud_signals`).
- [ ] Реальная генерация квоту уменьшает — регрессия на текущее поведение.

Регрессионные:
- [ ] Контрольная по-прежнему приходит двумя вариантами одним вызовом и одной попыткой.
- [ ] Бесплатная квота по-прежнему кончается после 5 реальных генераций (тест на `free_usage`).
- [ ] Упавшая генерация по-прежнему возвращает занятую попытку.
- [ ] Карточки/материалы/комплект (у них нет бэкенд-эндпоинта) по-прежнему отдают мок и не падают.

Качественные:
- [ ] У кнопки «Новый вариант» есть подпись про расход квоты (или решение владельца зафиксировано в `docs/backlog.md`).
- [ ] НОВЫЕ тесты падают на старом коде: тест «кэш-хит не тратит квоту» на старом коде красный (остаток уменьшается на 1). Результат прикладывается к отчёту.

## 6. Чего не делаем

- **Не добавляем nonce/вариант в ключ кэша.**
- **Не обходим кэш на первой генерации.**
- **Не меняем TTL и не удаляем записи кэша.**
- **Не трогаем `guardGeneration` и порядок «занял → позвонил → списал».** Меняется только последний шаг для кэш-хита.
- **Не отключаем антифрод и не уменьшаем счётчики.**
- **Не меняем число бесплатных генераций (5 в месяц).**
- **Не переделываем `saveWorksheet` и историю листов.**

## 7. Риски

| Риск | Вероятность | Цена | Что делаем |
|---|---|---|---|
| Бесплатной квотой можно «дёргать» кэш без расхода (нагрузка на API и D1) | Средняя | Низкая — провайдер не тратится, запрос стоит чтение из D1 | Антифрод считает запросы; при всплеске выдаётся капча. Дополнительно: запись в кэш `INSERT OR IGNORE` — записи не растут |
| Учитель нажал «Новый вариант» и не понял, что потратил попытку | Средняя | Средняя | Подпись под кнопкой (AD-3 в §3) |
| Обход кэша увеличил расход провайдеру для платящих | Низкая | Низкая | Кнопка «Новый вариант» — осознанное действие учителя; это ровно то, за что он платит |
| «Новый вариант» ушёл в кэш по ошибке (забыли прокинуть флаг) | Низкая | Высокая — возврат к текущему дефекту | Тест на перехваченном теле запроса |
| Кнопка «Новый вариант» для типов без бэкенд-эндпоинта (карточки, материалы) начнёт вести себя иначе | Низкая | Низкая | Для этих типов `bypassCache` игнорируется: запроса к бэку нет |

## 9. Что не удалось подтвердить

- **Сколько раз учителя нажимали «Новый вариант» и получали то же самое.** В базе нет события «нажата кнопка "Новый вариант"» — есть только `worksheet_generated`. Событие придётся добавить, если владелец захочет считать эффект; в этой задаче не добавляем.
- **Сколько именно попаданий в кэш происходит в проде.** Снимок D1 от 29.10.2026 не отработал: все SQL-запросы упали с `/tmp/q.sh: No such file or directory`, чисел из базы в файле нет. Известно только по живым прогонам: попадание есть и стоит 0 ₽.
- **Списалась ли квота в живых прогонах.** Логика кода однозначна (`consumeGenerationQuota` вызывается безусловно), но фактического прогона с бесплатной квотой и кэш-хитом в исследовании не было. Тест на бэке это закрывает.
