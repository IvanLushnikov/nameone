## 1. Что сделано

### `backend/src/llm/validation/skill-dupes.ts` (единственный изменённый исходник)

**1. Точное сравнение вместо подсчёта общих слов — основной критерий.**

Добавлены:

- `normalizeTaskText(value)` — нормализованный текст задания: обрезка, нижний регистр, схлопнутые
  пробелы, срезанная конечная пунктуация. Числа **не** срезаются («3/4» и «5/8» — разные задания),
  стоп-слова и морфология **не** применяются (в точной строке каждое слово значимо).
- `exactTaskKey(task)` — ключ задания: нормализованный текст + **множество** вариантов ответа.
  `null`, если у задания нет ни текста, ни вариантов (сравнивать нечего).
- `normalizeSkillLabel(value)` — нормализация метки навыка от модели: обрезка, нижний регистр,
  схлопнутые пробелы. Без стоп-слов и без морфологии: словарь метки нам неизвестен.

**2. Четыре критерия вместо одного** (`findSkillDupes`), в порядке проверки:

| № | Критерий | Условие | `reason` |
|---|---|---|---|
| 1 | exact | совпал нормализованный текст **И** множество вариантов ответа | `exact` |
| 2 | same-text | совпал текст, варианты разные (тот же вопрос дважды) | `same-text` |
| 3 | grams | ≥3 общих слов подряд — нынешнее поведение, порог не тронут | `grams` |
| 4 | same-skill | совпала непустая метка навыка **И** ≥2 общих цепочек из двух слов | `same-skill` |

**3. `reason` в паре** (`SkillDupePair.reason`) — по нему видно, по какому критерию найден дубль.

**4. `sameSkillPairs` в результате** — пары с одинаковой меткой навыка, которые дублём **не**
признаны. Это отчётность, а не повод для замены: правило промпта («один навык — максимум два
задания на лист») два задания одного навыка разрешает.

**5. Словари стоп-words, разделителей и порог `MIN_SHARED_PHRASE = 3` не тронуты** (AD-2, AD-4).
Добавлены только два именованных порога для пар с совпавшей меткой:
`SKILL_PHRASE_LENGTH = 2` (длина цепочки) и `SKILL_MIN_SHARED_PHRASES = 2` (сколько таких цепочек нужно).

**6. `SkillTaskLike` дополнен** полями `options` и `skill` — детектор теперь видит варианты ответа
и метку навыка от модели. Формат ответа API не менялся.

### 7.1. Упал чужой тест `tz25-quality-loss.test.ts` (кейс 10) — и это вскрыло баг в `index.ts`

   Они отличаются **одним числом**, то есть это один и тот же навык пять раз. Детектор ТЗ-26
   (и мой, и старый) правильно находит в них 10 пар-дублей.
2. Дозапрос в этом тесте отдаёт **те же** три задания, что уже стоят в листе. Старый детектор

   и затевалась.
3. Из-за этого `usable` оказался пустым → ветка « dropping duplicates, no usable replacement» →

**Главное: зелёный статус старого теста держался на баге в `index.ts`.** `index.ts:1084-1090`:

```ts

return current.map((task, index) => {
  const number = index + 1;
  if (!replaceNumbers.includes(number)) return task;
  return usable[cursor] ?? task;
  cursor += 1;          // ← НИКОГДА НЕ ВЫПОЛНЯЕТСЯ: стоит ПОСЛЕ return
```

`cursor += 1` — мёртвый код, `cursor` навсегда остаётся 0, и **во все слоты замены

### 7.2. Расхождение ТЗ с его же критериями приёмки (критерий «same-skill»)

§3 ТЗ описывает критерий 4 как «≥2 общих **3-грамм**», §5 — как «совпадающей по двум 3-граммам».
Такая формулировка **недостижима**: любая общая 3-грамма — это общий ряд из трёх слов подряд,
а его находит критерий 3 (`grams`), который проверяется раньше. Значит, при формулировке ТЗ
критерий 4 не мог бы сработать никогда, а `reason: "same-skill"` не появился бы ни разу.

Проверяемо только другое прочтение, и оно согласуется с §5: «два общих **грамма**» = две общие
цепочки из двух слов (в §5 оба критерия про метку написаны именно через «граммы»: «по двум
3-граммам» в первом и «двумя общими граммами» во втором, причём второй критерий — отрицательный:
«разные метки + два общих грамма → `hasDupes: false`» — он верен только при прочтении «грамма =
2-грамма», иначе пара с двумя общими 3-граммами была бы дублем по критерию 3).

Реализовано: **совпавшая метка + ≥2 общие цепочки из двух слов** (`SKILL_PHRASE_LENGTH = 2`,
`SKILL_MIN_SHARED_PHRASES = 2`). Это совпадает с AD-2 («порог 2 — только для пар с одинаковой
меткой») и не ловит пару «живая / неживая природа» (у неё нет ни одной общей цепочки из двух
слов). Вопрос к владельцу — §9, вопрос 1.

### 7.3. Почему «две цепочки», а не «одна»

Одна общая цепочка из двух слов — это общая рамка, а не повтор. «Опишите строение клетки
растения» и «Опишите строение клетки животного» делят цепочку «строение клетки», метка у них
одна и та же («Строение клетки») — и это РАЗНЫЕ задания. При пороге «одна цепочка» детектор
съедал бы нормальные листы по биологии. Поэтому нужны две отдельные общие цепочки. Это
зафиксировано тестом «клетка растения и клетка животного — не дубли (даже с одинаковой меткой)».

## 8. Находки вне задачи

   одинаковыми заданиями, и `repeatedSkills` показывает 0. Это баг уровня Q-01/Q-02, зона ТЗ-34.

4. **`filterBackedOff` в `quality` врёт** — это ТЗ-34, мне не трогать; здесь учтено: в своих
   выводах я на него не опираюсь.
5. **Промежуточные вызовы провайдера** в тестах считаются по HTTP-запросам, а не по

## 9. Пакет вопросов

1. **Критерий «same-skill»: «две 3-граммы» или «две 2-граммы»?**
   - Вариант A (реализовано): совпавшая метка + **две общие цепочки из двух слов**.
   - Вариант B (буквально §3): совпавшая метка + **две общие 3-граммы** — вариант недостижим
     технически: критерий 3 находит общую 3-грамму раньше и ставит `reason: "grams"`.
   - Вариант C: совпавшая метка + **одна общая цепочка из двух слов** — проще, но съедает
     «клетка растения / клетка животного» с общей меткой.
   Рекомендую A. От ответа зависит, не менять ли `SKILL_MIN_SHARED_PHRASES`.

2. **Прокинуть `reason` в лог генерации?**
   - Нужна одна правка в `index.ts` (`pairs: dupes.pairs.map((p) => \`${p.first}-${p.second}\`)` →
   добавить `(${p.reason})`). `index.ts` — зона ТЗ-34, я не трогал.
   - Без этого критерий ТЗ «в логе видно, по какому критерию найден дубль» не выполнен.
   Рекомендую: включить в ТЗ-34.

3. **Что делать с багом `cursor += 1` после `return` в `index.ts:1089`?**
   - Это отдельный дефект (лист с N одинаковыми заданиями + `repeatedSkills: 0`).
   - Вариант A: включить в ТЗ-34 как обязательный пункт (рекомендую — он вскрылся только
     вместе с честным детектором).
   - Вариант B: отдельная горячая правка сейчас.
   Я его не трогал: файл в зоне другого агента.

4. **Где взять живой материал для проверки ложных срабатываний?**
   - Квота боевого воркера исчерпана (5/5) до 1-го числа; живых листов у меня нет.
   - Вариант A: владелец даёт 3-5 листов из прод-выдачи (D1) — проверяю детектор на них.
   - Вариант B: владелец снимает лимит для этого fingerprint.
   - Вариант C: принять фикстуры как достаточные, а ложные срабатывания ловить в приёмке ТЗ-34.
   Рекомендую C сейчас + A после выкатки.

5. **Правило промпта «один навык — максимум два задания» и порог 2-грамм.**
   Сейчас критерий 4 требует **две** общие цепочки из двух слов. Если модель на живой теме
   формулирует задания одинаково, но меняет пару слов, цепочек будет одна — и дубль пройдёт.
   Нужен замер на живых листах (вопрос 4). Пока оставляю строже.
