## 1. Задача

Флоу генерации теряет качество материала в шести местах, и все шесть — молча. Учитель просит 15 заданий и получает 11 без признака. Контрольная приходит с двумя одинаковыми вариантами, с одним вместо двух или с разным количеством заданий в вариантах. ОГЭ отдаётся короче заказанного.

Жалоба пришла на английском, но проверка кода показала: дефекты не связаны с предметом. Четыре из шести бьют по **всем** предметам и всем типам работ — лист, контрольная, ОГЭ/ЕГЭ. Английский добавляет свой шестой разрыв (сбой языка проходит незаметно), остальные одинаковы везде. **Не чини только контрольную** — это главный риск этой задачи.

Твоя задача — закрыть ТЗ-25 полностью: код, тесты, проверка в браузере, коммит и MR.

## 5. Решения, которые нельзя переигрывать

Эти восемь AD приняты в ТЗ. Если кажется, что решение плохое — напиши об этом в отчёте, но не меняй молча.

- **AD-1** Различие проверяет код, не промпт. Новый модуль `validation/variant-check.ts`, чистая функция.
- **AD-2** Порог `maxDuplicates = max(1, floor(count / 5))` — **это гипотеза, помечай её комментарием в коде**. Отдельно: совпали все задания — плохо при любом `count`.
- **AD-3** Один ретрай. Не прошёл — отдаём первый вариант с `variantsDegraded: true` и причиной. Бесконечные попытки съедают норму учителя, контрольная идёт по Sonnet.
- **AD-4** В кэш кладётся только принятый результат. Отброшенный ретраем — никогда. Деградированный кладётся с флагом. Существующая логика `backend/src/llm/index.ts:159` (снос записи контрольной без `secondVariant`) после твоей правки должна сносить только записи **без флага результата**.
- **AD-5** Ретрай честно стоит второго вызова: `logLlmCall` пишется по **каждому** вызову провайдера, `recordUsage` получает сумму `weightedTokens` обоих. Сейчас лог один (`backend/src/llm/index.ts:319`, `336`) — цикл это свойство ломает. Невидимый для тарифа ретрай хуже честной цифры.
- **AD-6** System-промпт меняется один раз и сбрасывает prompt cache у Plus. Помечай это комментарием со ссылкой на `backend/src/llm/prompts/worksheet-gen.ts:4`.
- **AD-7 · Укороченный материал — это дефект, а не мелочь.** Если после фильтра заданий меньше, чем просил учитель, конвейер делает **один** дозапрос на недостающие и мержит. Если после дозапроса всё ещё мало — отдаёт что есть, но с явным признаком в API и сообщением в интерфейсе. Работает для **всех** типов работ, включая ОГЭ/ЕГЭ.
- **AD-8 · Равное количество заданий в двух вариантах — часть равносильности.** После фильтрации количества в вариантах сверяются; разошлись — добираем дозапросом, как в AD-7.

## 8. Критерии приёмки

Из ТЗ §6, все одиннадцать. Первые три — контрольная, остальные бьют по всем предметам:

- модель вернула два одинаковых листа → код заметил, сделал ретрай, второй лист отличается
- модель вернула два одинаковых листа дважды → первый лист + сообщение, что второй не получился
- модель не вернула `variants[1]` → в ответе API есть признак, а не отсутствующее поле
- скачаны оба варианта → два разных файла
- повторный запрос из кэша возвращает пару и тот же флаг деградации, денег не тратит
- в `llm_logs` видно два вызова при ретрае, норма посчитана по обоим
- фильтр выкинул задания → это видно в логах и в ответе API, учитель видит предупреждение
- материал укорочен фильтром → конвейер попытался добрать недостающее одним дозапросом
- ответ обрезан по `finish_reason=length` → материал **любого** предмета не проходит как нормальный результат
- количество заданий в двух вариантах после фильтрации одинаковое
- учитель запросил 15 заданий и получил меньше → это видно на экране без догадок, а не только в логах
