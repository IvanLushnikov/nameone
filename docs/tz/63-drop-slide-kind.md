# ТЗ-63: Вид слайда (`kind`) убирается из ответа модели — его ставит сервер

**Дата:** 30.10.2026
**Кто делает:** бэк + фронт
**Размер:** M (6 файлов, 1 день)
**Источник:** находка Н5 — `docs/research/03-prompt-quality-audit.md:441-461`; решение владельца 30.10.2026 — `:915` и `:931`
**Волна:** 3 (P2) · **Зависит от:** ТЗ-62 (волна 3) — переписываемый промпт не должен возвращать `kind`

---

## 1. Контекст и зачем

Модель сейчас выбирает вид слайда: титульный, тезисы, определение, пример, итоги. Пять значений, одно правило промпта («kind выбирается по назначению слайда», `backend/src/llm/prompts/presentation-gen.ts:64`).

Продукт на это значение не реагирует. Экспортёр рисует **все** слайды одной вёрсткой: заголовок 32 pt по центру, список пунктов, заметки (`src/lib/utils/pptx.ts:73-115`). Слово `kind` в экспортёре встречается один раз — в запасном титульном слайде, когда слайдов нет вообще (`:179`).

Учитель получает 10 одинаковых страниц. Модель тратит токены на выбор того, что никто не показывает. Решение владельца: `kind` уходит из промпта и из схемы ответа, настоящие макеты PPTX — позже, отдельной волной.

**Уточнение к исследованию, которое меняет реализацию.** Отчёт говорит: «`kind` не читается ни разу» — это верно про экспортёр, но не про продукт. В превью в браузере значение читается: `src/components/constructor/PresentationPreview.tsx:99-100` (плашки «Титульный» и «Итоги»), `:136` (подпись вида слайда под заголовком), `:146-153` (нумерованные пункты в слайде-итоге), `:170-183` (`kindLabel`). Убрать поле из ответа — значит сломать то, что учитель видит на экране.

Поэтому: **из контракта с моделью поле уходит, в контракт сервера — остаётся.** Ставит его сервер, по позиции слайда. Учитель видит то же, что видел, а модель перестаёт выбирать то, что не влияет на результат.

**Честная оговорка:** брак не измерен — в проде не было ни одной генерации презентации (0 вызовов `presentation-gen` в `llm_logs`). Претензия к `kind` — конструктивная: поле описывает то, чего продукт не показывает.

## 3. Технический дизайн

### 3.1. Модель больше не возвращает `kind`

`backend/src/llm/prompts/presentation-gen.ts`:

| Место | Что меняем |
|---|---|
| Правило про `kind` (`:64`) | Удалить. Правила после него перенумеровать по порядку |
| Блок «ФОРМАТ ОТВЕТА» (`:77-85`) | Убрать строку `"kind": "title|bullets|definition|example|summary"` из объекта слайда |
| Блок «ОГРАНИЧЕНИЯ» (`:91`) | Убрать строку «ВСЕ поля kind берутся ТОЛЬКО из списка выше» |
| `SLIDE_KINDS` (`:28`) | Оставить три значения: `["title", "bullets", "summary"]` |
| Тип `Slide` (`:38-43`) | Поле `kind` остаётся, но теперь его заполняет сервер |

Нумерация правил в system-промпте после удаления: было 6 (после ТЗ-62), станет 5. Тест на число правил из ТЗ-62 обновляется: 6 → 5.

User-промпт (`buildPresentationPrompt`, `:113-142`) в этой задаче **не меняется**: ТЗ-62 уже заменил блок `требования` (`:130-134`) на `структура_урока` без упоминания `kind`. Проверить, что слово `kind` не вернулось в user-промпт.

### 3.2. Нормализатор ставит вид слайда сам

`normalizePresentation` (`backend/src/llm/prompts/presentation-gen.ts:150-199`):

**Было:**

```ts
const kind = pickEnum(slide.kind, SLIDE_KINDS);
const title = asText(slide.title);
if (!kind || !title) continue;   // ← без kind слайд выбрасывается
```

**Стало:** вид слайда выбирается не из ответа модели, а по позиции в коллекции:

```ts
const title = asText(slide.title);
if (!title) continue;             // ← только заголовок обязателен
// ... слайд собирается без kind
```

После сборки коллекции каждому слайду проставляется вид:

| Позиция | `kind` |
|---|---|
| Первый | `title` |
| Последний (если слайдов больше одного) | `summary` |
| Остальные | `bullets` |

Один слайд в ответе — это `title` (первый и последний совпадают, приоритет у первого).

**Почему это не «сервер заполняет то, что просил промпт».** Раньше вид слайда задавала модель, и она могла поставить `summary` третьему слайду и `title` последнему. Теперь вид слайда — функция позиции, и модель на него не влияет. Это ровно то, что нужно: продукт различает три роли слайда, и различает их по месту.

Ответ модели, в котором `kind` всё-таки есть (старая модель, кеш, чужой ответ), **игнорируется**: вид слайда берётся из позиции, а не из ответа. Это отдельный тест.

## 4. Решения (AD-N)

**AD-1 · `kind` уходит из ответа модели, но остаётся в ответе сервера — ставится по позиции слайда.**
*Рационал:* значение читает превью в браузере (`PresentationPreview.tsx:99-100, 136, 146-153`), и без него учитель теряет плашки «Титульный»/«Итоги» и нумерованные пункты в итогах. Убрать поле из ответа — значит сломать видимое. Перенести выбор в сервер — значит, модель перестаёт решать то, что не влияет на картинку, а то, что видит учитель, остаётся как было.

**AD-2 · Три вида слайда вместо пяти: `title`, `bullets`, `summary`.**
*Рационал:* `definition` и `example` не различаются ни в вёрстке, ни в превью после этой правки — два значения, которые значат одно и то же. Оставить их в типе — значит оставить в коде описание того, чего продукт не показывает. Три роли соответствуют трём разным вёрсткам в превью (плашка титульного, обычный слайд, слайд с итогами).

**AD-3 · Старые значения `definition`/`example` не поддерживаем.**
*Рационал:* в боевой базе сохранённых презентаций нет вообще (184 листа, 0 презентаций — запрос 30.10.2026), так что legacy-ветку в zod-схеме держать не для чего. Заготовка для стенда (§3.4) переводится на три значения в этой же задаче, поэтому новых записей со старыми значениями не появится.

**AD-4 · Экспортёр PPTX не трогаем.**
*Рационал:* настоящие макеты слайдов — решение владельца «позже» (1–2 дня, волна Б). Пока их нет, все слайды рисуются одинаково, и это честное состояние: модель больше не обещает разной вёрстки, а продукт её и не делает.

**AD-5 · Вид слайда ставится по позиции, а не по содержимому.**
*Рационал:* правило «соответствие вида содержанию» из конструкции В12 требует эвристики (по заголовку понять, определение это или пример) — это отдельная задача с отдельными догадками. Позиция — единственный признак, который сервер знает наверняка: первый слайд титульный, последний — итог, остальные — содержательные. Ни одна эвристика по тексту не даёт такой точности.

## 5. Критерии приёмки

- [ ] В `PRESENTATION_GEN_SYSTEM` нет слова `kind` — ни в правилах, ни в блоке формата ответа, ни в ограничениях.
- [ ] В user-промпте презентации нет слова `kind`.
- [ ] Ответ модели из 5 слайдов **без** поля `kind` разбирается в 5 слайдов, а не в 0. Регрессия: на старом коде `pickEnum(undefined, …)` возвращает `null`, все слайды выбрасываются, генерация падает с «модель не вернула ни одного корректного слайда».
- [ ] Первый слайд получает `kind: "title"`, последний — `kind: "summary"`, все средние — `kind: "bullets"`.
- [ ] Модель, вернувшая на среднем слайде `kind: "example"`, не влияет на результат: сервер всё равно ставит `bullets`.
- [ ] `SLIDE_KINDS` содержит ровно три значения; тип `SlideKind` в `src/lib/types.ts:351` — тоже три.
- [ ] zod-схема `PresentationBody` (`backend/src/routes/worksheets.ts:545`) принимает ровно три значения.
- [ ] В превью первая миниатюра с плашкой «Титульный», последняя — с плашкой «Итоги», у последней пункты пронумерованы (1., 2., 3.); в коде превью нет слов «Определение» и «Пример» как подписей вида слайда.
- [ ] `kindLabel` для значения, которого нет в типе, возвращает «Слайд», а не пустую строку.
- [ ] Мок-генератор: первый слайд `title`, последний `summary`, средние `bullets`; заметки непустые; заголовки слайдов остаются разнообразными.

- [ ] Каждый новый тест падает на старом коде и зелёный на новом: тест «ответ без `kind` разбирается целиком» падает на старом коде (0 слайдов вместо 5), тест «вид слайда задаёт сервер, а не модель» падает (на старом коде сохраняется `example` из ответа).

## 6. Чего не делаем

- **Не делаем разные макеты слайдов в PPTX.** Это решение владельца «позже» (1–2 дня, волна Б). Экспортёр (`src/lib/utils/pptx.ts`) в этой задаче не меняется.
- **Не заводим отдельный `presentation-gen`** — решение владельца «позже» (2–3 дня, волна Б).
- **Не делаем эвристику «вид слайда по содержимому»** (по заголовку понять, определение это или пример). Позиция — единственный признак, который сервер знает наверняка (AD-5).
- **Не переносим `kind` в отдельное поле ответа** («slideRole» и подобное) — это та же проблема под новым именем.
- **Не трогаем печать критериев в ключе** (`src/lib/utils/docx.ts:864-874` — `criteriaForTask`, `:747` — почему в ключ, а не в тело листа), формулу взвешенного токена (`backend/src/llm/config.ts:332`), учёт по сумме всех вызовов конвейера (`backend/src/llm/index.ts:637-649, 2008-2013`), реестр типов задания (`src/lib/content/task-types.ts`), лимиты разнообразия и блок типов в промпте (`backend/src/llm/prompts/worksheet-gen.ts:130, 412`).
- **Не меняем число слайдов, `slideCount` и правило «ровно столько слайдов, сколько попросили».** Эта задача — про вид слайда, не про количество.
- **Не чиним формулировки в превью** («Определение»/«Пример» исчезают как подписи вида, но заголовки слайдов в демо-заготовке остаются разнообразными).
