## 5. Поток A — бэкенд и качество материала

### A-1. Смешанные числа в 5 классе

`backend/src/llm/prompts/worksheet-gen.ts`. Лист по математике 5 содержал задания
со смешанными числами (`1 2/9 + 2 4/9` → `3 2/3`). Это 6 класс по программе.

**Правило уходит в промпт, не в фильтр.** Фильтр постфактум не умеет переформулировать
задание — он может только выкинуть.

Добавь в промпт явный список понятий с классом, с которого они идут: смешанные числа — с 6,
десятичные дроби — с 5, степени с целым отрицательным показателем — с 7, логарифмы — с 10.

**Тест:** на фикстуре листа по математике 5 в ответе нет заданий со смешанными числами
и нет понятий из 6 класса и выше.

### A-2. Детектор повторяющегося навыка

Три воспроизведённых дубля:

| Файл | Задания | Что повторяется |
|---|---|---|
| русский 8 | 6 и 9 | бессоюзное предложение, вторая часть поясняет первую, рамка «Я выглянул в окно / в сад» |
| английский 11, вариант 1 | 2 и 10 | `haven't + V3 + yet` |
| карточки | 2 и 3 | «живая / неживая природа» |

Новый модуль `backend/src/llm/validation/skill-dupes.ts`, чистая функция,
рядом с `variant-check.ts`.

**Что сравнивать:** пару «навык + ключевой объект». **Что не сравнивать:** буквальное
совпадение текста и слова-разделители вроде «Вычислите» — на них ловится ложное
срабатывание. Это проверялось: `Jaccard 1.00` у математики оказался артефактом общего
слова «Вычислите».

При срабатывании — один дозапрос на замену. Два задания на одном навыке подряд
допустимы, если числа и формулировки разные.

**Тесты:** 5 листов (русский 8, английский 11, карточки, математика 5, биология 7) —
0 повторов внутри листа; на парах с общим началом — 0 ложных срабатываний.

### A-3. `answer: null`

В листе по русскому 8 у задания 7 поле `answer` = `null`, ответ есть только в пояснении.
В DOCX такое задание остаётся без строки ответа.

Считать `null` дефектом схемы, а не валидным значением: задание без ответа не доходит
до выгрузки.

**Тест:** в ответе API нет заданий с `answer: null`.

Правка `worksheet-gen.ts` сбрасывает prompt cache у тарифа «Плюс». Пометь это
комментарием со ссылкой на файл. Ожидаемый эффект — один холодный старт после выката.

## 6. Поток B — фронт и вёрстка

### B-1. Таймаут генерации — причина блокера №1

`src/lib/client/llm.ts:111` — `signal: AbortSignal.timeout(90_000)`.

Контрольная с двумя вариантами отдаёт за 95,8 с (вторая попытка — 101,8 с).
Фронт обрывает на 90-й секунде: в консоли `[generate] failed: TimeoutError`, в сети
`net::ERR_ABORTED`. Через сайт контрольная не работает **никогда** — разница системная.

- Поднять до **240 с**. Обоснование: худший замер 101,8 с, таймаут должен переживать его
  с запасом, а не впритык.
- Вынести в именованную константу, чтобы число не искали по коду.
- Развести `TimeoutError` от прочих отказов в `catch`
  (`src/app/constructor/page.tsx:1417`). Сейчас любой сбой получает
  «Попытка не потрачена — попробуйте ещё раз». Для контрольной это ложь: повтор
  закончится тем же. Текст для таймаута: «Генерация не успела закончиться. Попробуйте
  лист поменьше или снять ответы и пояснения».

**Тест:** контрольная через сайт доходит до результата; в таймаут-ветке — свой текст.

### B-2. Мобильная ширина конструктора — блокер №2

На 390×844 ширина страницы **834 px**, переполнение **444 px**. Обрезаны: тема, два шага
из четырёх, два варианта сложности из трёх, вторая кнопка, текст «Создать рабочий лист».

Найди источник фиксированной ширины в панели параметров и в полосе шагов, убери его.

Используй существующие примитивы из `src/components/ui/` — `Button`, `Card`, `Modal`,
`Toast`, `Tabs`, `Select`, `Input`, `Badge` — и токены `brand` / `accent` / `warm` из
`tailwind.config.ts`. Новых примитивов не заводи. Раскладку править `container-tight`
(`src/app/globals.css:48`) не нужно, если проблема не в нём.

**Проверка на 360 / 390 / 414 px:** `document.documentElement.scrollWidth === window.innerWidth`,
все четыре шага видны, все три варианта сложности видны, обе кнопки «С ответами» /
«С пояснениями» видны, текст кнопки не обрезан.

### B-3. Русское название предмета в шапке и в имени файла

Внутренний ключ предмета (`algebra`, `math`, `english`) попал в превью и в имя файла:

- на экране: «**algebra** · 8 класс · Средний Уровень»;
- имя файла: `algebra-8kl-сокращение-и-действия-с-рациональными-дробями.docx`;
- в DOCX: «algebra · 8 класс · средний уровень».

Плюс расхождение регистра «Средний Уровень» / «средний уровень» между экраном и файлом.

Найди построение имени файла в экспортере DOCX и подстановку предмета в превью.
Ключ предмета в интерфейс и в имя файла попадать не должен.

**Проверка:** имя файла и шапка используют «Алгебра», строки `algebra` в имени нет,
регистр названия уровня один на экране и в DOCX.

### B-4. Метрика грузится всегда, а текст говорит «по желанию»

`src/app/layout.tsx:90` подключает Яндекс.Метрику безусловно, с `webvisor:true`
— то есть с записью сессий. В `/legal/cookies/` и `/legal/privacy/` написано
«по желанию, можно отключить». Отключения на сайте нет.

**Два варианта, выбрать один — решение владельца, не твоё:**
- поставить баннер согласия и грузить метрику после согласия;
- переписать текст: метрика включается всегда, отключается в браузере. Второе честнее
  и дешевле.

Если выбираешь первое — `webvisor` по умолчанию выключи, запись сессий требует
отдельного согласия. Если второе — правь `src/lib/content/trust.ts`, он в потоке C,
**согласуй с потоком C перед правкой**, чтобы не возникло двух правок одного файла.

## 8. Браузер

**Проверяй в браузере, не по коду.** В прошлом прогоне два агента из четырёх
не смогли поднять Playwright MCP, и их отчёты были без скриншотов — это заметно
слабее проверенного глазами результата.

**Если `browser_*`-тулы не появились в списке инструментов:**

- попробуй `browser_tabs list` — иногда тулы есть, но не подгрузились;
- если их нет, вызови официальный Playwright MCP-сервер по его штатному MCP-протоколу
  через `mcp_invoke` / `tool_search`. В прошлом прогоне так сделал агент, и у него
  браузер работал;
- **свой playwright/puppeteer-код не пиши.**

Если поднять не удалось — напиши это первым абзацем отчёта, а не молча работай по коду.

**Размеры окна.** Перед каждым скриншотом `browser_resize`:
**1440×900** для десктопа и **390×844** для телефона. В бо́льшем окне переполнение
не видно — это уже стоило провала.

**Материал проверяй открытием файла, а не экраном.** Превью врёт: обрезает и прячет.

   но реализуй как есть.

осталось только для одного.** Если по второму пункту вышло «только один» — это
