## 1. Контекст и зачем

Как учитель, я хочу русские формулировки на русском предмете и задания по теме урока, а не «оргanelлу» / «ribosoma» и не «сколько букв о в хлоропласт» на биологии.

Сейчас:
- Страж языка смотрит **долю** латиницы по всему тексту (`language-guard.ts:86`). Слово с латиницей внутри кириллицы при общей доле &lt; 30% проходит.
- «Сколько букв» — запрет правила 9 в промпте (`worksheet-gen.ts` ~правило 9), в коде чужого предмета для этого нет.

Цена ошибки: брак в раздаточном материале; место в листе съедено фонетикой.

Подтверждено 02.11.2026 на фикстуре W2 з.2 и з.11.

## 3. Технический дизайн

| Файл | Что меняем |
|---|---|
| `backend/src/llm/validation/language-guard.ts` | Новая функция `hasMixedScriptToken(text): boolean` — токен (разделители: пробел/пунктуация), в котором есть **и** кириллическая, **и** латинская буква (`оргanelлу`, не `DNA` целиком и не `рис.`) |
| `backend/src/llm/validation/language-guard.ts` | `passesLanguageGuard`: для не-foreign subject, если `hasMixedScriptToken` → `false`. Короткие тексты (&lt;20 букв) для **доли** по-прежнему мягкие; смешанный токен ловим **даже в коротком** фрагменте (одно слово-брак достаточно) |
| `backend/src/llm/validation/quality-filter.ts` | `looksLikeLetterCountingTask(text): boolean` — маркеры вроде `сколько букв`, `подсчитайте букв`, `число букв «`. В `filterTasks`: если subject **не** русский язык / литература / иностранный (точный allowlist: `russian`, `literature`, `english`, `german` — сверить slug'и в `SubjectSlug`) и текст матчит — `droppedForeignMath` **или** новое поле отчёта `droppedOffTopic` если оно уже есть; если нового поля нет — переиспользовать `droppedForeignMath` и назвать причину в логе, **не** раздувая API без нужды. Предпочтительно: отдельный массив `droppedLetterCount` в `QualityFilterReport` только если это 1 строка типа + 1 push; иначе reuse `droppedForeignMath` с комментарием |
| `backend/tests/unit/language-guard.test.ts` | T-1: `оргanelлу` / `ribosoma` на biology → не проходит |
| `backend/tests/unit/quality-filter.test.ts` | T-3: «Сколько букв «о» в слове «хлоропласт»?» + biology → задание отфильтровано |

**Связка с листом:** убедиться, что `passesLanguageGuard` / `findLanguageViolation` реально вызываются для worksheet path. Если guard только на exam — **добавить** вызов в тот же место фильтра листа (или внутри `filterTasks` для text+options), иначе N1 не закроется. Это часть ТЗ, не «на будущее».

## 4. Решения (AD-N)

**AD-1 · Смешанный токен — в language-guard, не в промпте.**  
Правило про язык уже про долю; дополняем код.  
*Рационал:* промпт не ловим брак внутри кириллицы.

**AD-2 · «Сколько букв» — в фильтре качества как чужая активность.**  
Не расширяем промпт.  
*Рационал:* правило 9 уже в тексте; без кода повторится (W2).

**AD-3 · Foreign subjects не трогаем смешанным токеном.**  
english/german пишут латиницей.  
*Рационал:* иначе сломаем нормальные задания.

**AD-4 · Не поднимаем FORMAT_VERSION.**  
Промпт не меняем.  
*Рационал:* только пост-валидация.

## 5. Критерии приёмки

- [ ] `passesLanguageGuard("Выберите оргanelлу … ribosoma", "biology") === false`
- [ ] `passesLanguageGuard` на нормальном русском абзаце без смешанных токенов === true
- [ ] `passesLanguageGuard(..., "english")` со смешанным токеном не ужесточаем (true, как сейчас для foreign)
- [ ] `filterTasks` / эквивалент: задание «Сколько букв «о» в слове «хлоропласт»?» при subject biology не попадает в `kept`
- [ ] То же задание при subject `russian` (если slug такой) — **не** режем этим правилом (это может быть тема урока языка)
- [ ] Новые тесты падают на старом коде и зелёные на новом
- [ ] Worksheet-path реально вызывает проверку смешанного токена (не только exam)

---

## 6. Чего не делаем

- Не пишем полноценный langid.
- Не режем любые латинские термины целиком (`DNA`, `ATP`) — только **смешение внутри одного токена** и letter-counting.
- Не меняем правило 9 в тексте промпта и не поднимаем FORMAT_VERSION.
- Не делаем ТЗ-55 / запрет смешанных чисел.

| Риск | Цена ошибки | Что делаем |

| Guard не вызван на worksheet | N1 останется | Явно проверить call-site в §5 |
