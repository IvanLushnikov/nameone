## Зачем это ТЗ

Из конкурентного анализа (`2026-09-25-competitive-map.md`, §4 «Зазоры»): **у ЛистAI нет ни одного конкурента в РФ с нормальной SEO-картой «рабочий лист + [предмет] + [класс]» и с wizard'ом вместо промта**. Три фичи ниже закрывают эти зазоры по очереди, каждая самостоятельная, можно делать параллельно.

| # | Фича | Главный зазор | DoD-сложность | Ожидаемый эффект |
|---|---|---|---|---|
| **F-01** | SEO-карта: расширить с 46 до 200 тем (добавить физику + английский + углубить русский) | SEO exact-match в Яндексе | 🟡 средняя (контент) | ×4-5 органических страниц, ключевой канал трафика |
| **F-02** | Presets в wizard (5 типовых сценариев учителя) | UX wizard vs «напиши промт» | 🟡 средняя (UX + код) | Снижает барьер входа для 70% учителей |
| **F-03** | Превью 2-3 задания из темы на каждой SEO-странице | Конверсия из SEO в конструктор | 🟢 малая (код) | ↑ время на странице, ↑ CTR в конструктор |

Оценка трудозатрат: **2 недели на все три** (последовательно, full-time).

## F-01. SEO-карта: расширить таксономию с 46 до 200 тем

### Зачем
Сейчас 3 предмета × 9 классов × ~40 тем = ~70 тем в `subjects.ts`, но в SEO-роуты попадает 46. Обучай, MagicSchool, EasyClass — у всех десятки-сотни типов заданий, но **никто не имеет структурированной SEO-карты под поисковые запросы**. Это наш главный долгосрочный актив.

### Требования

1. **Добавить 2 предмета** (физика, английский) — каждый с 9 классами × ~20 тем = ~180 новых тем
2. **Углубить математику и русский** — добавить по 10-15 тем на класс где их мало
3. **Каждая новая тема** должна иметь:
   - `slug` (транслит, kebab-case, ≤40 символов)
   - `title` (человекочитаемое название)
   - `fgosRef` (раздел ФГОС, человекочитаемый)
   - `examples[]` — минимум 2 примера заданий с ответами (для F-03 и для превью)
4. **Валидация при сборке**: темы без `examples` падают в `npm run build` с понятной ошибкой

### Out-of-scope

- ❌ Не добавляем ОГЭ/ЕГЭ-таксономию (отдельное ТЗ, F-04 — следующая итерация)
- ❌ Не переписываем существующие 46 тем — только дополняем
- ❌ Не меняем схему `Topic` в `src/lib/types.ts` (только массивы)
- ❌ Не делаем новые предметы (химия, биология) — Q1 2027

### DoD (Definition of Done)

- [ ] В `subjects.ts` ≥ 200 тем, у каждой ≥ 2 примера заданий
- [ ] `npm run build` проходит без ошибок и предупреждений
- [ ] `npm run dev` → все новые темы рендерятся на `/subject/[subject]/[grade]/[topic]`
- [ ] Lighthouse SEO score ≥ 95 на 5 случайных темах
- [ ] Sitemap (`/sitemap.xml`) содержит все новые URL
- [ ] **Live-проверка в браузере**: открыть 3 новые темы, скриншоты в `.audit/qa-runs/2026-09-25-f01/`
- [ ] Edge case: тема с экранированными символами (например, «Площадь S = a·b») рендерится без HTML-инъекций

### Зависимости
- Готовый `subjects.ts` (есть, расширяем)
- Нужна консультация с действующим учителем по списку тем физики/английского — **запросить у пользователя отдельно, если нет источника**

### Acceptance
- ✅ Поисковый запрос «рабочий лист по физике 7 класс плотность» → наш URL в выдаче Яндекса через 3-6 месяцев после индексации
- ✅ Минимум 150 уникальных URL в sitemap.xml
- ✅ Нет «пустых» страниц (без `examples`)

## F-02. Presets в wizard: 5 типовых сценариев учителя

### Зачем
Сейчас в конструкторе (`src/app/constructor/page.tsx`) шаг 1 — выбор предмета. Это слишком абстрактно для учителя, который пришёл после урока с мыслью «мне нужна карточка на 15 минут». Конкуренты (Обучай, MagicSchool, EasyClass) просят промт — это барьер. Мы даём **готовые сценарии**, в один клик.

### Требования

1. **5 presets** на шаге 1 (после выбора класса):
   - 🎯 **«Карточка на 15 минут»** — 5 заданий, базовая сложность, без теории
   - 📝 **«Домашняя работа»** — 10 заданий, средняя, с пояснениями
   - 📊 **«Проверочная по новой теме»** — 8 заданий, средняя, разнообразные типы
   - 🖨 **«Раздаточный материал к уроку»** — 12 заданий, базовая, с местом для заметок
   - 🏆 **«Подготовка к ОГЭ/ЕГЭ»** — 6 заданий, повышенная, формат экзамена (только 9 и 11 класс)
2. **После выбора preset** — шаги 2-4 (тема, параметры, preview) с предустановленными значениями. Учитель может поменять любой параметр, но defaults уже разумные.
3. **Параллельный режим «свой вариант»** — старая логика (выбор параметров вручную) остаётся, переключатель «Использовать шаблон / Свой вариант».
4. **Mini-описание под каждым preset** (1 строка, что получится).
5. **Аналитика**: событие `preset_selected` с `preset_id` в localStorage-историю.

### Out-of-scope

- ❌ Не делаем персонализированные presets (на основе истории) — Q1 2027
- ❌ Не делаем кастомные presets (учитель сам создаёт) — Q1 2027
- ❌ Не трогаем моковый генератор `src/lib/mock/generator.ts` — он и так работает по параметрам
- ❌ Не делаем presets для ОГЭ/ЕГЭ-отдельного режима (это F-04)

### DoD

- [ ] 5 пресетов в `src/components/constructor/PresetGrid.tsx` (новый компонент)
- [ ] Клик на preset = переход на шаг 2 с заполненными параметрами
- [ ] Переключатель «Шаблон / Свой» работает в обе стороны
- [ ] Аналитика пишется в `src/lib/utils/storage.ts`
- [ ] **Live-проверка**: пройти полный flow по каждому из 5 presets → скриншоты в `.audit/qa-runs/2026-09-25-f02/`
- [ ] Mobile: presets помещаются в 2 колонки на 375px, не уезжают за экран
- [ ] a11y: каждый preset — `<button>` с `aria-label`, навигация Tab/Enter
- [ ] Edge case: учитель выбрал preset, потом переключил на «Свой» → поля не падают, не дублируются

### Зависимости
- Готовый wizard (есть в `src/app/constructor/page.tsx`)
- Storage-утилита (есть в `src/lib/utils/storage.ts`)

### Acceptance
- ✅ Учитель от выбора preset до PDF — **≤ 5 кликов** и **≤ 30 секунд**
- ✅ На мобиле (375×667) все 5 пресетов видны без скролла по вертикали

## F-03. Превью 2-3 задания на SEO-странице темы

### Зачем
Сейчас `/subject/[subject]/[grade]/[topic]` — это просто описание темы без примеров. Учитель из Яндекса приходит, читает абзац и уходит — **низкая конверсия в конструктор**. Если показать 2-3 реальных задания — он видит, что они подходят его классу, и кликает «Сделать такой же лист».

### Требования

1. **Под описанием темы** — блок «Примеры заданий из этой темы» с 2-3 заданиями из `examples[]` этой темы
2. **Формат блока** — карточка с текстом задания и ответом (серым, под спойлером или под «Показать ответ»)
3. **CTA после блока**: «Хотите 10 таких заданий в PDF? → Открыть конструктор» (deep-link с уже заполненными `subject`, `grade`, `topic`)
4. **Если `examples.length > 3`** — показывать 3, остальное не выводить (избежать перегруза)
5. **Если `examples.length === 0`** — НЕ рендерить блок, НЕ показывать CTA (страница остаётся, но без вводящей в заблуждение кнопки)

### Out-of-scope

- ❌ Не показываем превью заданий на странице предмета или класса (только темы)
- ❌ Не делаем интерактивное превью (где учитель кликает и сразу генерит лист в этой же вкладке) — F-02 закрывает
- ❌ Не выводим ответы на первом экране без явного действия (риск «утекших» ответов)

### DoD

- [ ] Блок рендерится в `src/app/subject/[subject]/[grade]/[topic]/page.tsx`
- [ ] При клике «Показать ответ» — ответ раскрывается (без JS-багов)
- [ ] CTA-ссылка ведёт на `/constructor?subject=X&grade=Y&topic=Z` (deep-link)
- [ ] При `examples.length === 0` блок и CTA не рендерятся, страница валидна
- [ ] **Live-проверка**: открыть 3 темы с примерами + 1 без → скриншоты в `.audit/qa-runs/2026-09-25-f03/`
- [ ] Мобилка: блок занимает ≤ 60vh, CTA виден без скролла после примеров
- [ ] Edge case: тема с HTML-символами (`<`, `>`, `&`) в `text` рендерится без XSS

### Зависимости
- Готовая таксономия (есть, расширяется в F-01)
- Готовые `examples[]` (есть, дополняются в F-01)

### Acceptance
- ✅ Конверсия SEO-страница → конструктор: цель **+30%** через месяц после раскатки (baseline нужен — замерить сейчас)
- ✅ Нет 404 после клика на CTA
