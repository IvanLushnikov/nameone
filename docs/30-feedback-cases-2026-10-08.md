## TC-01. Кнопка «Попробовать» из карточки фото-проверки

**Жалоба:** клик открывает генератор, а не проверку работ.

**Как:**
1. Открыть главную `https://uchlist.ru/`.
2. Найти карточку «Проверка работ по фото».
3. Нажать «Попробовать».

**Пройдено:** открывается экран входа в проверку по фото (заголовок «Проверка
работ по фото», объяснение, кнопки «Сделать лист и проверить фото» / «Взять
лист из истории»), а **не** форма выбора предмета и класса.

**Провалено:** сразу открывается выбор предмета/класса (генератор), либо
пустой экран без объяснения.

**Дополнительно (TC-01b):** нажать «Сделать лист и проверить фото» → выбрать
тему → сгенерировать лист. **Пройдено:** после генерации панель проверки по
фото открыта сама, без дополнительного клика по «Проверить фото».

## TC-05. Нет заданий «по образцу» без образца + конкретные ответы

**Жалобы 5 и 8.**

**Как:** та же живая генерация, но смотреть конкретно:
1. Есть ли в заданиях тексты «выполните по образцу», «аналогично», «по такой
   же схеме» — и есть ли сам образец в этом же задании?
2. Есть ли ответы вида «индивидуальный ответ», «зависит от ученика»,
   «по усмотрению»?

**Пройдено:**
- Задание со ссылкой на образец либо содержит образец в своём тексте, либо
  вообще не содержит ссылки.
- В ключе нет заглушек. Если задание без единственного ответа (сочинение,
  описание опыта) — ответ пустой, а в пояснении критерии проверки.
- То же самое в PDF и DOCX (скачать и посмотреть).

**Провалено:** «по образцу» без образца; заглушки в ключе.

## TC-07. Контрольная работа делается в два варианта

**Жалоба:** просят два варианта, получают один, «и тот кривой».

**Как:**
1. Тип материала → **Контрольная**.
2. Сгенерировать.
3. Посмотреть на переключатель «Вариант 1 / Вариант 2».

**Пройдено:**
- Присутствуют **два** настоящих варианта с разными заданиями (не копии).
- Переключение работает туда-обратно: после «Вариант 2» → «Вариант 1»

- Скачанный файл называется `…-variant-1.docx` / `…-variant-2.docx` — иначе

**Провалено:** один вариант; варианты идентичны; возврат к первому не

**Как проверить расход квоты:** см. TC-10, важно не залипнуть.

## TC-10. Лимит: 3 генерации, обход закрыт

**Жалоба 10.**

**Как (обязательно читать предупреждение ниже!):**
1. Очистить счётчики (нужен доступ к D1):
   `npx wrangler d1 execute rabochielisty --remote --command "DELETE FROM
   rate_limits WHERE key LIKE 'freetotal:%'"`
2. **Аноним:** 4 запроса подряд с одного браузера (в браузере, не через curl).
3. **Залогиненный:** войти, сделать 3 генерации на одном устройстве, затем
   зайти с другого устройства/браузера и попробовать ещё раз.

**Пройдено:**
- Аноним: 4-й запрос отклоняется с понятным объяснением.
- Залогиненный: после трёх попыток с первого устройства попытка со второго
  **тоже отклоняется** (счёт по человеку суммируется по всем его браузерам).

**Провалено:** счёт обнуляется при смене браузера или при выходе/входе.

### ⚠️ Предупреждение: как НЕ испортить эту проверку

Проверять лимит **только из браузера**. Через `curl` результат недостоверен:
у машины разработчика VPN с ротацией IP — Cloudflare видит разные адреса от
запроса к запросу, и один браузер даст два счётчика. Проверено 09.10.2026:
`113.160.248.172 → 14.165.209.122 → 113.160.248.172`.

Прежде чем писать «лимит сломан», проверить свой маршрут:
`for i in 1 2 3; do curl -s https://api.cloudflare.com/cdn-cgi/trace | grep "^ip="; done`

# ЧАСТЬ 3. Что нельзя считать доказательством

Проверяющий агент обязан это знать, иначе он повторит ошибки 09.10.2026:

1. **Комментарии в коде — не доказательство.** Код содержит объяснения, почему
   фикс сделан. Читать надо поведение, а не комментарий.
2. **Зелёные тесты — не доказательство.** 08.10.2026 было 566 зелёных тестов
   при падающем `tsc` (vitest снимает типы и не проверяет их). Прогонять
   `npx tsc --noEmit` отдельно.
3. **Тест, который не падает на сломанном коде, ничего не проверяет.** Если
   есть возможность — сломать код руками и убедиться, что тест краснеет.
4. **`cloudflarestatus.com` — не доказательство аварии.** Проверять другие
   сайты на той же платформе и другие ресурсы своего аккаунта.
5. **Измерения через `curl` по лимиту недостоверны** (VPN с ротацией IP).
   Только браузер.
6. **Отсутствие ошибки ≠ правильное поведение.** Проверять, что сделано
   нужное действие, а не что не пришло ошибка.

   - `npx vitest run` (корень).
7. Поищи остаточные дефекты, которые жалобы не покрывали: хардкод чужих
   предметов или заглушек, обещания в текстах без механики в коде.

**Формат ответа:**
- таблица TC-01…TC-13: вердикт + доказательство;
- список остаточных дефектов с приоритетом (P0 ломает фичу, P1 жалоба
  вернётся, P2 мелочь);
- результаты команд целостности;
- отдельным блоком — **что ты НЕ смог проверить и почему** (важнее, чем
  «всё хорошо»);
- вердикт в одну строку: можно закрыть задачу или нет.

**Не вноси изменения в код.** Только чтение, запуск и проверки.

# ЧАСТЬ 5. Что осталось открытым (проверяющий не должен считать это багом)

1. **Анонимные могут менять браузер.** У человека без входа нет

   владельцем продукта: предлагается при исчерпании просить войти.

3. **Тема недели обновляется по cron раз в сутки.** В момент проверки может
   быть чуть старше «правильной» недели — это норма, а не дефект.
