## 3. Что именно изменилось (по задачам)

### T01 — чужое избранное
* `addFavorite` читает `user_id` существующего worksheet: чужой не-null owner → 404
  до INSERT (тот же ответ, что у GET `/api/worksheets/:id` — существование не подтверждаем).
* `listFavorites` (оба пути: с курсором и без) фильтрует по владельцу в SQL:
  показываются свои листы и анонимные (`user_id IS NULL`), чужие — нет.
  Заведённая ранее плохая связь наружу не отдаётся.
* Свой payload не перезаписывается, импорт сохраняется под своим владельцем,
  повторное добавление даёт одну связь.

### T02 — подтверждение оплаты провайдером (fail-closed)
* Сверяется весь канонический объект платежа: `id`, `status=succeeded`,
  `paid=true`, `amount.value` в целых копейках, `currency=RUB`.
* Три исхода: **confirmed** (активируем) · **rejected** (окончательный отказ, без
  прав) · **unavailable** (сеть/5xx/битый JSON/неполные поля/нет ключей) —
  **ни одной записи** в payments/subscriptions/users и **503 наружу**, чтобы
  провайдер повторил уведомление.
* Демо-ветка осталась, но явная и изолированная: `ALLOW_DEMO_PAYMENTS=true` и
  только для платежа, созданного без провайдера (`yookassa_payment_id == наш id`).
  Боевой путь она не открывает: платёж с настоящим yk-id всегда сверяется.

### T03 — настоящий cron
* `app.fire` как cron-API больше не используется (это механизм событий Hono,
  рантайм Cloudflare его для триггера не зовёт).
* Воркер отдаётся как `Object.assign(app, { scheduled })` — у воркера есть
  метод `scheduled(event, env, ctx)`, который вызывает рантайм.
* Прежние разведения сохранены: суточный триггер убирает ПДн, часовой гоняет
  биллинг, незнакомый триггер делает всё (лучше лишняя работа, чем пропуск
  удаления персональных данных), `ctx.waitUntil` и логирование ошибок — на месте.

### T04 — атомарный переход «занято → использовано»
* Прибавление счётчика и снятие занятого места — **одна транзакция** (`db.batch`).
  Наружу не наблюдается состояние «слот освободился»: видно либо
  «4 использовано + 1 занято», либо «5 использовано + 0 занято».
* Сбой внутри пачки откатывает всё: занятие остаётся, повтор не двоит.
* Публичные сигнатуры `consumeFreeQuota` / `holdFreeQuotaSlot` не менялись.

### T05 — канонический id
* `/save` кладёт в payload `id` строки и согласованный `createdAt` (id назначает
  сервер — клиент подделать его не может).
* `getWorksheetById` читает `id`/`created_at` строки и гидратирует старые
  payload'ы без id/createdAt: id строки авторитетен, тип и содержимое
  артефакта не теряются (план урока остаётся планом, КТП — КТП).
* Битый JSON — как и раньше, `null`: выдуманный артефакт не отдаём.

### T06 — общий реестр типов
* `z.enum(TASK_TYPE_IDS as [string, ...string[]])` вместо локального списка из
  пяти: перечисление типов теперь одно на весь продукт.
* Поле осталось необязательным; merge структурированных полей при правке только
  текста, обрезка и проверка текста, удаление пустого ответа — как были.
  Форма ответа прежняя (400 + `issues[]`), текст ошибки теперь называет обе
  причины: пустой текст и неизвестный тип.

### T07 — раздаточный файл ученику
* В DOCX страница «Критерии оценивания» включается только вместе с ключом.
* В превью страницы критериев в режиме ученика не рисуются, а счётчик
  «Лист N из M» считает только реально включённые страницы.
* API, баллы и шкала отметок не тронуты.

### T08 — один источник финансовых входов
* `scripts/economics-inputs.mts` читает `PLANS`/`priceFor`,
  `PLAN_NORM_PER_MONTH`, квоту, `MODEL_COSTS` и исторические замеры и отдаёт
  версионированный JSON с единицами, путём к источнику и пометкой каждой
  величины (`canonical` / `assumption` / `modelRate` / `historicalActual` / `estimate`).
* `scripts/unit-economics.py` читает этот JSON (`--inputs`) и **ничего не знает
  про цены**. Нет файла входов или чужие единицы → понятная ошибка и ненулевой
  код; молчаливого отката к старым константам нет.
* Расчёт показывает месячную и годовую выручку по трём тарифам, бесплатную
  квоту и **вклад по фактической себестоимости** — со знаком, формулой и
  допущениями. Вклад отрицательный (−30 / −58 / −127 ₽/мес по историческому
  замеру 0,18 ₽/лист). Это зафиксировано, а не спрятано; расчёт при этом не
  ломает сборку, тарифы и нормы не менялись.

### T09 — шаг 4 конструктора
* На шаге «Параметры» вместо общего рекламного превью — сводка выбранных
  параметров (предмет, класс, тема, формат, уровень, число заданий) и до двух
  **настоящих** примеров из каталога тем с подписью «Пример по выбранной теме».
* Примеры берутся из `Topic.examples` (`src/lib/content/subjects.ts`), а не
  выдумываются; ничего не имитирует результат LLM. Нет примеров — честное
  пустое состояние.
* State machine генерации и сохранения, кнопка «Новый вариант» с `bypassCache`
  и подписью расхода, paywall и схема артефакта не тронуты. После генерации
  превью результата остаётся прежним `WorksheetPreview`.

## 6. Расширения allowlist — раскрыто (2 файла, T02)

Карточка T02 разрешала менять `backend/src/services/billing.ts`,
`backend/src/routes/billing.ts`, `backend/tests/unit/billing.test.ts` и новый
`backend/tests/unit/billing-webhook-authenticity.test.ts`. Пришлось тронуть
ещё два файла, и вот почему:

* `backend/tests/unit/billing-recurring.test.ts`
* `backend/tests/unit/security-regressions.test.ts`

Оба кодировали **старый fail-open контракт** («нет ключей ЮKassa → вебхук
активирует подписку по нашей БД и по сумме») — то есть ровно то поведение,
которое карточка T02 требует убрать. Без правки они падали бы на новом коде.
Правка **механическая**: в окружении вебхука появились ключи провайдера, а в
обработчик — подставленный fetcher, который подтверждает оплату; кейсы
демо-режима переведены на платёж без провайдера (`yookassa_payment_id == наш
id`). Смысл проверок сохранён полностью: обычная покупка, consent/renewal,
replay, «план берётся из БД, а не из тела запроса» — всё по-прежнему
проверяется. Провайдер при этом не зовётся: fetcher инжектирован, реальных
ключей и запросов к ЮKassa нет.
